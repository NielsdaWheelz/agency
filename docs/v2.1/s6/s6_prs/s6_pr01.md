# PR-01: Reports v2 Canonical Model + Mode-Aware Progression Contract

## Goal

Deliver one deterministic reports-v2 contract for review/PR/merge progression across JSON and markdown report artifacts.

## Builds On

Slice S5 complete baseline (`agent review`, `agent pr sync`, and `agent merge` canonical flows merged).

## Acceptance

- Report resolution uses one canonical model for JSON + markdown inputs, with deterministic precedence and conflict handling; `report.json` is authoritative when present.
- Equivalent report content yields stable machine-readable fields regardless of whether the source artifact is JSON or markdown.
- Headless progression paths enforce strict report validation and fail closed with typed deterministic outcomes for missing, malformed, oversized, or schema-incompatible inputs.
- In strict headless mode, `agent review` surfaces report-contract violations as deterministic blocked readiness output with typed blocking reasons (not transport/request failures).
- In strict headless mode, `agent pr sync` and `agent merge` return typed deterministic failures when report contract validation fails.
- Markdown-only repositories remain backward compatible through deterministic markdown-to-model mapping; JSON migration is optional.
- Headed and compatibility report consumers (including legacy `push`) remain progression-capable through deterministic fallback behavior with explicit diagnostics instead of brittle parse assumptions.
- Strict-vs-compatibility behavior is explicit and contract-documented so automation can rely on one deterministic matrix.
- Report ingestion and fallback PR-body generation remain bounded under large repository inputs, with explicit and stable truncation/degrade signaling.
- Deterministic tests cover precedence, serialization parity, strict failure behavior, compatibility fallback behavior, and bounded-input handling across progression surfaces.

## Non-Goals

- No broad CLI flag ergonomics normalization (`--yes`, short aliases, open-on-create); that remains PR-02 scope.
- No command-family redesign for review/PR/merge surfaces.
- No removal of markdown compatibility or forced migration to JSON reports.
- No expansion into GUI/full-screen TUI workflow scope.

## Key Decisions (if any beyond L2)

**Strictness surface**: keep one mode-aware contract where headless progression is fail-closed and typed, while headed/compatibility progression is fail-open with deterministic diagnostics.

**Single report contract source**: canonical and compatibility report consumers must use the same normalized report semantics so precedence, error typing, and fallback behavior cannot drift by command path.

**Review contract shape**: strict report violations in `agent review` are represented as deterministic blocked readiness reasons; typed hard failures are reserved for strict mutation progression (`agent pr sync` and `agent merge`).

**Compatibility scope in this PR**: report-aware compatibility behavior covered here is legacy `push`; no new report consumption is added to unrelated compatibility paths.
