# PR-01: Daemon-Backed Invocation Review + PR Sync

## Goal

Establish canonical invocation-scoped review and PR sync flows under `agent` with deterministic human and machine-readable contracts.

## Builds On

Slice S4 merged state (readiness model, daemon API envelopes, runner-capability model, and mutation JSON baselines).

## Acceptance

- `agency agent review <invocation_ref>` is the canonical S5 readiness/progression surface; it requires `invocation_ref`, supports `--repo` and `--json`, and returns one deterministic verdict with typed blocking reasons, navigation hints, and explicit PR progression eligibility.
- `agency agent checks` is removed from the S5 command surface; readiness/progression access is only through `agent review`.
- `agency agent pr sync <invocation_ref>` deterministically resolves invocation context to its integration worktree and performs branch push plus PR create/update as one invocation-addressed flow.
- PR identity remains branch-scoped for the resolved integration branch (not per-invocation object identity), with stable machine-readable identity/outcome fields across create/update/reuse outcomes.
- Validation and failure behavior are deterministic and typed for repo resolution, dirty-worktree policy, and force-with-lease policy, with script-safe errors and hints.
- PR body/report completeness checks and fallback generation are bounded by explicit limits; oversized inputs follow deterministic fail/degrade behavior with no unbounded in-memory reads.
- Canonical read and mutation behavior for review and PR sync is daemon-mediated with stable response/error envelopes and request correlation, not ad hoc CLI-local run-store orchestration.

## Non-Goals

- No invocation-scoped merge execution (`agent merge`) in this PR.
- No removal of legacy compatibility commands (`push`/`merge`) in this PR.
- No reports-v2 transition or broad CLI ergonomics standardization (Slice S6 scope).
- No expansion of host/provider scope beyond current GitHub-targeted PR behavior.

## Key Decisions (if any beyond L2)

**Canonical review surface**: `agent review` is the only readiness/progression entry point in S5 PR-01; `agent checks` is not retained.

**Branch-scoped PR lineage**: invocation selects context, but PR lookup/create/update remains anchored to the integration branch to avoid PR identity drift across repeated invocation cycles.

**Daemon-first authority**: review and PR sync contract behavior is owned by daemon APIs so validation, errors, and JSON outputs do not drift between CLI and daemon paths.
