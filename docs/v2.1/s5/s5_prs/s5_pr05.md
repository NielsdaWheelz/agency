# PR-05: PR Sync Strict-Decode Contract Closure

## Goal

Close the remaining S5 contract gap by making invocation-scoped PR sync request decoding strict, deterministic, and fully aligned with daemon API mutation-contract rules.

## Builds On

PR-04 merged state.

## Acceptance

- `agent pr sync` request handling rejects unknown JSON fields and trailing/multi-object payloads deterministically for invocation-scoped PR sync.
- Strict-decode failures return typed `E_INVALID_ARGUMENT` errors with stable, automation-safe message/hint behavior.
- Missing required query parameters (including `repo_id`) preserve existing `E_INVALID_REQUEST` behavior for compatibility in this PR.
- Request parsing behavior is consistent across known-length and unknown-length/chunked HTTP request bodies; option handling must not depend on `Content-Length`.
- Empty/default PR sync requests remain valid and preserve current default behavior when optional flags are omitted.
- Existing PR sync options (`allow_dirty`, `force_with_lease`) continue to behave identically when provided in valid request bodies.
- Response correlation remains contract-stable: mutation responses include `request_id` in body and matching `X-Request-ID` header on both success and failure paths.
- Tests cover strict-decode failure matrix (unknown fields, trailing data, multi-object payloads, malformed JSON, unknown-length body parsing) and regression-guard existing option semantics.

## Non-Goals

- No changes to branch-scoped PR identity or create/update progression semantics.
- No changes to invocation-scoped merge flow behavior or merge contract surfaces.
- No reports-v2 scope expansion or S6 ergonomics work.
- No broad request-decoding refactor across unrelated daemon endpoints in this PR.

## Key Decisions (if any beyond L2)

**Error-code normalization scope**: strict JSON body-decoding violations for PR sync use `E_INVALID_ARGUMENT`; existing query-validation behavior (including missing `repo_id` -> `E_INVALID_REQUEST`) and business-state failures remain unchanged.

**Contract-closure-first scope**: this PR closes strict-decode + deterministic error behavior for PR sync specifically, without widening scope into cross-endpoint decoding harmonization.
