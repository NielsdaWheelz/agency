# PR-03: Compatibility-Path Safety Parity for Legacy `push`/`merge`

## Goal

Close remaining S5 safety debt in legacy compatibility commands so non-canonical `push`/`merge` paths cannot violate S5 invariants.

## Builds On

PR-02 merged.

## Acceptance

- Legacy `agency push` report/body handling is bounded by explicit limits; report completeness checks and fallback-body generation avoid unbounded in-memory reads from report, git history, and changed-file inputs.
- Oversized or otherwise over-limit legacy `push` inputs resolve deterministically (typed fail/degrade behavior) so automation does not rely on unbounded fallback behavior.
- Legacy `agency merge` treats merge-log persistence as correctness-critical: write failures surface as typed operation failures rather than being silently ignored.
- Successful legacy merge-log artifacts are persisted with private permissions aligned to v2.1 safety expectations.
- Legacy merge verify environment uses deterministic root semantics: `AGENCY_REPO_ROOT` resolves to the actual repository root and `AGENCY_WORKSPACE_ROOT` resolves to the integration worktree path.
- Compatibility safety behavior is implemented via shared S5 primitives/contracts so legacy and canonical paths cannot drift on bounded-input, typed-error, and durability semantics.
- Compatibility-path failure/success contracts remain deterministic and script-safe, including stable typed errors and actionable hints for bounded-input and persistence failures.
- Targeted unit/integration coverage asserts oversized-input handling and merge-log persistence/root-semantics behavior for legacy compatibility flows.

## Non-Goals

- No removal of legacy compatibility commands (`push`/`merge` remain available).
- No expansion of legacy compatibility commands into new product surface beyond S5 safety parity.
- No reports-v2 migration or broad CLI ergonomics cleanup (Slice S6 scope).
- No changes to canonical daemon-backed `agent review` / `agent pr sync` / `agent merge` behavior beyond maintaining parity expectations.

## Key Decisions (if any beyond L2)

**Parity policy**: Compatibility commands may remain for backward compatibility, but they must match canonical S5 safety posture for bounded input handling, deterministic typed failures, and durable merge-log behavior.

**Compatibility-shim architecture**: Legacy command surfaces should reuse shared safety and contract primitives rather than maintaining separate ad hoc logic for report parsing, fallback body construction, merge-log persistence, and root-resolution semantics.

**Over-limit policy**: Legacy flows must use deterministic fail-or-degrade outcomes under oversized input conditions; silent truncation and unbounded read/write behavior are not acceptable.
