# PR-02: Invocation-Scoped Merge Contract + Durability + Workflow E2E

## Goal

Complete canonical invocation-scoped review -> PR sync -> merge progression with script-safe confirmation semantics and merge-path hardening.

## Builds On

PR-01 merged.

## Acceptance

- `agency agent merge <invocation_ref>` is the canonical S5 merge surface; it requires `invocation_ref`, supports `--repo` and `--json`, and enforces deterministic validation for merge strategy exclusivity and confirmation mode.
- Merge confirmation is script-safe: non-interactive execution requires explicit `--yes`, and missing confirmation in non-interactive mode fails with a typed deterministic error (no TTY scraping contract).
- Merge prechecks, verify execution, merge execution, and post-merge lifecycle actions execute as one invocation-scoped flow with stable machine-readable result/error fields.
- Canonical merge behavior is daemon-mediated and invocation-addressed (not CLI-local run-store orchestration), preserving deterministic error/hint semantics across human and `--json` modes.
- Merge execution resolves to one deterministic branch-scoped PR target for the invocation’s integration context and returns stable merge identity/outcome fields.
- Merge-log persistence failures are surfaced as typed operation failures; successful merge logs use private permissions aligned with v2.1 safety expectations.
- Verify environment root semantics are deterministic and correct in merge path execution (`repo root` = actual repository root; `workspace root` = integration worktree target).
- End-to-end coverage proves invocation-centric workflow integrity for happy path and key failure paths: not ready, missing/closed PR, mergeability failure, confirmation failure, bounded-input fail/degrade behavior, and log-write failure.

## Non-Goals

- No reports-v2 migration or broad CLI ergonomics standardization beyond canonical S5 confirmation behavior (`--yes` for non-interactive merge).
- No removal of legacy compatibility commands (`push`/`merge`) in this PR.
- No merge queue orchestration, policy-driven auto-fix loops, or GUI/TUI expansion.

## Key Decisions (if any beyond L2)

**Confirmation policy**: `--yes` is the only non-interactive confirmation contract for canonical `agent merge`; interactive typed confirmation remains human-facing behavior.

**Durability posture**: merge-log persistence is correctness-critical merge behavior; silent write failure is not acceptable.

**Bounded-input posture**: oversized/unreadable PR-body inputs must follow deterministic fail-or-degrade behavior with typed outcomes; no unbounded reads and no silent fallback ambiguity.
