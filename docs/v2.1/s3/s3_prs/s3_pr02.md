# PR-02: Follow-up Prompt Control Plane + Safety Bounds

## Goal

Add invocation-scoped follow-up prompting on existing headless sessions and enforce deterministic S3 prompt/log bounds for prompt submission and transcript/log reads.

## Builds On

PR-01 merged.

## Acceptance

- A follow-up prompt can be submitted against an existing invocation context through canonical `agent` control-plane surfaces, and the action does not create a new invocation.
- Accepted follow-up prompts appear in the unified invocation timeline in deterministic order alongside prompt seed, message, tool-use, and raw-log coverage entries.
- Follow-up prompt retries support idempotent duplicate handling: repeated submissions with the same request identity resolve deterministically and do not create duplicate timeline writes.
- Follow-up prompt input from direct text and file-backed sources enforces bounded read behavior and rejects over-limit payloads with deterministic validation errors.
- Transcript/history and log reads enforce S3 read-limit bounds with deterministic invalid-argument errors for out-of-contract values instead of silent coercion.
- Repeated detach and re-entry cycles preserve continuity for both timeline/log reads and follow-up prompt submission on the same invocation reference.
- Human-readable and `--json` surfaces stay behaviorally aligned for follow-up/timeline/log outcomes (same ordering and error semantics).

## Non-Goals

- No checkpoint restore + restart integration (PR-03 scope).
- No interactive history selector UX or mapping behavior (PR-04 scope).
- No turn-aware diff or checks-first readiness surface delivery (PR-05 scope).
- No redefinition of PR-01 ordering semantics or typed timeline contract.

## Key Decisions (if any beyond L2)

**Idempotency scope**: treat follow-up prompt retries as invocation-scoped idempotent writes keyed by request identity so duplicate detection is deterministic and auditable.

**Validation posture**: prefer fail-closed, deterministic parameter and payload-limit validation for prompt/log read contracts rather than permissive fallback defaults.
