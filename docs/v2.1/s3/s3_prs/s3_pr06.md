# PR-06: Unified Invocation Event Writer + Cross-Surface Sequencing

## Goal

Consolidate invocation event appends under one daemon-owned contract so concurrent mutation surfaces preserve deterministic sequencing and consistent write outcomes.

## Builds On

PR-03 merged (with PR-01 timeline ordering contract and PR-02 follow-up idempotency semantics already in place).

## Acceptance

- Follow-up prompts, checkpoint engine lifecycle events, checkpoint-apply events, and land/discard lifecycle events all append through one invocation-scoped event-write contract.
- Concurrent writes from different producers to the same invocation preserve one monotonic invocation sequence with deterministic ordering for timeline consumers.
- Follow-up retries using the same `client_request_id` remain idempotent after writer unification and do not create duplicate timeline writes.
- Event append failures are surfaced with explicit, deterministic outcomes across producers; no surface silently drops failed writes as best-effort behavior.
- Unified event writing preserves existing timeline read behavior for unchanged data: stable turn identities, deterministic checkpoint marker mapping, and aligned human/`--json` history semantics.

## Non-Goals

- No new user-facing CLI command family.
- No change to timeline entry taxonomy or cursor contract semantics.
- No expansion of S3 scope into new review/PR/merge mutation surfaces.
- No redefinition of restart, history selector, diff, or checks contracts delivered in PR-03 through PR-05.

## Key Decisions (if any beyond L2)

**Single sequencing authority**: invocation event ordering is allocated by one shared writer contract, not by producer-local sequence strategies.

**Unified failure posture**: event-write failure handling is defined once for all invocation-event producers and must be user-visible/deterministic instead of surface-specific silent fallback.
