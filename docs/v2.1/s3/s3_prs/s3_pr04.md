# PR-04: Interactive History Selector + Deterministic Mapping

## Goal

Provide arrow-key terminal history selection that deterministically resolves a chosen timeline point into checkpoint restore + restart outcomes.

## Builds On

PR-03 merged.

## Acceptance

- Users can invoke an interactive terminal selection flow over invocation history that includes timeline context and checkpoint context needed for restart decisions.
- Interactive selection supports arrow-key navigation and deterministic selection confirmation behavior in terminal sessions.
- Choosing a history item always resolves by one documented deterministic mapping rule to either a concrete checkpoint restart outcome through the canonical restart flow or a deterministic, user-visible error when no valid checkpoint mapping exists.
- The same selected history point yields the same mapping and outcome across repeated runs when underlying timeline/checkpoint data is unchanged.
- Selector-driven restart executes through the same invocation-scoped restart contract and result shape as explicit checkpoint restart (no divergent mutation path).
- Non-interactive/scripted usage remains available through explicit checkpoint selection with machine-readable output parity; interactive selection does not become the only restart path.
- Interactive flows fail fast with deterministic guidance when run without an interactive terminal.

## Non-Goals

- No full-screen watch workspace, multi-pane TUI chrome, or GUI parity work.
- No expansion of review/PR/merge command families.
- No redefinition of PR-01 timeline ordering/cursor contracts.
- No redefinition of PR-03 restart semantics, environment replay rules, or non-interactive runner defaults.
