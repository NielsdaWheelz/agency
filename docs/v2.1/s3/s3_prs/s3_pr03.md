# PR-03: Canonical Agent Restart-From-Checkpoint Flow

## Goal

Deliver one invocation-scoped canonical `agent` restart path that runs checkpoint restore and headless runner restart as a single contract.

## Builds On

PR-02 merged.

## Acceptance

- Explicit checkpoint selection executes checkpoint restore and runner restart in one command flow with one deterministic result contract.
- Canonical restart behavior is invocation-scoped under `agent`; users do not need manual multi-command sequencing to restart from checkpoint.
- Restart execution preserves invocation continuity on the same invocation context for subsequent timeline reads and follow-up prompts.
- Restart flow preserves deterministic invocation-order behavior needed by transcript/history consumers after checkpoint-apply boundaries.
- Restarted headless runner launch uses deterministic non-interactive defaults suitable for automation (no interactive stdin expectations and required environment defaults).
- Human-readable and `--json` restart surfaces remain behaviorally aligned for success and validation/error outcomes.

## Non-Goals

- No interactive history selector UX or timeline-point selection behavior (PR-04 scope).
- No turn-aware diff context or checks-first readiness surface delivery (PR-05 scope).
- No broad mutation-command `--json` parity expansion outside S3 chat/restart/checks scope.
- No redefinition of PR-01 timeline contract or PR-02 follow-up/idempotency semantics.
