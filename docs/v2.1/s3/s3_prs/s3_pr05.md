# PR-05: Turn-Aware Diff + Checks-First Readiness Surface

## Goal

Expose deterministic turn-anchored diff context and a terminal-first checks/readiness surface for a headless invocation.

## Builds On

PR-03 merged (with PR-01 timeline contract available).

## Acceptance

- Users can request diff context for a selected turn identity or inclusive turn range from invocation history, and the request resolves against the same invocation context.
- Turn selection is deterministic: the same turn selector resolves to the same diff mapping when invocation timeline/checkpoint state is unchanged.
- Turn-aware diff mapping remains stable across detach/re-entry and restart cycles for the same invocation.
- Turn-aware diff responses are available in both human and `--json` modes with behaviorally aligned success and error semantics.
- A checks-focused terminal surface reports invocation readiness state and explicit blocking reasons for merge/review progression.
- Checks output includes invocation-linked navigation context so users can move from readiness findings back to relevant invocation history and diff context.
- Checks/readiness output is scriptable in `--json` mode and usable in terminal mode without requiring full-screen workspace UI chrome.

## Non-Goals

- No invocation-scoped PR/review/merge mutation command family (S5 scope).
- No broad mutation-command `--json` parity expansion outside S3 chat/restart/checks surfaces.
- No full-screen watch workspace, multi-pane TUI chrome, or GUI parity delivery.
- No redefinition of PR-01 timeline ordering/cursor guarantees or PR-03 restart semantics.

## Key Decisions (if any beyond L2)

**Turn selector contract**: use one durable turn identity model shared between history navigation and diff context selection; do not introduce separate per-surface turn identifiers.

**Checks readiness contract**: expose machine-readable readiness state plus blocking reason taxonomy with human-readable parity, so terminal and automation consumers receive the same readiness truth.
