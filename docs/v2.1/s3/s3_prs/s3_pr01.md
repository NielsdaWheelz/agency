# PR-01: Unified Invocation Timeline + Durable Ordering

## Goal

Establish one daemon-owned invocation timeline read contract for detached transcript/history with typed entries, stable cursoring, and durable monotonic ordering.

## Builds On

Nothing - first PR in Slice S3.

## Acceptance

- Reading invocation transcript/history returns one ordered timeline (not split views) that includes prompt seed context, assistant/user messages, tool-use activity, and raw-log coverage markers.
- Timeline entries are typed and available in both human and `--json` command paths with the same ordering semantics.
- Cursor pagination for timeline reads is stable, deterministic, and supports incremental continuation without duplicate/skip drift.
- Timeline ordering remains monotonic across daemon restart boundaries.
- Timeline ordering remains monotonic across checkpoint-apply boundaries.
- Timeline reads preserve invocation continuity for detached inspection flows; they do not require creating a new invocation.

## Non-Goals

- No follow-up prompt write-path behavior or retry/idempotency flow (PR-02).
- No prompt/log payload-limit validation contract expansion (PR-02).
- No checkpoint restore + restart mutation flow (PR-03).
- No interactive history selector UX (PR-04).
- No turn-aware diff or checks-first readiness surface (PR-05).
