# PR-02: Stream Durability Hardening + Agent Mutation JSON Parity

## Goal

Make invocation stream ingestion contract-safe under failure/volume and complete stable mutation-command `--json` outputs for automation.

## Builds On

PR-01 merged.

## Acceptance

- Stream ingestion enforces bounded per-line processing for runner output so oversized lines cannot cause unbounded memory growth.
- Malformed/oversized runner lines are handled deterministically with explicit parse/failure signaling, while valid subsequent stream processing remains contract-consistent.
- Raw-log and normalized-stream write failures are surfaced deterministically (not silently dropped) with operation outcomes and attention/error signaling that scripts and operators can rely on.
- Normalized stream event sequencing remains monotonic and durable across append/restart boundaries for all reachable append paths; legacy paths must either preserve canonical sequence continuity or be retired from active use.
- `agent start`, `agent stop`, `agent kill`, `agent land`, and `agent discard` support stable machine-readable `--json` responses through one shared mutation envelope with deterministic success/error fields suitable for non-interactive automation.
- Mutation-command failure paths in `--json` mode are contract-first and do not require parsing human-formatted stderr/stdout text.
- Existing `agent chat` and `agent restart` JSON surfaces remain backward compatible while converging to the shared mutation-envelope contract.

## Non-Goals

- No new invocation-scoped `agent review`, `agent pr ...`, or `agent merge` behavior (Slice S5 scope).
- No reports-v2 artifact strictness or broader CLI ergonomics cleanup (Slice S6 scope).
- No full semantic parser feature parity expansion beyond S4 fallback and durability guarantees.

## Key Decisions (if any beyond L2)

**Mutation JSON contract posture**: mutation commands use one stable envelope contract with deterministic success and typed error semantics; `chat`/`restart` compatibility is preserved through additive transition behavior during v2.1.

**Stream failure posture**: stream/log persistence is correctness-critical contract data, not best-effort telemetry; silent write-loss behavior is not acceptable.

**Sequence continuity posture**: any reachable flow that appends normalized events must preserve monotonic continuity; divergent legacy append behavior is not acceptable.
