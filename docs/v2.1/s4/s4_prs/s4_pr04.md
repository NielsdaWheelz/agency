# PR-04: Mutation `--json` Parity Completion for `agent chat` + `agent restart`

## Goal

Complete mutation-contract parity so `agent chat --json` and `agent restart --json` provide deterministic machine-readable output for both success and failure paths.

## Builds On

PR-03 merged state.

## Acceptance

- `agent chat --json` and `agent restart --json` emit deterministic structured JSON for CLI-side validation failures, including bounded prompt/selector/input validation paths.
- `agent chat --json` and `agent restart --json` emit deterministic structured JSON for daemon-declared failures (`ok=false` responses), preserving typed error semantics and operator guidance.
- `agent chat --json` and `agent restart --json` emit deterministic structured JSON for transport/control-plane failures (daemon connectivity/version-path failures) so automation does not depend on human stderr/stdout parsing.
- Mutation-command JSON output remains contract-first: failure outcomes are script-classifiable from machine-readable fields, without fallback to human-formatted text parsing.
- Success-path JSON for `agent chat` and `agent restart` remains strictly backward compatible for existing scripts (additive-only changes; no removals or renames).
- Tests cover success/failure JSON behavior across all mutation commands (`start`, `stop`, `kill`, `land`, `discard`, `chat`, `restart`) with assertions on stable envelope semantics and command-specific success data.

## Non-Goals

- No changes to follow-up prompt idempotency semantics, invocation timeline behavior, or checkpoint mapping rules.
- No changes to runner capability model, stream-ingestion durability logic, or restart lifecycle behavior beyond JSON contract parity.
- No invocation-scoped `agent review` / `agent pr` / `agent merge` behavior (Slice S5 scope).
- No reports-v2 contract or ergonomics backlog work (Slice S6 scope).

## Key Decisions (if any beyond L2)

**Compatibility posture for parity completion**: converge `chat`/`restart` onto stable mutation JSON without removing or renaming currently script-consumed success fields during v2.1; success changes in this PR are additive-only.
