# PR-05: Runner Launch Matrix Parity for Headed/Headless `agent start`

## Goal

Make all v2.1 target runners launch reliably from one capability model across headed and headless `agent start` flows.

## Builds On

PR-04 merged state.

## Acceptance

- `agency agent start --runner <id>` accepts canonical v2.1 targets and compatibility aliases, then resolves to one canonical runner identity deterministically.
- Canonical targets `claude-code`, `codex`, `amp`, `opencode`, `cursor`, and `droid` are all launchable through capability-defined runner plans rather than per-call ad hoc branching.
- Headless start with `--prompt` applies runner-specific documented non-interactive subcommands/flags/parameters for each target so users do not manually translate runner syntax.
- Headed start applies capability-defined interactive launch behavior for each target; unsupported runner/mode combinations fail with typed deterministic error contracts.
- Reserved-argument conflict handling is enforced consistently across start/restart and headed/headless launch paths.
- Unknown runner IDs fail with deterministic typed unknown-runner errors suitable for automation.
- Tests cover runner identity resolution (including aliases), headed/headless launch planning for all target runners, and deterministic failure contracts for unknown-runner and reserved-arg conflicts.

## Non-Goals

- No semantic stream-adapter expansion beyond existing raw-log fallback guarantees.
- No mutation `--json` envelope expansion beyond PR-04 parity completion.
- No invocation-scoped `agent review` / `agent pr` / `agent merge` behavior (Slice S5).

## Key Decisions (if any beyond L2)

**Canonical identity stability with compatibility aliases**: keep constitution-defined canonical IDs (`cursor` included) and support legacy compatibility input aliases (at minimum `claude`) that resolve to canonical identities in metadata and JSON outputs.

**Capability metadata as launch source of truth**: runner-specific base launch templates (subcommands/flags/params), mode support, and reserved-arg policy are centralized in capability contracts, not scattered conditional logic.
