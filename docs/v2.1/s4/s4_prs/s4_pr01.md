# PR-01: Runner Capability Engine + Launch-Contract Convergence

## Goal

Replace hardcoded runner branching with one capability-driven runner contract that governs validation, canonical identity, and launch behavior consistently across start and restart flows.

## Builds On

Slice S3 merged state.

## Acceptance

- Start/control-plane/restart surfaces accept the v2.1 runner target set (`claude-code`, `codex`, `amp`, `opencode`, `cursor`, `droid`) through capability-driven validation rather than runner-name allowlists.
- Legacy `claude` input is accepted as a compatibility alias, while persisted and emitted runner identity is canonicalized to `claude-code` across lifecycle metadata and automation-facing outputs.
- Unknown runner identifiers fail with deterministic typed errors suitable for scripts, without relying on human-formatted message parsing.
- Runner launch behavior is capability-scoped and consistent across start and restart: required base args, reserved-flag conflict handling, and launch-mode support rules do not diverge by entry point.
- Runners without semantic adapters execute successfully with explicit raw-log-first fallback semantics; invocation lifecycle and transcript/log read surfaces remain functional without implying semantic-event guarantees.
- Headless runtime environment assembly for start and restart follows one deterministic merge rule with stable precedence, duplicate-key elimination, and stable output ordering.

## Non-Goals

- No mutation-command `--json` parity rollout for `agent start`, `agent stop`, `agent kill`, `agent land`, or `agent discard` (owned by PR-02).
- No stream-ingestion durability hardening for write-failure surfacing or oversized-line memory bounds beyond what is strictly required for capability fallback behavior (owned by PR-02).
- No invocation-scoped review/PR/merge command-family behavior (Slice S5 scope).

## Key Decisions (if any beyond L2)

**Canonical runner identity**: treat `claude-code` as canonical and `claude` as input-only compatibility alias during v2.1 migration; canonical IDs are the only persisted and emitted runner identities.

**Single capability source of truth**: one shared runner capability model defines validation, mode support, launch shaping, reserved-flag policy, and semantic-adapter availability for both CLI and daemon entry paths.

**Fallback contract posture**: when semantic parsing is unavailable, the system must explicitly operate in raw-log-first mode and preserve lifecycle continuity without fabricating semantic outcomes.

**Deterministic launch environment policy**: adopt one precedence rule for environment assembly across start/restart so behavior is reproducible and test-stable across runners and execution paths.
