# PR-08: Cursor Manual Closure and Follow-Up Parity

## Goal

Seal Cursor (`agent`) runner parity so prompt echoing, follow-up turns, checkpoint mapping, and retained history remain consistently readable across every S8 surface.

## Builds On

Slice S8 merged baseline and the manual validation evidence in `docs/v2.1/s8/s8_manual_validation_20260319.md`.

## Historical / Manual Context

- Cursor historically had the prompt-echo bug where the initial prompt rendered as `Tool Result`.
- Manual invocation `20260319074340-1a8e` showed the current intended behavior: the initial prompt rendered as `prompt`, the follow-up rendered as `follow-up`, and the follow-up turn completed successfully.
- The remaining observed gap on this runner was the shared `agent diff --turn` mismatch.

## Acceptance

- Cursor’s echoed initial prompt and resumed follow-up prompt render as `prompt` / `follow-up` entries in `agent history`; they must never appear as `Tool Result`.
- Cursor history must preserve assistant text, file reads, searches, edits, shell commands, and follow-up continuation without blank rows in:
  - `agent history`
  - `agent history --last`
  - `agent history --json`
  - `agent history --json --last`
- `agency agent show --json`, `agency agent review`, `agency checkpoint ls --invocation`, and `agency agent restart --history` converge on the same latest turn, checkpoint id, changed path list, and readiness state for Cursor invocations.
- `agency agent diff --turn <latest_turn>` for Cursor shows the file change associated with the checkpoint shown by `show` / `review` / `checkpoint ls`; it must not report `(no changes)` for a turn that visibly changed a file.
- A live Cursor follow-up sent with `agency agent chat --prompt-file ... --json` resumes in the same invocation, finishes cleanly, and leaves the invocation in `finished` / `ready for review`.
- After `agency agent discard`, the retained Cursor artifacts remain readable through `show`, `history`, `logs`, `logs --kind stream`, `logs --kind stderr`, and `checkpoint ls`.

## Manual Validation

1. Build the branch binary from repo root:
   - `GOCACHE=/tmp/agency-gocache go build -o ./agency ./cmd/agency`
2. Start a live Cursor invocation:
   - `./agency agent start --worktree <wt> --headless --runner cursor --name s8-manual-cursor --prompt-file docs/v2.1/s8/manual_prompts/seed_live.txt --json`
3. While it is active, inspect:
   - `./agency agent show <id> --json`
   - `./agency agent history <id>`
   - `./agency agent history --json <id>`
   - `./agency agent logs <id> --kind stream`
   - `./agency agent logs <id> --follow`
   - `./agency watch`
4. Send the follow-up while the invocation is still active:
   - `./agency agent chat <id> --prompt-file docs/v2.1/s8/manual_prompts/followup_live.txt --json`
5. After completion, inspect:
   - `./agency agent history --last <id>`
   - `./agency agent history --json --last <id>`
   - `./agency checkpoint ls --invocation <id>`
   - `./agency agent review <id>`
   - `./agency agent diff <id> --turn <latest_turn_id>`
   - `./agency agent restart <id> --history`
6. Discard and verify retention:
   - `./agency agent discard <id> --json`
   - re-run `show`, `history`, `logs`, `logs --kind stream`, and `checkpoint ls`

## Non-Goals

- No Claude lifecycle repair in this PR.
- No Codex-specific raw-output fidelity repair unless a shared projection change is required for Cursor parity.

## Key Decisions

**Prompt echo is first-class context, not noise**: Cursor’s echoed prompt/resume text must remain visible as prompt/follow-up context rather than being hidden or mislabeled as tool output.

**Cursor closure is regression-oriented**: this PR is done only when the previously broken prompt/follow-up rendering stays correct under a real live follow-up run, not just fixtures.
