# PR-09: Claude Follow-Up Completion and Status Correctness

## Goal

Fix Claude headless follow-up lifecycle reduction so successful Claude invocations finish cleanly and stay consistent across history, review, status, and retention surfaces.

## Builds On

Slice S8 merged baseline and the manual validation evidence in `docs/v2.1/s8/s8_manual_validation_20260319.md`.

## Observed Failure

- Manual invocation `20260319074013-b0d6` emitted successful `final` events for both the seed turn and the follow-up turn in the stream log.
- Live Claude runs can also coalesce a pre-final follow-up into a single successful `final`, creating ambiguous turn accounting under stdin chat delivery.
- Despite that, `agency agent show --json` and `agency agent review` remained `running` / `working`.
- Manually stopping the invocation after those successful finals changed it to:
  - `status: failed`
  - `exit_reason: stopped`
  - `exit_code: 0`
- The same invocation also showed the shared `agent diff --turn` mismatch.

## Acceptance

- After successful Claude seed + follow-up work completes, the invocation automatically transitions to `finished` / `ready for review` within a bounded delay and without requiring `agency agent stop`.
- Once the Claude stream records a successful `final` for the active turn, `agency agent show --json`, `agency agent review`, `agency agent ls`, and `agency watch` must stop reporting that invocation as `running` / `working`.
- If `agency agent stop` is issued after the Claude invocation has already completed successfully, the invocation must remain successful or the stop must no-op; it must not be relabeled `failed` with `exit_reason: stopped` and `exit_code: 0`.
- Claude follow-up prompt events and second-turn activity remain visible and ordered correctly in:
  - `agent history`
  - `agent history --json`
  - `agent logs`
  - `agent logs --kind stream`
  - `agent restart --history`
- `agency agent diff --turn <latest_turn>` for Claude shows the same changed path/checkpoint reported by `show` / `review` / `checkpoint ls`; it must not print `(no changes)` for a turn with a visible changed file.
- After `agency agent discard`, Claude history, logs, checkpoint listing, and status details remain readable from invocation-owned artifacts.

## Manual Validation

1. Build the branch binary from repo root:
   - `GOCACHE=/tmp/agency-gocache go build -o ./agency ./cmd/agency`
2. Start a live Claude invocation:
   - `./agency agent start --worktree <wt> --headless --runner claude-code --name s8-manual-claude --prompt-file docs/v2.1/s8/manual_prompts/seed_live.txt --json`
3. While it is active, inspect:
   - `./agency agent show <id> --json`
   - `./agency agent history <id>`
   - `./agency agent history --json <id>`
   - `./agency agent logs <id> --follow`
   - `./agency watch`
4. Send a live follow-up:
   - `./agency agent chat <id> --prompt-file docs/v2.1/s8/manual_prompts/followup_live.txt --json`
5. Wait for both turns to finish and confirm that no manual stop is needed:
   - `./agency agent show <id> --json`
   - `./agency agent review <id>`
   - `./agency agent history --last <id>`
   - `./agency agent history --json --last <id>`
6. Validate post-completion parity:
   - `./agency checkpoint ls --invocation <id>`
   - `./agency agent diff <id> --turn <latest_turn_id>`
   - `./agency agent restart <id> --history`
7. Explicitly test the previous failure mode:
   - if the invocation is already complete, `./agency agent stop <id> --json` must not convert it to `failed`
8. Discard and verify retention:
   - `./agency agent discard <id> --json`
   - re-run `show`, `history`, `logs`, `logs --kind stream`, and `checkpoint ls`

## Non-Goals

- No broad Claude TUI redesign or assistant-summary formatting changes outside the status/follow-up correctness work.
- No Cursor/Codex-specific parser changes except shared code required for the Claude fix.

## Key Decisions

**Claude follow-ups use session resume, not stdin streaming**: each follow-up is queued and launched as an explicit resume turn (`--resume <session_id>`), eliminating ambiguous multi-prompt stdin turn coalescing from lifecycle accounting.

**Stream final is authoritative for completion**: once a Claude resume turn emits successful `final`, the daemon-side lifecycle reducer must converge all human-facing surfaces to a completed state.

**Successful completion is sticky**: later stop/cleanup actions must not overwrite a successful Claude outcome with a spurious failed state.
