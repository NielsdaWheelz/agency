# PR-02: Replayable Claude, Codex, and Cursor Converters

## Goal

Update the supported runner converters so current raw outputs normalize into one canonical runner event model and unknown output fails safely.

## Builds On

PR-01 merged durable replay inputs and fixture-capture baseline.

## Acceptance

- Current Claude, Codex, and Cursor outputs replay into canonical normalized events for prompts, messages, tool activity, tool results, file edits, usage, and errors.
- Supported runner outputs that were previously misclassified or lost now surface correct semantic categories instead of blank history rows or misleading tool-result labels.
- Unknown, malformed, or oversized runner output is preserved and surfaced with parse or truncation diagnostics instead of silently disappearing.
- Regression fixtures cover the current supported runner shapes that motivated this slice, including current Codex and Cursor behaviors.
- Downstream consumers can read one runner-neutral normalized event model without embedding runner-specific display logic.

## Non-Goals

- No full migration of history, restart, watch, or review surfaces in this PR.
- No new runner-family support beyond Claude, Codex, and Cursor.
- No final human-rendering cleanup beyond what is needed to validate normalized output.

## Key Decisions (if any beyond L2)

**Runner-specific at ingestion, runner-neutral downstream**: converter logic remains per-runner, but the emitted event categories are shared so later projections and UIs do not branch by runner.

**Use action families, not per-tool-name rendering contracts**: PR-02 should normalize current runner output into stable families such as message, command execution, file read, file change, search, web action, final, error, and unknown event. Exact tool names and nested runner payloads remain available as metadata, but downstream surfaces should not depend on them for basic usability.

**Unknown output must remain usable**: when the converter sees a new or partially understood runner event shape, it should still emit a typed diagnostic event and preserve the raw payload for replay, rather than dropping it or coercing it into a misleading category.
