# PR-02: Delegation-First Watch Actions + Session-Ended Resilience

## Goal

Enable a first, production-safe set of in-watch invocation actions by delegating to canonical Agency behavior while keeping the full-screen workspace stable through recoverable failures, including headed session-ended paths.

## Builds On

PR-01 merged watch shell and daemon-snapshot composition model.

## Acceptance

- Watch exposes an explicit first action set inside the workspace: `enter`, `open`, and `pr sync`.
- Each watch action delegates to canonical invocation/worktree command-contract behavior instead of re-implementing policy in watch.
- Delegated action behavior preserves existing deterministic validation, confirmation, and typed error semantics (including existing confirmation-required behavior where applicable), rather than introducing watch-specific alternatives.
- When enter/attach is attempted for a headed invocation whose tmux session has ended, watch surfaces deterministic session-ended guidance aligned with `E_SESSION_ENDED` semantics.
- Session-ended action outcomes are non-destructive to the workspace: watch remains open, selection/context is preserved, and users can continue monitoring/navigation without restarting watch.
- Recoverable action failures (for example contract/validation/precondition failures) are surfaced in-session and do not collapse the watch runtime.
- Action outcomes keep readiness monitoring actionable: after action handling and refresh, users can still distinguish progression-ready vs progression-blocked state and see canonical blocking reasons/diagnostics.
- Canonical scriptable CLI contracts remain unchanged (`agent ... --json` stays the machine-facing contract; watch remains additive human-interactive surface).
- Coverage asserts delegation behavior, typed session-ended continuity handling, and non-collapse behavior for recoverable action failures.

## Non-Goals

- Does not redesign tmux lifecycle to keep headed sessions alive after runner exit.
- Does not introduce new readiness/blocking taxonomy or daemon-side readiness logic.
- Does not ship `merge` as an in-watch action in this PR.
- Does not replace CLI-first scriptable contracts with watch-specific machine interfaces.
- Does not add GUI/web dashboard scope or merge-queue/autonomous progression policy.

## Key Decisions (if any beyond L2)

**Delegation boundary**: watch actions are orchestration wrappers over canonical command/contract semantics, not a second policy engine.

**MVP action-set boundary**: PR-02 ships `enter`, `open`, and `pr sync` only; `merge` is intentionally deferred to keep confirmation complexity and irreversible-flow risk out of the first action pass.

**Session-ended posture**: `E_SESSION_ENDED` is treated as a first-class, recoverable in-workspace state with actionable guidance, not a fatal watch error.
