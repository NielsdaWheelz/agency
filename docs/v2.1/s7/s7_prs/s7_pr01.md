# PR-01: Canonical `agency watch` TUI Shell + Daemon-Snapshot Readiness Workspace

## Goal

Deliver a production-grade, full-screen `agency watch` workspace that provides canonical invocation readiness monitoring via existing daemon read/review contracts.

## Builds On

Slice S6 merged baseline (`agent review` / `agent pr sync` / `agent merge` readiness and report contracts are stable and canonical).

## Acceptance

- In an interactive terminal, `agency watch` enters a full-screen keyboard-navigable workspace, refreshes periodically, and restores the prior shell state cleanly on exit.
- The watch shell runs on the dedicated TUI stack (Bubble Tea v2 + Bubbles + Lip Gloss) with deterministic terminal lifecycle setup/teardown, not bespoke ANSI redraw loops as the primary architecture.
- In non-interactive contexts, `agency watch` fails deterministically with interactive-required behavior and an actionable recovery hint.
- Watch workspace state is composed from canonical daemon read surfaces for repos/worktrees/invocations/review; no local store scanning is used to derive watch state.
- Watch snapshot composition preserves canonical daemon list semantics (existing filtering/sorting behavior) and does not silently truncate large fleets when list pagination is required.
- Selecting an invocation shows canonical review/readiness output: verdict, blocking reasons, report diagnostics, and navigation context aligned with invocation review semantics.
- Workspace rendering makes progression-ready vs progression-blocked state visible across mixed invocations without redefining readiness taxonomy.
- Selection/focus remains stable across refresh cycles by canonical entity identity, including when list ordering changes.
- Recoverable daemon/read failures are surfaced in-session with deterministic diagnostics and retry continuity, without collapsing the watch workspace.
- Terminal lifecycle cleanup is deterministic on normal exit and interruption/error paths (screen/cursor/input state restored before returning to shell).
- Existing `agent ... --json` machine contracts remain unchanged; watch is additive as a human-interactive surface.

## Non-Goals

- No mutation/action dispatch from watch in this PR (read-only seed only).
- No new daemon event-stream dependency.
- No new daemon readiness/blocking logic or parallel readiness taxonomy.
- No watch-specific machine-readable API contract.
- No headed-session attach/enter resilience flow (`E_SESSION_ENDED` handling is deferred to PR-02).

## Key Decisions (if any beyond L2)

**Interactive failure contract alignment**: non-interactive startup follows existing typed interactive-preflight behavior (`E_NOT_INTERACTIVE`) so automation and users get deterministic failure semantics plus a recovery hint.

**Snapshot completeness over list pagination**: watch must consume daemon cursor pagination during refresh so high-cardinality repo/worktree/invocation views remain complete and deterministic.
