# pr-02: shared cli navigation resolution kernel

Last updated: 2026-02-25
Status: implemented
Upstream l2: `docs/v2.1/s2/s2_spec.md`
Upstream l3: `docs/v2.1/s2/s2_roadmap.md` (PR-02)

## goal
Establish one shared daemon-first CLI read-routing and navigation selection/resolution kernel that downstream `worktree` and canonical `agent` command migrations consume without redefining routing, ambiguity, daemon-failure, or TTY-preflight semantics.

## context
- `docs/sdlc/L4-pr-spec.md:25` requires a full skeleton first, then acceptance-cluster micro-loops, then hardening.
- `docs/v2.1/s2/s2_roadmap.md:76` defines PR-02 as the shared CLI navigation resolution kernel, not a command-family rollout.
- `docs/v2.1/s2/s2_roadmap_ownership.md:11` assigns PR-02 ownership of shared read-routing lifecycle, selection/resolution lifecycle, fallback boundary, ambiguity/daemon-unavailable/TTY preflight semantics.
- `docs/v2.1/s2/s2_spec.md:120` and `docs/v2.1/s2/s2_spec.md:134` define PR-02-owned domain models `NavigationSelection` and `NavigationCommandIntent`.
- `docs/v2.1/s2/s2_spec.md:169` and `docs/v2.1/s2/s2_spec.md:203` define the PR-02-owned state machines (CLI Read Routing Lifecycle and Navigation Selection Lifecycle).
- `docs/v2.1/s2/s2_spec.md:395` defines the normative CLI Navigation Resolution Contract (including `E_DAEMON_CONNECTION_FAILED`, `E_DAEMON_INCOMPATIBLE`, `E_NO_REPO_CONTEXT`, `E_AMBIGUOUS`).
- `docs/v2.1/s2/s2_spec.md:476`, `docs/v2.1/s2/s2_spec.md:477`, `docs/v2.1/s2/s2_spec.md:478`, and `docs/v2.1/s2/s2_spec.md:479` lock ambiguity candidate preservation, TTY preflight, scriptable selection identity, and no post-routing local-store discovery.
- `internal/commands/repo.go:49` already provides shared daemon-aware repo context resolution (`ResolveRepoViaClient`), which PR-02 should consume rather than duplicate.
- `internal/commands/worktree.go:426` and `internal/commands/worktree.go:511` still re-resolve worktree targets via local store after daemon repo resolution (`worktree open/shell`), which PR-03 will fix by consuming PR-02.
- `internal/commands/agent.go:608` and `internal/commands/agent.go:1109` still re-resolve invocations via local store after daemon repo resolution (`agent attach/open`), which PR-04/PR-05 will fix by consuming PR-02.
- `internal/commands/agent.go:562` has command-local TTY preflight for `agent attach`; PR-02 should centralize this behavior as shared kernel semantics.
- `internal/daemon/read_types.go:21` and `internal/daemon/read_types.go:24` show daemon read errors can include structured `details` (including ambiguity candidates).
- `internal/daemonclient/client.go:624` and `internal/daemonclient/client.go:750` currently convert daemon API errors to `errors.New(code, message)` and drop `hint`/`details`, which directly impacts PR-02 ambiguity candidate preservation.
- `internal/errors/errors.go:216` constrains `AgencyError.Details` to `map[string]string`, which may be too narrow for direct passthrough of daemon `details.candidates` arrays.

## dependencies
- PR-01 merged (`docs/v2.1/s2/s2_prs/s2_pr01.md`) and available as current baseline daemon read contract behavior.

## deliverables

### `internal/commands/navigation_kernel.go` (new)
- introduce shared PR-02 kernel helpers/types for:
  - CLI read-routing lifecycle orchestration for single-target read/navigation commands:
    - repo context resolution via `ResolveRepoViaClient`
    - daemon ensure/connect + API compatibility check
    - explicit no-local-discovery fallback after routing starts (except bootstrap/health boundary behavior)
  - navigation selection normalization for `explicit_ref`, `machine_ref`, and `list_row` selector sources
  - daemon-first target resolution helpers for worktree and invocation targets via daemon read endpoints (`GetWorktree`, `GetInvocation`)
  - shared TTY preflight for interactive attach/enter semantics (returns `E_NOT_INTERACTIVE` before dispatch)
  - shared ambiguity and daemon failure translation preserving S2 error semantics (`E_AMBIGUOUS`, `E_DAEMON_CONNECTION_FAILED`, `E_DAEMON_INCOMPATIBLE`, `E_NO_REPO_CONTEXT`)
- define kernel behavior in a command-family-agnostic way:
  - no command registration / cobra wiring
  - no editor/shell/tmux dispatch execution
  - no compatibility alias dispatch behavior (PR-05)
  - no command-family-specific UX text decisions (PR-03/PR-04)
- enforce the S2 invariant that target resolution after daemon routing begins does not use local store scans.

### `internal/commands/navigation_kernel_test.go` (new)
- add unit/integration tests for shared routing and selection semantics:
  - routing lifecycle order and explicit failure behavior (repo context -> daemon -> resolve -> dispatch-preconditions)
  - daemon unavailable and daemon incompatible errors outside bootstrap/health fallback boundary
  - ambiguous target resolution returns S2 ambiguity semantics with preserved candidate data (see D-002)
  - TTY preflight rejects interactive attach/enter flows in non-interactive sessions before dispatch
  - deterministic selection identity for `explicit_ref`, `machine_ref`, and daemon-sourced list-row inputs used by downstream path/open/shell/enter flows
- tests must validate kernel behavior directly without requiring PR-03/PR-04 command-family migrations to be merged.

### `internal/daemonclient/client.go`
- add a narrowly scoped, typed read-API error passthrough path used by PR-02 kernel resolution calls so daemon `hint` and structured `details` are preserved for ambiguity and failure semantics.
- preserve at least:
  - `error_code`
  - `message`
  - `hint`
  - raw structured `details` (typed field or raw JSON payload)
- keep existing daemonclient methods backward-compatible for current call sites:
  - PR-02 may add parallel helper(s) or an opt-in path
  - PR-02 must not silently change the error shape returned by unrelated existing callers
- limit daemonclient changes to read/error propagation support needed by the shared kernel; no unrelated endpoint behavior changes.

### `internal/daemonclient/client_test.go` (new)
- add focused tests asserting:
  - daemon read error code/message/hint/details are preserved for PR-02 kernel consumers
  - candidate details are recoverable without parsing human-readable error text
  - existing non-passthrough client methods remain behaviorally unchanged

## acceptance tests

### file: `internal/commands/navigation_kernel_test.go`

**test: `TestNavigationKernel_ReadRoutingLifecycle_OrderAndGuards`**
- input: kernel test harness with fake repo resolver, fake daemon client, and hook counters; single-target navigation intent (`worktree open` / non-interactive dispatch stub).
- output:
  - repo context resolution occurs before daemon ensure/version check
  - daemon target resolution occurs before dispatch precondition/result handoff
  - no local-store discovery callback is invoked after daemon routing begins
  - kernel returns resolved target payload (`resolved_repo_id`, `resolved_id`, `resolved_path`) on success

**test: `TestNavigationKernel_RepoContextRequired_ReturnsENoRepoContext`**
- input: kernel invocation with no `--repo`, CWD outside git repo, and single-target intent requiring repo scope.
- output:
  - returns `E_NO_REPO_CONTEXT`
  - no daemon target resolution attempted
  - no local-store discovery fallback attempted

**test: `TestNavigationKernel_NoLocalDiscoveryAfterDaemonRouting`**
- input: kernel harness with a local-discovery spy callback that fails test if called after daemon routing; daemon returns explicit connection failure.
- output:
  - returns daemon failure (`E_DAEMON_CONNECTION_FAILED` or `E_DAEMON_INCOMPATIBLE` depending setup)
  - local-discovery spy is not called

**test: `TestNavigationKernel_BootstrapFallbackBoundary_GuardedCallback`**
- input: kernel test harness with synthetic boundary-eligible routing intent (`bootstrap_fallback_allowed=true`) and injected fallback callback spy; daemon ensure/connect path fails before target resolution.
- output:
  - kernel invokes the supplied fallback callback only when boundary fallback policy is explicitly enabled
  - callback invocation occurs after daemon failure and before final render/dispatch handoff
  - same routing path with boundary policy disabled does not invoke callback and returns explicit daemon failure
  - same routing path with boundary policy enabled but callback absent does not infer fallback and returns explicit daemon failure
  - lifecycle ordering remains `resolve_repo_context -> daemon_attempt -> guarded_fallback_callback -> render_or_dispatch_handoff` for the boundary-enabled callback case

**test: `TestNavigationKernel_DaemonUnavailable_NoFallback`**
- input: daemon ensure/connect path returns connection failure for a normal S2 read/navigation command.
- output:
  - returns `E_DAEMON_CONNECTION_FAILED`
  - no local store scan / legacy resolver path attempted

**test: `TestNavigationKernel_DaemonIncompatible_NoFallback`**
- input: daemon health/version check returns API mismatch for a normal S2 read/navigation command.
- output:
  - returns `E_DAEMON_INCOMPATIBLE`
  - no local store scan / legacy resolver path attempted

**test: `TestNavigationKernel_InteractivePreflight_RequiresTTY`**
- input: interactive navigation intent (`attach` or `enter`) with `requires_tty=true` and `isInteractive=false`.
- output:
  - returns `E_NOT_INTERACTIVE`
  - failure occurs before dispatch callback
  - error includes a non-empty recovery hint with an interactive-terminal recovery cue

**test: `TestNavigationKernel_SelectionIdentity_StableForDispatch`**
- input: one worktree and one invocation selection resolved via daemon DTOs; kernel emits navigation selection/result for `path|open|shell|enter` intents.
- output:
  - stable `resolved_repo_id` and `resolved_id` preserved across action intents
  - `resolved_path` preserved for `path|open|shell`
  - no action intent rewrites selector identity

**test: `TestNavigationKernel_NormalizeMachineSelectorInput`**
- input: structured repo-scoped machine-selection input(s) at the kernel boundary (no opaque token grammar required in PR-02).
- output:
  - normalizer returns deterministic `NavigationSelection` with `selector_source=machine_ref`
  - fleet/global machine selection without explicit `repo_id` fails explicitly
  - invalid structured inputs fail explicitly (no silent fallback to heuristic parsing or human-output parsing)

**test: `TestNavigationKernel_ListRowSelection_UsesDaemonIDs`**
- input: daemon-sourced list row identity payload for invocation/worktree with IDs and repo ID.
- output:
  - selection normalization prefers daemon IDs/repo ID over display labels
  - downstream resolution call uses deterministic IDs/refs without local scanning

**test: `TestNavigationKernel_ExplicitRefSelection_Deterministic`**
- input: explicit CLI ref (`alpha`, unique prefix, full ID) and repo-scoped intent.
- output:
  - selection normalization preserves original ref and repo scope
  - daemon resolution returns deterministic target or explicit ambiguity/not-found error

**test: `TestNavigationKernel_ResolveWorktree_AmbiguousPreservesCandidates`**
- input: kernel worktree target resolution where daemon returns ambiguous error with candidate details.
- output:
  - returns `E_AMBIGUOUS` for navigation-resolution ambiguity
  - kernel error exposes machine-readable candidate data (not message text) with preserved candidate count and preserved per-candidate identity fields needed for retry (at minimum repo scope + worktree identifier/ref)
  - kernel does not parse candidate data from human-readable error text

**test: `TestNavigationKernel_ResolveInvocation_AmbiguousPreservesCandidates`**
- input: kernel invocation target resolution where daemon returns ambiguous error with candidate details.
- output:
  - returns `E_AMBIGUOUS` for navigation-resolution ambiguity
  - kernel error exposes machine-readable candidate data (not message text) with preserved candidate count and preserved per-candidate identity fields needed for retry (at minimum repo scope + invocation identifier/ref)
  - kernel does not parse candidate data from human-readable error text
