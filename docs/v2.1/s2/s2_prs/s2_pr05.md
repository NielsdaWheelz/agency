# PR-05: Compatibility Adapters + Command-Policy Enforcement

## Goal

Preserve v2.1 compatibility command surfaces while enforcing S2 command-policy boundaries by routing compatibility target resolution through the same daemon-first contract as canonical `agency agent` navigation.

## Builds On

PR-03 and PR-04 merged (with PR-01 and PR-02 already in place).

## Acceptance

- `agent attach` delegates target resolution through the same daemon-first invocation navigation resolution used by canonical `agent enter`, while preserving headed attach compatibility behavior.
- Legacy top-level `path`, `open`, and `attach` delegate target resolution through the same canonical/shared daemon-first path and preserve deterministic script-safe exit behavior.
- Legacy top-level `resume` remains available with documented compatibility dispatch behavior; `resume --restart` remains compatibility-scoped headed-only/non-checkpoint behavior.
- Compatibility wrappers preserve deterministic failure semantics and exit behavior for ambiguity, daemon-unavailable/incompatible failures, and interactive TTY preflight outcomes.
- Compatibility commands may emit non-breaking deprecation messaging without changing success/failure or dispatch semantics.
- Compatibility surfaces do not perform post-daemon local-store target discovery for invocation/worktree resolution.

## Non-Goals

- Does not assign canonical `agent restart` semantics or implement checkpoint-aware restart/chat continuation behavior.
- Does not expand canonical command families beyond S2 policy (`agent path/open/shell/enter` plus existing worktree surfaces).
- Does not change daemon read endpoint contracts, list-filter validation, or shared navigation-kernel semantics.
- Does not redefine legacy `resume` into a new canonical workflow.

## Key Decisions (if any beyond L2)

**Compatibility restart boundary**: keep `resume --restart` as the S2 compatibility restart path and explicitly keep it headed-only/non-checkpoint.

**Deprecation posture**: permit compatibility-surface guidance/warnings only when they are non-breaking and preserve deterministic exit behavior.
