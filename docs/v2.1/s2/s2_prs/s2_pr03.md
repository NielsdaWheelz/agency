## goal
Converge the `worktree` command family (`ls/show/path/open/shell`) onto daemon-first reads and PR-02 shared navigation resolution without post-daemon local-store target re-resolution.

## deliverables

### `internal/commands/worktree.go`
- migrate `worktree path`, `worktree open`, and `worktree shell` target resolution onto PR-02 shared navigation kernel (`ResolveNavigation`) using `target_kind=worktree` and `command_family=worktree`.
- remove post-daemon local-store target re-resolution for `worktree open` and `worktree shell`:
  - no `integrationworktree.NewService(...).Resolve(...)` for target discovery/path lookup in these commands after daemon routing begins.
- preserve existing local dispatch responsibilities after daemon path resolution:
  - `worktree path` prints path only
  - `worktree open` resolves editor config and launches editor at daemon-resolved path
  - `worktree shell` launches shell with cwd set to daemon-resolved path
- preserve `worktree ls`/`worktree show` daemon DTO rendering behavior and JSON serialization semantics (no local DTO field re-derivation).
- switch `worktree show` to daemonclient rich read (`GetWorktreeRich`) so direct single-target read ambiguity preserves daemon-provided candidate details while keeping worktree-read endpoint error semantics (entity-specific ambiguity code).
- consume PR-02 kernel behavior as-is for routing/fallback/ambiguity/TTY semantics; do not duplicate or redefine kernel semantics in `worktree.go`.
- align `worktree open` and `worktree shell` target-resolution error semantics to daemon-first navigation/read behavior and remove the local `E_WORKTREE_BROKEN` target-resolution branch (no post-daemon local meta validation for target lookup).
- accept PR-02 kernel ambiguity normalization for worktree navigation surfaces:
  - `worktree path/open/shell` ambiguity after kernel migration returns `E_AMBIGUOUS` (navigation semantics)
  - `worktree show` ambiguity remains `E_WORKTREE_ID_AMBIGUOUS` (direct read semantics)

### `internal/commands/worktree_test.go` (new)
- add worktree command tests covering PR-03 surface adoption and regressions for:
  - `worktree ls` and `worktree show` daemon-of-record read behavior + daemon DTO rendering
  - `worktree path/open/shell` daemon-first path resolution and no local-store target re-resolution
  - worktree-side scriptable identity/output stability (JSON DTO shape unchanged; human output remains human-oriented)
- use a daemon-backed test harness (short socket-path-safe temp dirs) consistent with existing command tests (for example `internal/commands/agent_test.go`) so PR-03 validates end-to-end command behavior against the daemon read contract.
- include exact assertions for dispatch path/cwd in `worktree open` and `worktree shell` without requiring PR-04/PR-05 surfaces.
- test `worktree open` and `worktree shell` dispatch via executable shims + env overrides (`AGENCY_DATA_DIR`, `AGENCY_CONFIG_DIR`, `SHELL`) in a daemon-backed harness; do not add new production launcher seams/option overrides unless the shim approach proves unworkable.
- keep env-mutating dispatch tests non-parallel (or serialize subtests) to avoid process-env interference.

### `internal/commands/navigation_kernel.go` (no semantic changes expected)
- no PR-03-owned semantic changes.
- if implementation reveals a missing shared behavior needed by both worktree and agent command families, stop and reassign to PR-02 rather than patching PR-03 locally.

## acceptance tests

### file: `internal/commands/worktree_test.go`

**test: `TestWorktreeLS_DaemonOfRecord_RendersDaemonDTO`**
- input: daemon-backed worktree test env with one repo and one or more integration worktrees; run `WorktreeLS` (non-watch, human mode).
- output:
  - command succeeds via daemon list endpoint path
  - rendered human rows contain daemon DTO-derived `worktree_id`, `name`, `branch`, and archived marker behavior
  - no local-store-only derived fields are introduced

**test: `TestWorktreeShow_DaemonOfRecord_RendersDaemonDTO`**
- input: daemon-backed worktree test env; run `WorktreeShow` in human mode with valid `worktree_ref`.
- output:
  - command resolves via daemon get endpoint
  - output fields reflect daemon DTO values (`worktree_id`, `name`, `repo_id`, `branch`, `parent_branch`, `state`, `created_at`, `tree_path`)
  - no local store read path is required for rendering

**test: `TestWorktreeLS_JSONOutput_DirectDaemonDTO`**
- input: daemon-backed worktree test env; run `WorktreeLS` with `JSON=true`.
- output:
  - JSON output decodes directly to `[]daemon.WorktreeDTO`
  - field names/shape match daemon DTO serialization (no wrapper or renamed fields added by CLI)

**test: `TestWorktreeShow_JSONOutput_DirectDaemonDTO`**
- input: daemon-backed worktree test env; run `WorktreeShow` with `JSON=true`.
- output:
  - JSON output decodes directly to `daemon.WorktreeDTO`
  - field names/shape match daemon DTO serialization

**test: `TestWorktreeShow_AmbiguousPreservesCandidates`**
- input: two repos/worktrees that make `worktree show <ref>` ambiguous within command scope.
- output:
  - returns explicit worktree read ambiguity error (`E_WORKTREE_ID_AMBIGUOUS`), not navigation-kernel `E_AMBIGUOUS`
  - candidate details remain machine-readable when daemon provides candidates
  - no candidate parsing from human-readable error message text

**test: `TestWorktreePath_UsesNavigationKernelDaemonResolution`**
- input: daemon-backed worktree test env; run `WorktreePath` with valid ref.
- output:
  - command resolves target via PR-02 kernel path (daemon-first)
  - stdout is exactly the daemon-resolved `tree_path` plus newline
  - no local store target discovery path is used

**test: `TestWorktreeOpen_UsesNavigationKernelDaemonPath_NoLocalResolve`**
- input: daemon-backed worktree test env with executable editor shim that records argv/cwd; run `WorktreeOpen`.
- output:
  - command resolves worktree via PR-02 kernel before dispatch
  - editor is launched with daemon-resolved `tree_path`
  - dispatch cwd equals daemon-resolved `tree_path`
  - no `integrationworktree` local target resolve is used after daemon routing begins
  - corrupt/broken local worktree metadata is not surfaced via local `E_WORKTREE_BROKEN` target-resolution branch on this PR-03 navigation surface
  - test uses process env overrides (`AGENCY_DATA_DIR`, `AGENCY_CONFIG_DIR`) and is not run in parallel with other env-mutating dispatch tests

**test: `TestWorktreeShell_UsesNavigationKernelDaemonPath_NoLocalResolve`**
- input: daemon-backed worktree test env with executable shell shim (via `SHELL`) that records cwd/argv and exits cleanly; run `WorktreeShell`.
- output:
  - command resolves worktree via PR-02 kernel before dispatch
  - shell is launched with cwd equal to daemon-resolved `tree_path`
  - no local target resolve is used after daemon routing begins
  - corrupt/broken local worktree metadata is not surfaced via local `E_WORKTREE_BROKEN` target-resolution branch on this PR-03 navigation surface
  - test uses process env overrides (`AGENCY_DATA_DIR`, `SHELL`) and is not run in parallel with other env-mutating dispatch tests

**test: `TestWorktreeLS_JSONOutput_PreservesRepoScopedIDs`**
- input: daemon-backed multi-repo worktree list setup; run `WorktreeLS` with `--all-repos` and `JSON=true`.
- output:
  - each row preserves daemon DTO `repo_id` + `worktree_id`
  - output remains suitable as the script-safe source for downstream structured selection inputs (PR-02 contract)

**test: `TestWorktreePath_OutputsDaemonResolvedPath`**
- input: worktree ref that resolves to a known daemon DTO `tree_path`.
- output:
  - printed path equals daemon DTO `tree_path`
  - path value is not re-derived from local metadata

**test: `TestWorktreeHumanOutput_RemainsHumanOriented_ScriptContractViaJSON`**
- input: daemon-backed `WorktreeLS` human mode and JSON mode on same dataset.
- output:
  - human output remains current human-oriented row format (no new machine token grammar introduced)
  - JSON output remains the canonical script-safe identity source (`repo_id`, `worktree_id`)

**test: `TestWorktreeNavigation_DoesNotReturnEWorktreeBrokenForTargetResolution`**
- input: daemon-backed test harness with two explicit subtests (`open`, `shell`) that each exercise a target-resolution failure condition after PR-03 migration on the corresponding command surface.
- output:
  - in both subtests, target-resolution errors follow daemon-first navigation semantics
  - in both subtests, no `E_WORKTREE_BROKEN` expectation remains on PR-03 worktree navigation target resolution

**test: `TestWorktreePath_AmbiguityUsesEAmbiguous`**
- input: ambiguous worktree ref against PR-03-migrated `worktree path`.
- output:
  - navigation ambiguity returns `E_AMBIGUOUS` (not `E_WORKTREE_ID_AMBIGUOUS`)
  - candidate details remain machine-readable per PR-02 kernel semantics

**test: `TestWorktreeOpen_AmbiguityUsesEAmbiguous_NoDispatch`**
