## deliverables

### `internal/commands/agent.go`
- preserve `agent ls` daemon-of-record read behavior and daemon DTO rendering / JSON serialization semantics.
- migrate `agent show` to a daemonclient rich read path for direct invocation reads if needed to preserve daemon-provided ambiguity candidate details while keeping direct read endpoint error semantics (decision D-001).
- add canonical `agent path`, `agent shell`, and `agent enter` command functions (or equivalent canonical command-surface handlers) that consume PR-02 shared navigation kernel with:
  - `command_family=agent`
  - `target_kind=invocation`
  - canonical verbs `path|shell|enter`
- migrate canonical `agent open` to shared-kernel daemon-first invocation resolution before local editor dispatch.
- remove post-daemon local invocation target re-resolution for canonical navigation surfaces (`agent path/open/shell/enter`):
  - no local `invocation.NewService(...).Resolve(...)` for target identity/path discovery after daemon routing begins.
- align canonical navigation target-resolution error semantics to daemon-first navigation/read behavior (decision D-004):
  - no local `E_INVOCATION_BROKEN` target-resolution branch on canonical `agent path/open/shell/enter`
  - any retained local filesystem/runtime checks after daemon resolution (for example sandbox path existence before editor/shell dispatch) must use daemon-resolved path data, not local invocation target discovery
- preserve/standardize post-resolution sandbox-missing runtime handling for canonical `agent open/shell` using daemon-resolved `sandbox_path` (decision D-005):
  - sandbox existence checks (if performed) are local runtime checks, not target-resolution discovery
  - canonical `agent path` remains a path-printing surface and must not fail solely because the printed daemon-resolved path no longer exists locally
- preserve local dispatch responsibilities after daemon-first resolution:
  - `agent path` prints daemon-resolved sandbox path
  - `agent open` launches editor at daemon-resolved sandbox path
  - `agent shell` launches shell with cwd set to daemon-resolved sandbox path
  - `agent enter` performs interactive tmux attach dispatch after daemon-first resolution + mode validation
- accept PR-02 navigation-kernel ambiguity normalization for canonical navigation surfaces:
  - `agent path/open/shell/enter` ambiguity returns `E_AMBIGUOUS`
  - direct `agent show` ambiguity remains direct read semantics (`E_INVOCATION_ID_AMBIGUOUS`)
- enforce canonical interactive-mode validity for `agent enter` using daemon-resolved invocation data and preserve `E_INVOCATION_INVALID_MODE` semantics for unsupported mode/action combinations.
- source canonical `agent enter` tmux session name without local invocation target discovery (decision D-002), using daemon-resolved invocation identity as the source of truth for session selection.
- consume PR-02 kernel TTY-preflight behavior for canonical `agent enter`; do not duplicate conflicting TTY checks in a way that changes PR-02 error semantics.

### `internal/cli/cobra/agent.go`
- add canonical `agent path`, `agent shell`, and `agent enter` subcommands to the `agent` command family.
- wire canonical subcommands to PR-04 command handlers without changing `agent attach` compatibility behavior (PR-05 owns alias rollout/policy enforcement).
- preserve existing `agent ls/show/open` command semantics while routing `open` through the PR-04 canonical shared-kernel implementation.
- do not assign canonical `agent restart` semantics.

### `internal/commands/agent_test.go`
- add/extend daemon-backed command tests covering PR-04 surface adoption and regressions for:
  - `agent ls` and `agent show` daemon-of-record read behavior + daemon DTO rendering
  - canonical `agent path/open/shell/enter` daemon-first invocation resolution via PR-02 kernel
  - canonical navigation ambiguity behavior (`E_AMBIGUOUS`) and no-dispatch on ambiguous targets for representative surfaces
  - canonical `agent enter` invalid-mode semantics (`E_INVOCATION_INVALID_MODE`) and no dispatch on invalid mode
  - scriptable identity/output expectations for `agent ls` JSON output and daemon-resolved `agent path`
- prefer daemon-backed executable shims + env overrides for editor/shell dispatch tests (reusing PR-03 pattern) rather than broad new production launcher seams unless proven unworkable.
- keep env-mutating dispatch tests non-parallel (or serialize subtests) when using `AGENCY_DATA_DIR`, `AGENCY_CONFIG_DIR`, or `SHELL`.
- reuse existing `AgentAttach` test seams (`IsInteractive`, `TmuxClient`) when validating canonical `agent enter` pre-dispatch behavior; avoid duplicating PR-02 kernel internals.

### `internal/commands/error_codes_test.go` (optional if needed)
- add/adjust only if canonical `agent enter` error-code regression coverage is placed in the shared error-code test file rather than `agent_test.go`.
- do not move or reinterpret `agent attach` compatibility error-code tests here as part of PR-04 scope.

### `internal/commands/navigation_kernel.go` (no semantic changes expected)
- no PR-04-owned semantic changes.
- if implementation reveals a missing shared behavior that applies to both worktree and agent command families, stop and reassign to PR-02 boundary rather than patching PR-04 locally.
