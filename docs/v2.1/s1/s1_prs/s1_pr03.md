- add PR-03 aggregate-readiness error constants:
  - `E_GATE_SET_DRIFT`
  - `E_GATE_BLOCKED`
- keep string values stable and prefixed with `E_`.

### `internal/s1gates/types.go`
- add PR-03 aggregate evaluation models:
  - `GateStatus` (`gate_id`, `total_items`, `closed_items`, `blocking_items`, `status`)
  - `GatesEvaluateRequest` (`gate_set_source`, `slice`)
  - `GatesEvaluateResult` (`slice`, `gate_a`, `gate_b`, `slice_ready`)
- add constants for canonical aggregate sources:
  - `CanonicalIssueMapPath = "docs/v2.1/constitution.md"`
- keep field names and constraints aligned with L2 `GateStatus` and `/gates/evaluate` response contract.

### `internal/s1gates/issue_map_parser.go`
- implement deterministic parser for `docs/v2.1/constitution.md` issue references.
- parsing rules:
  - accept numbered list items with backtick-wrapped `docs/issues/*.md` paths under all H2 slice sections.
  - ignore non-issue lines and fenced content.
  - preserve deterministic encounter order and also return deterministic occurrence counts per issue path.
  - malformed/empty parse result for expected file shape returns `E_GATE_SET_INVALID`.
- parser output must support PR-03 drift rules without introducing PR-04 change-validation behavior.

### `internal/s1gates/evaluate_gates.go`
- implement `EvaluateGates(req GatesEvaluateRequest, repoRoot string) (*GatesEvaluateResult, error)`.
- request validation:
  - require `req.slice == "S1"`; otherwise `E_GATE_SET_INVALID`.
  - require `req.gate_set_source == CanonicalGateSourcePath`; otherwise `E_GATE_SET_INVALID`.
- aggregate evaluation flow:
  1. parse canonical gate source using PR-01 `ParseGateSet`.
  2. parse canonical issue-map source and compute deterministic per-issue occurrence counts.
  3. evaluate each Gate A and Gate B item via PR-01 `EvaluateGateItem`.
  4. treat item as closed only when `state == closed` and item evaluation has no `blocking_code`.
  5. compute `closed_items`, `total_items`, and `blocking_items` in canonical gate order.
  6. compute gate `status` as `ready` iff `closed_items == total_items`, otherwise `blocked`.
  7. compute `slice_ready` as `gate_a.status == ready && gate_b.status == ready`.
- aggregate error mapping:
  - item-level parse/load failures encountered during aggregate evaluation must surface as `E_GATE_SET_INVALID` with details including `issue_path` and root item error code.
  - item-artifact `E_GATE_SET_INVALID` detail keys are fixed:
    - `issue_path`: failing gate issue path
    - `item_error_code`: underlying item error code (`E_GATE_ITEM_NOT_FOUND` or `E_GATE_ITEM_INVALID`)
    - `item_error_message`: underlying item error message
  - do not return item-level `E_GATE_ITEM_*` codes directly from aggregate surface.
- drift detection:
  - compare canonical Gate A/B membership against issue-map occurrences.
  - drift is present when any Gate A/B issue path is missing from `constitution.md` or appears more than once there.
  - on drift, return `E_GATE_SET_DRIFT`.
  - when multiple drift mismatches exist, choose the first mismatching gate issue path in canonical gate order.
  - `E_GATE_SET_DRIFT` detail keys are fixed:
    - `issue_path`: first mismatching canonical gate issue path
    - `issue_map_count`: observed issue-map occurrence count for that path
    - `drift_kind`: `missing` when count is `0`, `duplicate` when count is `>1`
  - non-gate issue-map entries (S2+) are allowed and must not trigger drift.
- deterministic precedence for `EvaluateGates`:
  1. gate source parse/load failures (`E_GATE_SET_INVALID`)
  2. issue-map parse/load failures (`E_GATE_SET_INVALID`)
  3. aggregate item-evaluation artifact failures (`E_GATE_SET_INVALID`)
  4. gate-source vs issue-map drift (`E_GATE_SET_DRIFT`)
  5. success result (`slice_ready` true or false)

### `internal/s1gates/require_ready.go`
- implement `RequireSliceReady(req GatesEvaluateRequest, repoRoot string) (*GatesEvaluateResult, error)`.
- behavior:
  - call `EvaluateGates` and propagate all non-blocked errors unchanged.
  - if evaluation succeeds and `slice_ready == false`, return `E_GATE_BLOCKED`.
  - `E_GATE_BLOCKED` detail keys are fixed:
    - `gate_a_status`, `gate_b_status`
    - `gate_a_closed_items`, `gate_a_total_items`
    - `gate_b_closed_items`, `gate_b_total_items`
    - `gate_a_blocking_items`, `gate_b_blocking_items`
  - `gate_*_blocking_items` values are `|`-joined canonical-order issue paths (empty string when no blockers).
  - if `slice_ready == true`, return the aggregate result unchanged.
- this helper is the PR-03 enforcement primitive for downstream release consumers (PR-05), without changing `/gates/evaluate` success semantics.

## decision ledger

| question | decision | rationale | fallback/default |
|---|---|---|---|
| How should drift be defined when `constitution.md` contains non-S1 issues? | Drift is defined only against Gate A/B membership: each canonical gate issue must appear exactly once in `constitution.md`; extra non-gate entries are allowed. | `constitution.md` is canonical for gate membership, while `constitution.md` is broader slice execution tracking. Full-document equality would create false-positive drift. | Missing or duplicate gate issue in issue-map => `E_GATE_SET_DRIFT`. |
| How should `E_GATE_BLOCKED` be surfaced without changing `/gates/evaluate` request shape? | Keep `EvaluateGates` pure/read-only and add strict wrapper `RequireSliceReady` that returns `E_GATE_BLOCKED` when `slice_ready=false`. | Preserves L2 evaluate success shape for blocked states while providing explicit enforcement primitive for release workflows. | Downstream release flows call `RequireSliceReady`; plain evaluate remains non-error for blocked status. |
| What counts as "closed" in aggregate readiness? | Count closed only when `state=closed` and item evaluation has no `blocking_code`. | Prevents false ready from manual `state: closed` edits that violate acceptance/tests/evidence requirements. | If state is closed but evaluator blocks, keep item in `blocking_items`. |
| How should aggregate evaluation map per-item parse/load failures? | Map per-item `E_GATE_ITEM_NOT_FOUND`/`E_GATE_ITEM_INVALID` to aggregate `E_GATE_SET_INVALID` with detailed cause metadata. | Keeps `/gates/evaluate` error contract stable and aggregate-focused while preserving diagnostics. | Include `issue_path` and `item_error_code` in details. |
| How should blocker lists be ordered? | Preserve canonical order from Gate A/B sections in `constitution.md`. | Deterministic output avoids report churn and mirrors source-of-truth gate ordering. | No alphabetical or map-iteration ordering. |
| How should aggregate evaluation choose one error when multiple failure classes apply? | Enforce deterministic precedence: gate source invalid -> issue-map invalid -> item artifact invalid -> drift -> success result. | Stabilizes aggregate error behavior for CI/reporting and prevents incidental first-failure drift. | Any precedence change requires explicit spec + test updates in same PR. |
| How should aggregate error details be encoded for stable automation consumption? | Fix `AgencyError.Details` key set/encoding for `E_GATE_SET_INVALID` (item-artifact case), `E_GATE_SET_DRIFT`, and `E_GATE_BLOCKED`; use canonical-order `|`-joined blocker serialization for list values. | Prevents downstream parsing drift and makes CLI/CI/report consumers deterministic. | Any detail-key change requires spec + tests in the same PR. |
