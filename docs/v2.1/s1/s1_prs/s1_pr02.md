### `internal/s1gates/transition.go`
- implement `TransitionGateItem(req GateTransition, repoRoot string) (*GateTransitionResult, error)`.
- validation and guard rules:
  - parse current item state from issue stub and require `req.from_state` to match current state.
  - enforce legal transitions exactly:
    - `open -> in_progress`
    - `in_progress -> ready_for_verification`
    - `ready_for_verification -> closed`
    - `closed -> in_progress`
  - reject all other transitions with `E_GATE_TRANSITION_INVALID`.
  - require valid `actor_role` for all transitions; malformed/unknown role => `E_GATE_TRANSITION_INVALID`.
  - for library-level transition calls, treat empty `reason` as allowed for non-reopen transitions and required for reopen (`closed -> in_progress`).
  - require issue path to belong to canonical Gate A or Gate B set; non-member path => `E_GATE_TRANSITION_INVALID`.
  - enforce deterministic transition-validation precedence in this exact order:
    1. issue artifact parse/load failure (`E_GATE_ITEM_NOT_FOUND` or `E_GATE_ITEM_INVALID`)
    2. `from_state` mismatch (`E_GATE_TRANSITION_INVALID`)
    3. illegal lifecycle edge, including no-op/self-transition (`E_GATE_TRANSITION_INVALID`)
    4. malformed/unknown `actor_role` (`E_GATE_TRANSITION_INVALID`)
    5. non-member gate issue path (`E_GATE_TRANSITION_INVALID`)
- closure guard rules for `ready_for_verification -> closed`:
  - evaluate current item using PR-01 evaluator.
  - if evaluator reports missing preconditions, fail with evaluator `blocking_code`.
  - require `req.evidence_refs` non-empty and parsed closure evidence `implemented_refs` non-empty; otherwise `E_GATE_ITEM_EVIDENCE_MISSING`.
  - resolve gate membership from canonical release-gates source and enforce role policy:
    - Gate A: `actor_role=maintainer`
    - Gate B: `actor_role in {maintainer, reviewer}`
    - failure => `E_GATE_APPROVAL_REQUIRED`
  - if `requires_gh_e2e=true`, require at least one passing evidence row with `scope=e2e_opt_in`; missing => `E_GATE_E2E_REQUIRED`.
  - if `type=design`, require at least one passing enforcement evidence row with scope in `{targeted, suite, e2e_opt_in, lint, format, vet}`; missing => `E_GATE_ITEM_TESTS_INCOMPLETE`.
  - enforce deterministic closure-guard precedence in this exact order:
    1. PR-01 evaluator `blocking_code` (acceptance/tests/closure-block/evidence preconditions)
    2. request/parsed evidence-ref non-empty guard (`E_GATE_ITEM_EVIDENCE_MISSING`)
    3. Gate A/B role policy (`E_GATE_APPROVAL_REQUIRED`)
    4. GH e2e evidence guard (`E_GATE_E2E_REQUIRED`)
    5. design enforcement-evidence guard (`E_GATE_ITEM_TESTS_INCOMPLETE`)
- reopen guard rules for `closed -> in_progress`:
  - require non-empty `reason` and non-empty `evidence_refs`; missing either => `E_GATE_REOPEN_REASON_REQUIRED`.
- transition apply behavior:
  - on successful validation, persist new `state:` metadata in the issue stub deterministically.
  - replace existing `state:` line when present, otherwise insert `state:` immediately after `labels:` line (or after title if labels absent).
  - write failures wrap as `E_GATE_TRANSITION_INVALID` with file-path details.
- return `GateTransitionResult{issue_path, state}` on success.

### `internal/s1gates/issue_parser.go`
- enforce transition-critical metadata validity:
  - `priority` must resolve to `p0|p1`; missing/invalid => `E_GATE_ITEM_INVALID`.
  - `type` must resolve to known enum value; missing/invalid => `E_GATE_ITEM_INVALID`.
  - explicit `state:` metadata must be one of known states; invalid explicit state => `E_GATE_ITEM_INVALID`.
  - when `state:` metadata is absent, default `state=open`.
- enforce `TestEvidence` enum validity for every parsed evidence row:
  - `scope` must be in known `ValidScopes`.
  - `result` must be in known `ValidResults`.
- invalid scope/result values return `E_GATE_ITEM_INVALID`.

## decision ledger

| question | decision | rationale | fallback/default |
|---|---|---|---|
| How should PR-02 classify Gate A vs Gate B for role checks? | Use canonical gate membership from `constitution.md` via PR-01 source parser; do not infer from priority alone. | L2 invariant anchors membership to release-gates source, not labels. | If membership cannot be resolved, return `E_GATE_TRANSITION_INVALID`. |
| Should transition requests enforce current-state match (`from_state` == parsed issue state)? | Yes, mismatch fails with `E_GATE_TRANSITION_INVALID`. | Prevents stale/unsafe transition requests and keeps transition semantics deterministic. | none |
| How is transition `reason` interpreted given L2 has both model-level reason field and reopen-specific non-empty guard? | `reason` is required in request shape for all transitions; non-empty is enforced only for reopen transitions. | Resolves L2 wording tension without widening scope. | Empty non-reopen reason is accepted. |
| How are closure precondition failures surfaced in transition flow? | Reuse PR-01 evaluator and return its deterministic `blocking_code` for missing prerequisites. | Avoids duplicate precondition logic and keeps item-level error semantics stable across PRs. | If evaluator has no `blocking_code` but closure guard fails, use specific PR-02 guard code. |
| How are role-related failures mapped to error codes? | Policy role mismatch during closure returns `E_GATE_APPROVAL_REQUIRED`; malformed/unknown role values return `E_GATE_TRANSITION_INVALID`. | Separates policy failures from request-shape failures. | none |
| What reopen-specific constraints are mandatory? | `closed -> in_progress` requires non-empty `reason` and non-empty `evidence_refs`. | Preserves reopen auditability semantics defined by L2 invariants. | Missing either field => `E_GATE_REOPEN_REASON_REQUIRED`. |
| How is `requires_gh_e2e=true` enforced at closure time? | Require at least one passing evidence row with `scope=e2e_opt_in` before allowing close. | Preserves GH mutation safety invariant. | Missing required evidence => `E_GATE_E2E_REQUIRED`. |
| How is PR-01 open default (`gate-item/evaluate` success-shape vs error-shape) handled for PR-02 implementation start? | Canonical library behavior is: transition/evaluate functions return typed results and `AgencyError` codes; transport mapping is adapter responsibility. | Resolves PR-01 blocker without coupling PR-02 to daemon route wiring. | Until adapter exists, library behavior is source of truth. |
| How is design-item “contract enforcement evidence” interpreted without runtime-diff introspection in PR-02? | Require at least one passing evidence row in allowed enforcement scopes; runtime-diff detection is not part of PR-02. | Enforces L2 design guard with deterministic inputs available today. | Keep this evidence-based default until a later slice adds runtime-diff-aware enforcement. |
| Should successful transitions persist `state:` or only validate? | Successful transitions persist normalized `state:` metadata in issue stubs. | Enables downstream evaluations to observe applied lifecycle progression. | write failure => `E_GATE_TRANSITION_INVALID` |
| Should unknown evidence enum values be tolerated at parse time? | No. Unknown evidence `scope`/`result` are invalid artifacts (`E_GATE_ITEM_INVALID`). | Transition guards depend on deterministic evidence semantics. | none |
| How is deterministic error selection guaranteed when multiple transition checks fail? | Transition and closure guards follow fixed precedence orders documented in deliverables. | Prevents flaky behavior and inconsistent client/report interpretation. | If precedence order is changed, corresponding tests must be updated in same PR. |
| How are malformed issue metadata fields handled for transition-policy safety? | Transition-critical metadata (`priority`, `type`, explicit `state`) is strict-invalid on parse errors. | Avoids silent downgrades that could bypass GH e2e/design closure rules. | Missing `state:` defaults to `open`; all other malformed fields fail with `E_GATE_ITEM_INVALID`. |

## acceptance tests

### file: `internal/s1gates/transition_test.go`

**test: `TestTransition_EnforcesLegalAndIllegalTransitions`**
- input: transition requests for every legal edge and every illegal lifecycle edge defined by L2 contract.
- output:
  - legal edges succeed and return expected `state`
  - illegal edges fail with `E_GATE_TRANSITION_INVALID`.

**test: `TestTransition_RejectsNoOpTransition`**
- input: request where `from_state == to_state` for each lifecycle state.
- output:
  - every no-op transition fails with `E_GATE_TRANSITION_INVALID`.

**test: `TestTransition_FromStateMustMatchCurrentState`**
- input: request where `from_state` differs from issue’s parsed `state`.
- output:
  - transition fails with `E_GATE_TRANSITION_INVALID`.

**test: `TestTransition_InvalidActorRoleReturnsTransitionInvalid`**
- input: transition request using malformed `actor_role` (for example `owner`) on an otherwise valid lifecycle edge.
- output:
  - transition fails with `E_GATE_TRANSITION_INVALID`.

**test: `TestTransition_NonReopenAllowsEmptyReason`**
- input: non-reopen transition request (for example `open -> in_progress`) with `reason=""` and otherwise valid fields.
- output:
  - transition succeeds and returns the expected target `state`.

**test: `TestTransition_RejectsIssueOutsideGateMembership`**
- input: transition request for issue path that exists but is not listed in Gate A or Gate B in release-gates source.
- output:
  - transition fails with `E_GATE_TRANSITION_INVALID`.

**test: `TestTransition_CloseRequiresAcceptanceAndTestsAndEvidence`**
- input: `ready_for_verification -> closed` requests over fixtures missing acceptance/tests/closure evidence/evidence refs.
- output:
  - each request fails with deterministic blocking code from item-level model (`E_GATE_ITEM_ACCEPTANCE_INCOMPLETE`, `E_GATE_ITEM_TESTS_INCOMPLETE`, `E_GATE_ITEM_CLOSURE_BLOCK_MISSING`, or `E_GATE_ITEM_EVIDENCE_MISSING`).

**test: `TestTransition_P0CloseRequiresMaintainer`**
- input: Gate A item closure attempted by `reviewer` and `contributor`.
- output:
  - both fail with `E_GATE_APPROVAL_REQUIRED`.

**test: `TestTransition_GateBCloseByContributorRejected`**
- input: Gate B item closure attempted by `contributor`.
- output:
  - fails with `E_GATE_APPROVAL_REQUIRED`.

**test: `TestTransition_CloseSucceedsForGateBReviewer`**
- input: Gate B item with complete closure prerequisites, closure attempted by `reviewer`.
- output:
  - succeeds; returned `state=closed`; issue stub `state:` is persisted as `closed`.

**test: `TestTransition_PersistsStateByReplacingExistingStateLine`**
- input: successful transition request on an issue stub that already has `state: in_progress`.
- output:
  - exactly one `state:` line exists after apply
  - existing `state:` line is replaced with target state (for example `state: ready_for_verification`).

**test: `TestTransition_PersistsStateByInsertingAfterLabelsWhenStateMissing`**
- input: successful transition request on an issue stub that has `labels:` but no `state:` metadata.
- output:
  - new `state:` line is inserted immediately after `labels:`
  - returned `state` matches persisted metadata.

**test: `TestTransition_ReopenRequiresReasonAndEvidence`**
- input: `closed -> in_progress` requests missing `reason`, missing `evidence_refs`, and missing both.
- output:
  - all fail with `E_GATE_REOPEN_REASON_REQUIRED`.

**test: `TestTransition_RequiresGHE2EWhenFlagged`**
- input: closure request for item with `requires_gh_e2e=true` but no passing `scope=e2e_opt_in` evidence.
- output:
  - fails with `E_GATE_E2E_REQUIRED`.

**test: `TestTransition_DesignCloseRequiresEnforcementEvidence`**
- input: `type=design` closure request with no passing enforcement evidence.
- output:
  - fails with `E_GATE_ITEM_TESTS_INCOMPLETE`.

**test: `TestTransition_ErrorPrecedenceIsDeterministic`**
- input: closure and non-closure transition requests where multiple guards fail simultaneously.
- output:
  - returned error code follows the documented precedence order for transition validation and closure guards.
