# pr-01: gate corpus + evidence intake

Last updated: 2026-02-16
Status: draft
Upstream l2: `docs/v2.1/s1/s1_spec.md`
Upstream l3: `docs/v2.1/s1/s1_roadmap.md` (PR-01)

## goal
Implement deterministic S1 gate corpus intake and gate-item evidence normalization so downstream PRs consume one machine-checkable item evaluation model.

## context
- `docs/v2.1/s1/s1_roadmap.md:62` defines PR-01 ownership as corpus intake + evidence intake + item-level error surfacing.
- `docs/v2.1/s1/s1_spec.md:28` defines PR-01-owned domain models: `GateSet`, `GateItemRef`, `TestEvidence`, `ClosureEvidence`.
- `docs/v2.1/s1/s1_spec.md:211` defines the gate-item evaluation response shape and missing-requirement semantics.
- `docs/v2.1/s1/s1_spec.md:239` defines PR-01-owned item-level error codes.
- `docs/v2.1/constitution.md:9` and `docs/v2.1/constitution.md:15` are the canonical Gate A/Gate B source lists.
- `docs/issues/README.md:4` and existing issue stubs establish the markdown artifact shape that intake must parse.
- `internal/errors/errors.go:13` is the stable error-code registry and must carry any new public S1 error code constants.
- `internal/report/completeness.go:80` shows the current markdown parsing pattern used in the repo (line-oriented + fenced-block handling).

## dependencies
- none (PR-01 is the first S1 dependency node).

## deliverables

### `internal/errors/errors.go`
- add PR-01 S1 error constants only:
  - `E_GATE_SET_INVALID`
  - `E_GATE_ITEM_NOT_FOUND`
  - `E_GATE_ITEM_INVALID`
  - `E_GATE_ITEM_ACCEPTANCE_INCOMPLETE`
  - `E_GATE_ITEM_TESTS_INCOMPLETE`
  - `E_GATE_ITEM_EVIDENCE_MISSING`
  - `E_GATE_ITEM_CLOSURE_BLOCK_MISSING`
- keep string values stable and prefixed with `E_`.
- do not add PR-02+ S1 error codes in this PR.

### `internal/errors/errors_test.go`
- add compile-time/string-value assertions for the PR-01 S1 error constants.
- assert no renamed error constants for the PR-01 set.

### `internal/s1gates/types.go`
- define PR-01-owned S1 data models:
  - `GateSet`
  - `GateItemRef`
  - `TestEvidence`
  - `ClosureEvidence`
  - `GateItemEvaluation`
- model constraints encoded in types/validators must match L2 sections owned by PR-01 only.
- no state-transition policy types (owned by PR-02).
- no aggregate gate/slice readiness types (owned by PR-03).

### `internal/s1gates/source_parser.go`
- implement deterministic parser for `docs/v2.1/constitution.md` Gate A/B sections only.
- gate membership extraction rules:
  - accept numbered list items with backtick-wrapped issue paths under Gate A and Gate B headings.
  - preserve source order as listed.
  - reject duplicate issue paths across A/B.
  - require each issue path to exist under `docs/issues/`.
- output `GateSet{slice:"S1", gate_a_items, gate_b_items, source_ref}` with stable ordering.
- on malformed source or unresolved paths, return `E_GATE_SET_INVALID`.

### `internal/s1gates/issue_parser.go`
- parse one issue stub into normalized `GateItemRef` + optional `ClosureEvidence`.
- normalization rules:
  - `priority` derives from `labels:` first; fallback to title tag only when labels are absent.
  - `type` derives from `labels: type:<value>`.
  - `state` derives from optional `state:` metadata line; default is `open`.
  - `acceptance_complete=true` only when all acceptance checkboxes are checked.
  - `requires_gh_e2e=true` only when labels include `requires:gh-e2e`; otherwise false.
- closure evidence parse rule:
  - read `## closure evidence` section and parse the first fenced `json` block.
  - required top-level keys: `implemented_refs`, `targeted_test_refs`, `suite_test_refs`.
  - enforce `TestEvidence` schema and allowed `scope`/`result` values.
  - enforce `recorded_at` presence for every `result=pass` test evidence row.
  - enforce suite command allowlist for `scope=suite`:
    - `go test ./...`
    - `make test`
    - `make check`
    - `make verify`
- malformed metadata/sections return `E_GATE_ITEM_INVALID`.

### `internal/s1gates/evaluate_item.go`
- implement PR-01 item-evaluation precondition checks for one issue path.
- behavior:
  - if issue path does not exist: return `E_GATE_ITEM_NOT_FOUND`.
  - if issue artifact shape is malformed: return `E_GATE_ITEM_INVALID`.
  - otherwise return `GateItemEvaluation` including:
    - normalized fields (`state`, `requires_gh_e2e`, `acceptance_complete`, `tests_complete`, `evidence_refs`)
    - `closure_evidence_present`
    - deterministic `missing_requirements` list
    - deterministic primary `blocking_code` from item-level S1 codes when requirements are incomplete.
    - `blocking_code` is internal evaluator output for PR-01 library consumers, not a public HTTP contract field.
  - `tests_complete=true` only when:
    - closure evidence contains at least one targeted evidence row
    - closure evidence contains at least one passing suite evidence row using allowed suite commands.
  - when normalized `state=closed`, `evidence_refs` must be non-empty or evaluation reports `E_GATE_ITEM_EVIDENCE_MISSING`.
- precedence for `blocking_code` when multiple checks fail:
  1. `E_GATE_ITEM_ACCEPTANCE_INCOMPLETE`
  2. `E_GATE_ITEM_CLOSURE_BLOCK_MISSING`
  3. `E_GATE_ITEM_EVIDENCE_MISSING`
  4. `E_GATE_ITEM_TESTS_INCOMPLETE`
- do not implement transition authorization or reopen policy checks (PR-02).

### `internal/s1gates/testdata/*`
- add deterministic markdown fixtures for:
  - valid/invalid release-gates corpus
  - issue stub variants (valid, missing acceptance section, bad labels, closure evidence variants)
- fixtures must be minimal and purpose-built per test case.

### `internal/s1gates/source_parser_test.go`
- add unit tests for gate source parsing and deterministic ordering.
- include failure cases that must produce `E_GATE_SET_INVALID`.

### `internal/s1gates/issue_parser_test.go`
- add unit tests for metadata derivation and closure evidence normalization.
- include malformed-shape tests that must produce `E_GATE_ITEM_INVALID`.
- include schema enforcement tests for:
  - missing `recorded_at` on passing evidence rows
  - invalid `scope=suite` command outside the allowlist.

### `internal/s1gates/evaluate_item_test.go`
- add unit tests for missing-requirement detection and deterministic `blocking_code` selection.
- include not-found and malformed issue tests for `E_GATE_ITEM_NOT_FOUND` and `E_GATE_ITEM_INVALID`.

## decision ledger

| question | decision | rationale | fallback/default |
|---|---|---|---|
| What is the canonical source for Gate A/B membership? | Parse only `docs/v2.1/constitution.md` Gate A/Gate B sections. | Enforces one source of truth and deterministic ordering. | none |
| How is closure evidence represented for machine parsing? | `## closure evidence` uses a fenced `json` block with required keys. | Avoids ambiguous free-form markdown parsing and enables strict schema validation. | Missing/invalid block => `E_GATE_ITEM_CLOSURE_BLOCK_MISSING` or `E_GATE_ITEM_INVALID` |
| How is `state` derived when issue stubs omit explicit state? | `state:` metadata is optional; default to `open`. | Existing stubs do not carry state metadata yet; default keeps intake deterministic. | `open` |
| How is `requires_gh_e2e` assigned in PR-01? | Parse `requires:gh-e2e` label; otherwise false. | Deterministic and auditable without heuristic keyword matching. | false |
| How are multiple incomplete requirements surfaced deterministically? | Return ordered `missing_requirements` and precedence-driven `blocking_code`. | Prevents flaky behavior and keeps downstream closure/reporter behavior stable. | Precedence order in deliverables |
| How are L2 `gate-item/evaluate` incomplete states surfaced before transport wiring is selected? | PR-01 evaluator returns structured results with `missing_requirements` + `blocking_code`; transport-level mapping to `E_GATE_ITEM_*` response mode is deferred. | L2 defines both success-shape and item-level incomplete error codes; PR-01 resolves parser/evaluator semantics without locking final transport behavior. | Use evaluator output as normative default until transport contract is finalized in a later PR |

## acceptance tests

### file: `internal/s1gates/source_parser_test.go`

**test: `TestParseGateSet_DeterministicMembershipFromCanonicalSource`**
- input: fixture `release_gates_valid.md` with Gate A/B/C sections and valid `docs/issues/*.md` paths.
- output:
  - parse succeeds
  - `slice == "S1"`
  - `source_ref == "docs/v2.1/constitution.md"`
  - `gate_a_items` and `gate_b_items` exactly match fixture order
  - no Gate C items included.

**test: `TestParseGateSet_RejectsMissingIssuePathWithEGateSetInvalid`**
- input: fixture where one Gate B entry references a non-existent `docs/issues/*.md` file.
- output:
  - parse fails with error code `E_GATE_SET_INVALID`
  - error details include the unresolved `issue_path`.

**test: `TestParseGateSet_RejectsDuplicateIssueRefs`**
- input: fixture where one `issue_path` appears in both Gate A and Gate B.
- output:
  - parse fails with `E_GATE_SET_INVALID`
  - duplicate path is surfaced in error details.

### file: `internal/s1gates/issue_parser_test.go`

**test: `TestParseIssue_NormalizesPriorityTypeAndState`**
- input: issue fixture with `labels: p1, type:bug, area:daemon`, explicit `state: ready_for_verification`, acceptance checklist.
- output:
  - `priority == "p1"`
  - `type == "bug"`
  - `state == "ready_for_verification"`
  - `acceptance_complete` reflects checkbox completion.

**test: `TestParseIssue_DefaultStateOpenWhenMissingStateMetadata`**
- input: issue fixture without `state:` metadata.
- output:
  - `state == "open"` (default)
  - no parse error.

**test: `TestParseIssue_ParsesClosureEvidenceJSON`**
- input: issue fixture with `## closure evidence` and fenced JSON block containing required keys.
- output:
  - closure evidence parsed into typed `ClosureEvidence`

**test: `TestParseIssue_MissingAcceptanceSectionReturnsEGateItemInvalid`**

- output:
  - parse fails with `E_GATE_ITEM_INVALID`.

**test: `TestParseIssue_PassEvidenceRequiresRecordedAt`**
- input: issue fixture where one test evidence row has `result=pass` but no `recorded_at`.
- output:
  - parse fails with `E_GATE_ITEM_INVALID`.

**test: `TestParseIssue_SuiteScopeRequiresAllowedCommand`**
- input: issue fixture where one suite evidence row has `command` not in the allowed suite list.

  - parse fails with `E_GATE_ITEM_INVALID`.
