# PR-09 — Daemon-Owned Landing Workflow (diff / land / discard)

## Purpose

Implement the **landing workflow** that safely applies sandbox results into an integration worktree.

This PR makes the daemon the **sole authority** for all landing-related git mutations:

- Cherry-picking sandbox commits
- Apply-mode landing for uncommitted changes
- Sandbox cleanup
- Snapshot ref cleanup
- Invocation state transitions

After this PR:

- All landing mutations flow through the daemon
- Integration worktrees are never modified directly by runners or CLI
- Landing is explicit, inspectable, and reversible on failure

---

## Scope

### Adds (Daemon-owned)

- Landing service (`internal/daemon/landing/`)
- Daemon handlers:
  - `POST /invocations/{id}/land`
  - `POST /invocations/{id}/discard`
- Conflict detection and reporting
- Sandbox cleanup on success
- Snapshot ref cleanup on success/discard
- Invocation meta updates for landing state
- Agency events for land/discard lifecycle

### CLI Changes

- `agency agent land <invocation>`:
  - Calls daemon endpoint
- `agency agent discard <invocation>`:
  - Calls daemon endpoint
- `agency agent diff <invocation>`:
  - **Remains CLI-local and read-only**
  - Uses git diff against sandbox branch (no mutation)

---

## Preconditions

### Landing (`agent land`)

Landing **must fail** if:

- Invocation is still running
- Invocation is already landed or discarded
- Invocation sandbox is missing or corrupted
- Integration worktree cannot be resolved
- Repo-level lock cannot be acquired

No `--force` land in slice 8.

### Discard (`agent discard`)

- May be called on running or finished invocations
- If running: daemon must stop -> wait -> kill before cleanup

---

## Invocation Meta Requirements

Invocation meta **must include**:

- `repo_id`
- `integration_worktree_id`
- `sandbox_path`
- `sandbox_branch`
- `base_commit`
- `status`
- `landing_status` (`null` | `landed` | `discarded`)

`repo_id` is mandatory so daemon endpoints do not rely on client CWD.

---

## Landing Algorithm (Daemon)

All steps run under the **repo-level lock**.

### 1. Resolve State

Given `(repo_id, invocation_id)`:

- Load invocation meta
- Load integration worktree meta
- Resolve:
  - `integration_tree_path`
  - `sandbox_tree_path`
  - `sandbox_branch`
  - `base_commit`

Verify:

- Invocation is terminal (`status=finished` or `failed`)
- `landing_status == null`

Emit event: `agency.land_started`

---

### 2. Determine Landing Mode

Compute commit range:

```bash
git rev-list --count <base_commit>..<sandbox_branch>
```

**Case A — Commit Range Non-Empty (Normal Mode)**

- Use cherry-pick mode

**Case B — Commit Range Empty**

Check sandbox cleanliness:

```bash
git -C <sandbox_tree> status --porcelain
```

- If clean -> error: nothing to land
- If dirty -> use apply mode

---

### 3. Cherry-Pick Mode

Executed in integration worktree.

```bash
git -C <integration_tree> cherry-pick --no-edit <base_commit>..<sandbox_branch>
```

**On Success**

- Record:
  - `integration_head_before`
  - `integration_head_after`
- Proceed to cleanup

**On Conflict**

1. Capture conflict files:
   ```bash
   git diff --name-only --diff-filter=U
   ```
2. Abort cherry-pick:
   ```bash
   git cherry-pick --abort
   ```
3. Integration tree must be clean
4. Emit event: `agency.conflict_detected`
5. Mark invocation unchanged (`landing_status` still `null`)
6. Return error with:
   - Conflict file list
   - Resolution hint

Sandbox is preserved.

---

### 4. Apply Mode (No Commits)

Used when sandbox has uncommitted changes.

**Patch Generation (Sandbox)**

```bash
cd <sandbox_tree>
git add -A           # obey denylist rules
git diff --cached <base_commit> > land.patch
```

- Denylisted files -> error (no silent drop)
- Patch stored under sandbox tmp dir

**Apply to Integration**

```bash
git -C <integration_tree> apply --index land.patch
git -C <integration_tree> commit -m "agency: land invocation <invocation_id>"
```

**On Failure**

- `git reset --hard` integration tree
- Emit `agency.land_failed`
- Sandbox preserved

---

### 5. Cleanup (Success Only)

Performed after successful land.

1. Update invocation meta:
   ```json
   "landing_status": "landed"
   ```
2. Delete sandbox git worktree:
   ```bash
   git worktree remove --force <sandbox_tree_path>
   ```
3. Delete sandbox branch:
   ```bash
   git branch -D <sandbox_branch>
   ```
4. Delete snapshot refs:
   ```
   refs/agency/snapshots/<invocation_id>/*
   ```
5. Preserve:
   - logs
   - `checkpoints.json`
6. Emit: `agency.land_succeeded`

---

## Discard Algorithm

### Steps

1. Emit `agency.discard_started`
2. If running:
   - Stop
   - Wait (5s)
   - Kill
3. Delete sandbox worktree
4. Delete sandbox branch
5. Delete snapshot refs
6. Update invocation meta:
   ```json
   "landing_status": "discarded"
   ```
7. Emit `agency.discard_succeeded`

Integration worktree is never touched.

---

## Events (Agency Namespace)

All appended to `invocations/<id>/events.jsonl`.

| Event | Data |
| --- | --- |
| `agency.land_started` | `invocation_id`, `worktree_id` |
| `agency.conflict_detected` | `invocation_id`, `files[]` |
| `agency.land_failed` | `invocation_id`, `reason` |
| `agency.land_succeeded` | `invocation_id`, `head_before`, `head_after` |
| `agency.discard_started` | `invocation_id` |
| `agency.discard_succeeded` | `invocation_id` |

Meta updates must be written before emitting terminal events.

## API Contract

### `POST /invocations/{id}/land`

**Success response:**

```json
{
  "ok": true,
  "invocation_id": "...",
  "applied_mode": "cherry_pick|apply_patch",
  "integration_head_before": "...",
  "integration_head_after": "..."
}
```

**Conflict response:**

```json
{
  "ok": false,
  "error_code": "E_LAND_CONFLICT",
  "conflict_files": ["file1", "file2"],
  "hint": "resolve conflicts and retry landing"
}
```

---

### `POST /invocations/{id}/discard`

**Response:**

```json
{
  "ok": true,
  "invocation_id": "..."
}
```

---

## Invariants (Hard)

These must not be violated:

1. Integration worktree is never mutated on failure
2. Sandbox is preserved on land conflict
3. Sandbox is deleted only after successful land or discard
4. Repo lock is held across all integration mutations
5. CLI performs no git mutations
6. No runner ever executes in integration tree

---

## Acceptance Criteria

- [ ] Cherry-pick landing works with committed sandbox
- [ ] Apply-mode landing works with uncommitted sandbox
- [ ] Conflicts abort cleanly with sandbox preserved
- [ ] Integration tree is clean after failure
- [ ] Discard removes sandbox without touching integration
- [ ] Snapshot refs are removed on land/discard
- [ ] Events emitted for all transitions
- [ ] CLI never performs git mutations

---

## Explicit Non-Goals

- Merge strategy
- Rebase support
- Auto-land
- Conflict resolution UI
- Headed runner parsing
- Watch integration (PR-13)
