# Slice 8 — PR-03: Headed Agent Execution (tmux)

## Purpose

Restore **interactive (headed) agent execution** inside **sandbox worktrees**, using tmux for lifecycle control, without violating core slice-8 invariants:

- Runners never execute in integration trees
- Each invocation owns exactly one sandbox
- State is mutated only by explicit commands
- Read paths remain side-effect free

This PR establishes the tmux-backed execution model that headless, watch, and reconcile will later build upon.

---

## Scope

### In Scope

- Headed `agent start` (tmux-backed)
- tmux session creation in sandbox CWD
- `agent attach`
- `agent stop`
- `agent kill`
- Invocation lifecycle updates on explicit actions only

### Explicitly Out of Scope

- Headless execution
- Log capture / parsing
- Checkpoints
- Landing
- Watch / reconcile
- Stream parsing
- Semantic status inference

---

## Architectural Constraints

This PR must respect the following constraints:

1. **Sandbox-only execution**
   - tmux sessions must always start with CWD = sandbox tree
   - Integration trees are never used as execution CWD
2. **No reconcile-on-read**
   - `agent ls` / `agent show` must not mutate invocation records
   - Missing tmux sessions do not automatically persist `finished_at`
3. **Explicit lifecycle mutation**
   - Invocation state changes occur only in:
     - `agent start`
     - `agent stop`
     - `agent kill`
     - (future) `agent reconcile`
4. **No background processes**
   - No daemons, goroutines, or polling loops introduced in this PR

---

## Invocation Lifecycle (Headed)

### States (persisted)

| State | Meaning |
|---|---|
| `starting` | tmux session being created |
| `running` | tmux session exists |
| `finished` | Runner exited normally (set only by explicit command or future reconcile) |
| `failed` | Killed or crashed |

### Derived Display Status (Deferred)

Derived display logic (e.g., "running but tmux missing → show as finished") belongs in `agent ls` / `agent show`, which are not in PR-03 scope. This PR establishes persisted state transitions only. Display derivation will be added in a later PR alongside those commands.

## Command Behavior

### `agency agent start --worktree <ref>`

**Behavior:**

1. Resolve integration worktree (verify marker, validate state)
2. Create sandbox worktree + sandbox branch (PR-02 path)
3. Resolve runner command via `config.ResolveRunnerCmd` (returns single string)
4. Create invocation record:
   - `status = "starting"`
   - `mode = "headed"`
   - `started_at = now` (set here — means "launch attempted", not "runner confirmed alive")
   - `runner = <resolved_runner_name>`
5. **Preflight:** `tmux.HasSession(ctx, sessionName)` — if session already exists, abort with `E_TMUX_SESSION_EXISTS`. This guards against leaked sessions, test reuse, or parallel execution bugs.
6. Create tmux session:
   - Session name: `tmux.SessionName(invocationID)` → `agency_<invocation_id>`
   - CWD: sandbox tree path
   - argv: `[runnerCmd]` (passed directly to tmux `--`, no `sh -lc` wrapping)
7. Update invocation meta:
   - `status = "running"`
   - `tmux_session = <session_name>`

**`started_at` timing rationale:** Set at step 4, before tmux creation, because it means "we attempted to start." If tmux fails, `started_at` plus `status=failed` tells you when the attempt happened. Setting it after success would lose timing info on failures.

#### Failure Matrix

| Failure point | Sandbox | Invocation record | tmux session |
|---|---|---|---|
| Sandbox creation fails (PR-02 path) | Cleaned up by PR-02 | Not created | N/A |
| Invocation record write fails | Removed (best-effort) | Not persisted | N/A |
| `tmux.NewSession` fails | Preserved | Marked `status="failed"`, `exit_reason="start_failed"`, `finished_at=now` | N/A |
| Meta update to `running` fails after tmux created | Preserved | Marked `status="failed"` (best-effort) | Best-effort `KillSession` |

**Key rule:** On any failure after sandbox creation succeeds, the invocation record is **kept** with `status="failed"` so users can see it failed and why. Sandbox is preserved for inspection. Integration tree remains untouched in all cases.

### `agency agent attach <invocation>`

- Resolve invocation by ID / prefix
- Attach to tmux session via `tmux.Attach(ctx, sessionName)`
- Errors:
  - Invocation mode is not `headed` → `E_INVALID_MODE` with hint: "invocation is headless; attach is only supported for headed invocations"
  - tmux session does not exist → `E_TMUX_SESSION_MISSING` with details: session name, invocation ID, hint: "session may have exited; use 'agent kill' to finalize or 'agent start' to create a new invocation"

No state mutation.

---

### `agency agent stop <invocation>`

**Semantics:** graceful interrupt request.

- Sends `C-c` via `tmux.SendKeys(ctx, sessionName, []Key{KeyCtrlC})`
- Does **not** assume termination — the runner may ignore the signal
- Updates invocation meta:
  - `stop_requested_at = now`
  - `flags.needs_attention = true`
  - `status` remains `running`
  - `exit_reason` remains null
  - `finished_at` remains null

**Does not write `exit_reason="stopped"`.** That would be a semantic lie — "stopped" reads like the process ended, but stop is a request, not a guarantee. Actual termination is observed later via reconcile or kill.

If tmux session is already missing when stop is called: log a warning, still set `stop_requested_at` and `flags.needs_attention` (the user's intent to stop is recorded regardless).

---

### `agency agent kill <invocation>`

**Semantics:** forceful termination.

- Executes `tmux.KillSession(ctx, sessionName)`
- If successful, update invocation meta:
  - `status = "failed"`
  - `exit_reason = "killed"`
  - `finished_at = now`
  - `tmux_session` — **kept as historical value** (not nulled). It records which session was killed.

If session is already missing: still mark `status="failed"`, `exit_reason="killed"`, `finished_at=now`. The user's intent is to finalize the invocation regardless of current tmux state.

Sandbox is preserved for later inspection.

## tmux Integration

### Client Usage

- Use existing `tmux.Client` interface
- Use `NewSession(ctx, name, cwd, argv)`
  - Do **not** use shell wrappers
  - Let tmux `-c` handle CWD

### Session Naming

- Use existing helper: `tmux.SessionName(invocationID)`
- No parsing of session names anywhere in code

---

## Reconciliation Policy (Deferred)

This PR does **not** reconcile missing tmux sessions.

If a tmux session disappears outside of Agency control, the invocation record stays as-is (`status="running"`). No reads trigger writes. No derived state is persisted.

Persistent reconciliation is deferred to a future PR via:

- `agent reconcile` (explicit command)
- Or watch-driven reconciliation (background)

## Tests

### Unit Tests (Required)

- **`agent start`:**
  - `tmux.NewSession` called with sandbox CWD (not integration CWD)
  - `tmux.NewSession` **never** called with integration tree path
  - Preflight: if `HasSession` returns true, start aborts with `E_TMUX_SESSION_EXISTS`
  - On tmux failure: invocation record exists with `status="failed"`, `exit_reason="start_failed"`
- **`agent start` runner argv (critical):**
  - Assert `tmux.NewSession(ctx, name, sandboxCwd, []string{resolvedRunnerCmd})` — verify exact argv
  - Assert argv does **not** contain `"sh"`, `"-lc"`, or any shell wrapper
  - This enforces the resume-style direct invocation contract
- **`agent attach`:**
  - Calls `tmux.Attach` with correct session name
  - Returns `E_TMUX_SESSION_MISSING` when session does not exist
- **`agent stop`:**
  - Calls `tmux.SendKeys(C-c)`
  - Sets `stop_requested_at` and `flags.needs_attention`
  - Does **not** set `finished_at` or `exit_reason`
- **`agent kill`:**
  - Calls `tmux.KillSession`
  - Marks invocation `status="failed"`, `exit_reason="killed"`, `finished_at` set
  - `tmux_session` preserved (not nulled)

### Invariant Tests (Critical)

- Sandbox path ≠ integration path
- Sandbox path does not contain `INTEGRATION_MARKER`
- If sandbox creation fails, tmux is never invoked

### E2E tmux Tests (Optional)

- May skip if tmux unavailable (existing pattern)
- Not required for acceptance
