# PR-08 — Daemon-owned Checkpoint Engine (Private Refs)

## Purpose

Introduce a **daemon-owned checkpoint engine** that continuously snapshots sandbox state during headless agent execution, enabling safe rollback without branch pollution or cross-invocation interference.

After this PR:

- All checkpoints are created, stored, and applied by the daemon
- Checkpoints are **per-invocation**, **per-sandbox**
- Snapshot state is captured via **private git refs**, not stash
- Rollback is exact and reversible
- CLI never writes checkpoint state directly

This PR establishes the foundation for safe experimentation, rewind, and recovery.

---

## Architectural Invariants

This PR must preserve the following invariants:

1. **Only the daemon writes checkpoint state**
   - Snapshot refs
   - `checkpoints.json`
   - Any rollback mutations

2. **Checkpoints are sandbox-scoped**
   - No shared refs across invocations
   - No repo-global mutable state (no stash)

3. **Checkpoint failures never abort an invocation**
   - Failures degrade functionality, not execution

4. **Checkpointing never mutates integration worktrees**
   - All operations are sandbox-only

## Scope

### In Scope

- Snapshot creation via private git refs
- fsnotify-based checkpoint triggering with polling fallback
- Checkpoint metadata recording

- Integration tests for snapshot + rollback

### Explicitly Out of Scope

- Watch integration
- Auto-rollback

## Checkpoint Model

### Storage

**Per invocation:**

```
sandboxes/<invocation_id>/
├── checkpoints.json
└── tree/
```

**Git refs:**

```
refs/agency/snapshots/<invocation_id>/
```

### checkpoints.json Schema

```json
{
  "schema_version": "1.0",
  "checkpoints": [
    {
      "id": 1,
      "snapshot_ref": "refs/agency/snapshots/<invocation_id>/1",
      "snapshot_commit": "abc123...",
      "sandbox_head_sha": "def456...",
      "created_at": "2026-02-01T12:34:56Z",
      "includes_untracked": true,
      "diffstat": "+12 -4 in 2 files"
    }
  ]
}
```

- `sandbox_head_sha`: HEAD of the sandbox branch at snapshot time (`git rev-parse HEAD` in sandbox). Records what the snapshot is relative to — useful for debugging and for future "diff between checkpoint i and j".

- Written atomically via `WriteJSONAtomic`
- Append-only semantics (rewrite whole file, never in-place mutate)
- Canonical source of checkpoint history for an invocation

## Snapshot Mechanism (Gold Standard)

### Primitive

Snapshots are created using git plumbing with a temporary index:

1. Clone the current index into a temp file
2. Stage changes into the temp index
3. Write a tree object
4. Create a commit via `git commit-tree`
5. Store commit under a private ref
6. Record metadata in `checkpoints.json`

### Snapshot Creation (Tracked + Untracked)

```bash
GIT_INDEX_FILE=$TEMP_INDEX git add -A -- . ':(exclude).agency' ':(exclude).git'
tree=$(GIT_INDEX_FILE=$TEMP_INDEX git write-tree)
commit=$(git commit-tree $tree -p HEAD -m "agency snapshot <invocation_id> <n>")
git update-ref refs/agency/snapshots/<invocation_id>/<n> $commit
```

- Real index is never touched
- No branch or HEAD mutation
- Snapshot commits are GC-safe while ref exists
- **Pathspec exclusions** for `.agency/` and `.git/` are mandatory — do not rely on `.gitignore` to exclude these; `.agency/` may not be ignored in all sandbox configurations

### `--no-include-untracked`

If invocation was started with `include_untracked: false`:

```bash
GIT_INDEX_FILE=$TEMP_INDEX git add -u
```

(No pathspec exclusion needed — `add -u` only stages tracked files.)

## Denylist Policy

### Hardcoded Denylist (v1)

Untracked non-ignored files matching any of the following patterns are excluded from snapshots:

- `.env` (exact basename)
- `.env.*` (prefix match on basename)
- `*.key` (suffix match on basename)
- `*.pem` (suffix match on basename)
- `credentials.json` (exact basename)
- `secrets.json` (exact basename)

**Matching semantics:** `filepath.Match` (glob) applied to the **base filename** only. No regex. Case-sensitive.

Denylist only applies to untracked non-ignored files (files from `git ls-files -o --exclude-standard`). Tracked files are never denylisted.

### Behavior

If denylisted untracked files are detected:

- Snapshot degrades to tracked-only (`git add -u` instead of `git add -A`)
- Snapshot still succeeds
- A warning event is emitted (`checkpoint_denylist_triggered`)
- `includes_untracked = false` is recorded in that checkpoint entry

Invocation continues normally.

## Triggering Policy

### Primary: fsnotify

fsnotify is **not recursive by default**. The daemon implements dynamic watch registration:

**Initial setup:**

1. Walk the sandbox tree directory
2. For each directory (excluding `.git/` and `.agency/`), add an `fsnotify.Add()` watch
3. Skip symlinks

**Runtime:**

4. On `Create` events for new directories: add watcher for the new dir (and any subdirs)
5. On `Remove` events for directories: watcher is automatically removed by fsnotify
6. **Ignore all events from `.git/` and `.agency/` paths** (prefix check)

**Debounce:** 3 seconds after last event before triggering snapshot
**Rate limit:** 1 snapshot per 10 seconds

**Storm prevention:** `checkpoints.json` lives at `sandboxes/<invocation_id>/checkpoints.json`, **outside** the watched tree (`sandboxes/<invocation_id>/tree/`). Daemon writes to `checkpoints.json` must never trigger the watcher.

### Fallback: Polling

- Interval: 30 seconds
- Check: `git status --porcelain` in sandbox tree
- If dirty and rate limit allows → snapshot

### Dirty Detection

"Dirty" is determined by `git status --porcelain` output:

- If `include_untracked: true` (default): any non-empty output means dirty (tracked changes + untracked files)
- If `include_untracked: false`: ignore `??` lines (untracked); only `M`/`A`/`D`/`R` etc. lines count as dirty

Empty output after filtering → skip snapshot ("no changes").

### Additional Triggers

- Invocation exit (final snapshot)
- Explicit rollback (post-apply snapshot optional, not required)

## Daemon Integration

### Checkpoint Policy in InvocationMeta

Add to `InvocationMeta`:

```go
CheckpointIncludeUntracked bool `json:"checkpoint_include_untracked"`
```

- Set at invocation creation time based on CLI flag `--no-include-untracked` (default: `true`)
- Daemon reads this field to determine snapshot mode (`git add -A` vs `git add -u`)
- Passed through the control plane start request

### Lifecycle Hooks

Checkpoint loop is started after invocation enters `running`:

```go
go s.runCheckpointLoop(proc)
```

The loop:

- Initializes watcher
- Responds to fsnotify + polling ticks
- Terminates cleanly on `proc.done`
- Performs final snapshot on exit

### Locking

- Repo lock is acquired only for:
  - `git update-ref`
  - Writing `checkpoints.json`
- **No lock during** (these are the expensive operations):
  - fsnotify handling
  - `git add` into temp index
  - `git write-tree`
  - `git commit-tree`
  - Diffstat computation
- Lock is held for **milliseconds** (`update-ref` + atomic JSON write only)
- Target: <100ms typical, <500ms worst-case on normal repos

## Rollback / Apply

### Endpoint

`POST /invocations/{id}/checkpoints/apply`

**Request body:**

```json
{
  "checkpoint_id": 3
}
```

### Semantics

**Precondition:** invocation `status` must be `finished` or `failed`. If `status == running` or `status == starting`, return `E_INVOCATION_STILL_RUNNING` with hint "stop the invocation first". Do **not** auto-stop — auto-stop can corrupt runner state.

Rollback restores sandbox working tree exactly:

```bash
git -C <sandbox_path> reset --hard
git -C <sandbox_path> clean -fd
git -C <sandbox_path> checkout <snapshot_commit> -- .
```

- Sandbox only
- Does not resume the same process
- Snapshot refs remain intact

## Events

Daemon emits checkpoint-related events to:

```
invocations/<invocation_id>/events.jsonl
```

This file is **distinct from `stream.jsonl`** (which holds normalized runner output events). `events.jsonl` holds **agency lifecycle events** only. Kinds are namespaced with `agency.` to avoid ambiguity:

- `agency.checkpoint_created`
- `agency.checkpoint_failed`
- `agency.checkpoint_applied`
- `agency.checkpoint_denylist_triggered`

### events.jsonl Schema

```json
{
  "schema_version": "1.0",
  "seq": 1,
  "timestamp": "2026-02-01T12:40:00Z",
  "invocation_id": "...",
  "kind": "agency.checkpoint_created",
  "data": {
    "checkpoint_id": 3,
    "includes_untracked": true,
    "sandbox_head_sha": "abc123..."
  }
}
```

- `seq`: monotonic uint64, per invocation, independent of `stream.jsonl` seq
- `kind`: always prefixed with `agency.` (runner events use unprefixed kinds in `stream.jsonl`)
- `schema_version`: "1.0"

## Error Codes

| Code | Meaning |
| --- | --- |
| `E_INVOCATION_STILL_RUNNING` | Apply refused — invocation must be stopped/finished first |
| `E_CHECKPOINT_NOT_FOUND` | Requested checkpoint_id does not exist in checkpoints.json |
| `E_ROLLBACK_FAILED` | Git reset/clean/checkout failed during apply |

## Failure Handling

| Scenario | Behavior |
| --- | --- |
| fsnotify failure | Fall back to polling |
| Snapshot creation error | Emit `agency.checkpoint_failed` event, continue invocation |
| Denylisted files | Degrade to tracked-only, emit `agency.checkpoint_denylist_triggered` |
| No changes (empty `git status --porcelain` after filtering) | Skip snapshot |
| Rollback failure | Abort apply, return `E_ROLLBACK_FAILED` |
| Apply while running | Return `E_INVOCATION_STILL_RUNNING` |

No checkpoint failure aborts an invocation.

## Tests

### Required Tests

1. **Unit**
   - Snapshot helper produces valid commit + ref
   - `sandbox_head_sha` recorded correctly
   - Tracked-only vs tracked+untracked behavior
   - Pathspec excludes `.agency/` and `.git/` from staging
   - Dirty detection: `include_untracked: true` includes `??` lines, `false` ignores them
   - Pruning: adding checkpoint 201 deletes checkpoint 1's ref and rewrites checkpoints.json
2. **Integration**
   - Start daemon
   - Create integration worktree
   - Start headless invocation that writes file + sleeps
   - Verify checkpoint created with `sandbox_head_sha`
   - Modify file again
   - Apply checkpoint (invocation must be stopped/finished first)
   - Verify file contents restored exactly (including untracked files cleaned)
   - Apply while running → `E_INVOCATION_STILL_RUNNING`
3. **Denylist**
   - Create `.env` (exact match)
   - Create `foo.pem` (suffix match)
   - Verify snapshot degrades to tracked-only
   - Verify `agency.checkpoint_denylist_triggered` event emitted
4. **Watcher**
   - fsnotify fires on file write → checkpoint created after debounce
   - New subdirectory created → watcher added for it
   - Events from `.git/` subdirectory → ignored (no checkpoint triggered)
5. **Events**
   - `events.jsonl` events have `agency.` prefix and monotonic `seq`
   - `events.jsonl` schema does not overlap with `stream.jsonl` kinds

## Pruning Policy

Max checkpoints per invocation: **200**.

**Deterministic pruning algorithm** (after adding checkpoint N):

1. Read `checkpoints.json` (source of truth, ordered by `id`)
2. If `len(checkpoints) > max`:
   - Compute IDs to delete = smallest `id` values until `len == max`
   - For each deleted checkpoint (under repo lock):
     - `git update-ref -d <snapshot_ref>`
   - Rewrite `checkpoints.json` atomically with remaining entries only
3. **Do not** use `git for-each-ref` to guess what exists — trust `checkpoints.json`

- Headed invocation checkpointing remains unsupported
- GC of old snapshot refs deferred to post-slice cleanup
