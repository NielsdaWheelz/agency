# PR-07 — Headless Stream Parsing, Normalized Events, and Semantic Status

## Purpose

Introduce **daemon-side parsing of headless runner output**, producing:

- A **stable, normalized event stream** (`stream.jsonl`)
- A **persisted semantic status** (`semantic_status`) in `InvocationMeta`
- No required CLI behavior changes — daemon remains the sole authority

This PR does **not** change lifecycle semantics. It augments headless invocations with higher-fidelity status while preserving graceful degradation.

---

## Scope

**In scope:**

- Line-framed parsing of headless runner stdout
- Runner-specific adapters (Claude, Codex)
- Normalized event schema
- Semantic status inference (headless only)
- Persisting semantic status into `InvocationMeta`
- Golden test fixtures for real runner output

**Out of scope:**

- Headed (tmux) parsing
- Watch UI
- SSE log streaming
- Checkpoints
- Invocation-level events.jsonl (optional follow-up)

---

## Architectural Position

PR-07 runs **inside the daemon** and sits directly in the headless streaming pipeline:

```
runner stdout
      ↓
line reader (bufio.Reader)
      ↓
┌─────────────┬─────────────────────────┐
│ raw.jsonl   │ normalized parser       │
│ (verbatim)  │ (runner-specific)       │
└─────────────┴──────────────┬──────────┘
                             ↓
                       stream.jsonl
                             ↓
                   semantic_status update
                             ↓
                     InvocationMeta write
```

**Daemon wiring:**

In `server.go`, the existing `streamOutput(proc, reader, file)` is replaced with:

```
streamAndParseOutput(proc, reader, rawFile, normalizedFile, adapter)
```

- `adapter` is chosen based on `invocation.Runner` (`claude`/`codex`) and `mode=headless`
- `normalizedFile` is `stream.jsonl`, created alongside `raw.jsonl` at invocation start (append-only)
- **stderr is not parsed** — `stderr.log` continues to be written verbatim with no normalization

If parsing fails at any point:

- raw.jsonl continues to be written
- lifecycle status continues normally
- semantic_status remains null

## Input Handling (Critical Change)

### Line-Framed Reader

Replace the existing chunk-based reader with a **line-based reader**:

- Use `bufio.Reader.ReadBytes('\n')`
- No `bufio.Scanner` (line length limits are unacceptable)
- Preserve exact bytes (including trailing newline) when writing `raw.jsonl`

**EOF partial line (critical):**

- On EOF with a non-empty buffer (final line without trailing newline), **still write it to raw.jsonl** and attempt to parse it as a normalized event
- Without this, the final runner event (often `result:success` or `turn.completed`) is silently dropped and "verbatim" becomes false

**Max line safety valve:**

- If a single line exceeds **8 MB**, write the raw bytes to `raw.jsonl` as-is, emit a `kind=parse_error` normalized event, and skip parsing for that line
- Implementation: accumulate via `ReadBytes('\n')` and check `len(buf)` before parsing; if over limit, write + skip
- Prevents unbounded memory growth from malformed runner output

**Invariant:**

> One logical JSON object per line is assumed for parsing, but raw capture remains verbatim regardless of parse success or line size.

```

├── raw.jsonl        # verbatim stdout (JSONL)
├── stderr.log       # verbatim stderr
└── stream.jsonl     # normalized events (this PR)
```

- `raw.jsonl` is written exactly as emitted by the runner
- `stream.jsonl` is daemon-generated
- CLI never parses `raw.jsonl`

## Normalized Event Schema

All normalized events written to `stream.jsonl` conform to:

```json
{
  "schema_version": "1.0",
  "seq": 42,
  "timestamp": "2026-02-01T14:12:33Z",
  "invocation_id": "20260128120500-b7c9",
  "runner": "claude|codex",
  "kind": "session_start|tool_start|tool_end|message|final|error|usage|status|parse_error",
  "data": { "... runner-specific payload ..." }
}
```

### Fields

- `seq`: monotonic `uint64`, starts at 1, incremented per normalized event per invocation. Provides stable ordering without relying on timestamps (which can collide). Enables cursor-based SSE streaming in future PRs.
- `kind`: event type. `parse_error` is emitted for malformed/oversized lines.

### Design Principles

- **Stable across runners**
- **Append-only**
- **Lossy by design** — not all runner detail is preserved
- Optimized for status derivation and watch UI, not full replay

## Runner Adapters

### Claude (`claude -p --output-format stream-json --verbose`)

Input events (raw.jsonl):

- `type=system, subtype=init`
- `type=assistant`
- `type=user`
- `type=result, subtype=success|error`

Normalization rules:

| Raw Event | Normalized kind | `data` contents |
| --- | --- | --- |
| system:init | session_start | `cwd`, `model`, `session_id` (if present) |
| assistant (with tool_use) | message | `has_tool_use: true`, `tool_names: [...]`, `text` (full content) |
| assistant (text only) | message | `has_tool_use: false`, `text` (full content) |
| user | message | `text` (tool result content) |
| result:success | final | `duration_ms` (if present), `cost_usd` (if present), `usage` (if present) |
| result:error | error | `message`, `code` (if present) |

### Codex (`codex exec --json`)

Input events:

- `thread.started`
- `turn.started`
- `item.started command_execution`
- `item.completed command_execution`
- `item.completed agent_message`
- `turn.completed`

Normalization rules:

| Raw Event | Normalized kind | `data` contents |
| --- | --- | --- |
| thread.started | session_start | (empty or minimal) |
| item.started command_execution | tool_start | `command` |
| item.completed command_execution | tool_end | `command`, `exit_code` |
| item.completed agent_message | message | `text` (full content) |
| turn.completed | usage | `input_tokens`, `output_tokens` |

**Text field policy:** store full text in normalized events (it's local storage; raw.jsonl has it anyway). No truncation in `data`.

Unknown event types are ignored (logged internally, not fatal).

## Semantic Status Inference (Headless Only)

### Baseline Rules

- Default: **no semantic status**
- Lifecycle status remains authoritative
- Semantic status updates are best-effort

### Claude

| Condition | Semantic Status |
| --- | --- |
| any assistant event | working |
| result:success | ready_for_review |
| result:error | unset (lifecycle = failed) |

Claude headless never emits "needs_input".

### Codex

| Condition | Semantic Status |
| --- | --- |
| any command_execution | working |
| agent_message (final) | ready_for_review |

**No `blocked` inference for headless codex in PR-07.** Codex does not emit a reliable structured signal for "cannot proceed." Attempting string-match heuristics is brittle and wrong more often than right. Lifecycle failure (`status=failed`, `failure_reason`) handles the actual error case. Blocked inference may be revisited if Codex adds explicit structured signals.

### Failed Invocations

If lifecycle status becomes `failed`:

- semantic_status is cleared
- no further semantic updates occur

---

## Update Throttling

Semantic status updates:

- Updated **in memory** on every parsed event
- Flushed to `InvocationMeta` at most **once per 500ms**, but **only if something changed**:
  - `semantic_status` value changed (e.g. `working` → `ready_for_review`)
  - `semantic_status_updated_at` timestamp advanced
- If nothing changed since last flush, no write occurs (avoids writing every 500ms when idle)
- Final flush guaranteed on process exit

Same mechanism as `last_output_at`.

---

## Error Handling

### Parse Errors

- Do **not** fail the invocation
- Do **not** mark lifecycle as failed
- Emit an internal daemon log
- Emit a throttled `kind=parse_error` normalized event (see Tests section for throttle rules)
- Increment in-memory `parse_error_count`
- semantic_status remains unchanged (last valid status preserved)

### Unknown Runner Output

- Ignored
- Logged at debug level
- No crash, no state change

## Tests

### Fixtures (Required)

Add real runner output fixtures:

```
internal/daemon/testdata/
├── claude_stream.jsonl
├── codex_stream.jsonl
├── malformed_mid_stream.jsonl
├── no_trailing_newline.jsonl
```

- Captured from actual runs (redacted paths allowed)
- Must include:
  - tool execution
  - final success
  - at least one long line (>4KB) to validate reader
  - `malformed_mid_stream.jsonl`: valid lines, then a malformed JSON line, then more valid lines
  - `no_trailing_newline.jsonl`: final line has no trailing `\n` (EOF partial line)

### Test Coverage

- Raw → normalized mapping (both adapters)
- `seq` values are monotonically increasing, starting at 1
- Semantic status transitions:
  - null → working → ready_for_review
- Throttled meta writes (only on change, not idle)
- Parser robustness to unknown events (ignored, no crash)
- Malformed JSON line in middle of stream:
  - raw.jsonl still has the line
  - `kind=parse_error` normalized event emitted with `data: { parse_error_count: N }`
  - subsequent valid lines still parsed normally
- EOF partial line (no trailing newline):
  - raw.jsonl has the final bytes
  - final event is still parsed and normalized
- Line exceeding 8 MB:
  - raw.jsonl has the raw bytes
  - `kind=parse_error` event emitted
  - parsing continues on next line

### Parse Error Normalized Events

On the first malformed/oversized line, emit:

```json
{ "kind": "parse_error", "data": { "parse_error_count": 1 } }
```

Subsequent parse errors increment the counter but **throttle emission** — emit at most one `parse_error` event per 10 errors (or per 5s), whichever comes first. This avoids flooding `stream.jsonl` with error events from a corrupted stream while still surfacing the problem.

## Acceptance Criteria

- [ ] raw.jsonl remains verbatim (including EOF partial lines and oversized lines)
- [ ] EOF partial line (no trailing newline) is written to raw.jsonl and parsed
- [ ] Lines exceeding 8 MB are written to raw.jsonl but not parsed (parse_error emitted)
- [ ] stream.jsonl is written for headless invocations with monotonic `seq`
- [ ] Normalized `data` fields match the per-adapter contracts (not handwavy)
- [ ] semantic_status appears in InvocationMeta
- [ ] No codex `blocked` inference (deferred)
- [ ] lifecycle behavior unchanged
- [ ] No CLI behavior changes required (optional changes allowed only to surface new fields)
- [ ] Parsing failures do not crash daemon
- [ ] Meta writes only flush when semantic_status actually changed
- [ ] Tests use real runner output fixtures (including malformed + EOF partial)
