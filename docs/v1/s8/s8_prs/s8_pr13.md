# Agency — Slice 8 — PR-13: Daemon Event Stream + Watch (L3 Spec)

## Purpose

Introduce a **daemon-owned event stream** and a **watch TUI** that consumes it, eliminating all filesystem polling and CLI-side state derivation.

After PR-13:

- The daemon is the **single source of truth** for state changes.
- The CLI (including `watch`) is a **pure client**.
- All live updates flow through an **ephemeral SSE stream**.
- Watch reacts to events; on disconnect or daemon restart, it performs a **full resync** via existing read endpoints.

This PR satisfies **Parity Rule C**.

---

## Non-Goals

- No WebSockets (SSE only).
- No durable event log (events are ephemeral, in-memory only — see §AD-1).
- No editing/config UI.
- No new semantic status logic (already exists from PR-07).
- No daemon-side summary cache (watch computes rollups client-side).
- No log SSE streaming (deferred; see §Log Streaming Deferral).

---

## Architectural Decisions (Locked)

### AD-1: Ephemeral in-memory event stream

No durable event log. No `events.jsonl`. No disk writes for events.

The daemon has no in-memory cache today — it recomputes truth from `meta.json` scans per request. Introducing a durable event log with replay/recovery/rotation creates a second authority that the daemon itself doesn't use. That's a half-measure.

Instead:
- Events live in an **in-memory ring buffer** (default 1000 events).
- Cursor = `uint64`, starts at 1 on each daemon boot. **Cursors are not valid across daemon restarts.**
- `since=<cursor>` works if the cursor is still in the ring buffer.
- If the cursor is evicted or from a previous daemon instance → client resyncs via list endpoints.
- On daemon restart: clients detect stale cursor from `daemon.hello` (new `daemon_instance_id`) and resync.

This matches the daemon's "no cache" philosophy. Durable replay can be added later with proper event sourcing if needed.

### AD-2: Event payloads

- Events carry **full DTO snapshots**, not deltas.
- Events are **notifications for incremental updates**; the resync endpoints (list/get) are authoritative. Clients use events to avoid polling, but must resync on cursor gaps or daemon restart.
- Event `data` field contains the DTO directly (e.g. `InvocationDTO`), not wrapped in `{"invocation": {...}}`. `entity_kind` + `entity_id` in the envelope provide routing.

### AD-3: Event types

| Type | When |
|------|------|
| `daemon.hello` | First event on SSE connect (always) |
| `worktree.upsert` | Worktree created, metadata changed, or `last_used_at` updated |
| `worktree.archived` | Worktree archived/removed |
| `invocation.upsert` | Lifecycle/status/display changes (see §Emission Rules) |
| `invocation.activity` | Periodic liveness signal for running invocations |
| `invocation.op` | Phase signal for multi-step operations (land/discard/checkpoint) |

`invocation.deleted` is deferred until GC is implemented. Invocation records are immutable once terminal for PR-13.

`daemon.hello` carries:
```json
{
  "type": "daemon.hello",
  "daemon_instance_id": "d-abc123",
  "cursor_now": 42,
  "api_version": 2,
  "build_version": "v0.8.13",
  "git_sha": "abc1234"
}
```

`invocation.activity` carries minimal data (not a full DTO):
```json
{
  "type": "invocation.activity",
  "entity_id": "inv-abc123",
  "repo_id": "repo-xyz",
  "last_output_at": "2026-02-05T14:03:12Z"
}
```
Emitted at most once per second per running invocation. Watch uses this for "last output X seconds ago" freshness without requiring status upserts.

`invocation.op` carries operation phase:
```json
{
  "type": "invocation.op",
  "entity_id": "inv-abc123",
  "repo_id": "repo-xyz",
  "op": "land",
  "phase": "started"
}
```
Phases: `started`, `succeeded`, `failed`. Watch can show a spinner or "landing..." indicator.

### AD-4: Emitter model — unit-of-work boundary

Central `EventEmitter` inside daemon. **All state-change events must flow through it.** No other package may emit events directly.

**Not** a wrapper-per-store-function. Instead, a unit-of-work API:

```go
// daemon/state package
func (s *StateService) Mutate(ctx context.Context, repoID string, fn func(tx *MutateTx) error) error
```

The closure performs mutations. On success, `Mutate` computes which DTOs changed and emits the appropriate events. This captures all writes regardless of which store function is called inside the closure.

For background loops (supervised process exit, checkpoint engine, stall detection): they call `Mutate(...)` the same way handlers do.

**Rule**: after PR-13, calling `store.*` write functions outside `Mutate()` for daemon-visible state is a bug.

### AD-5: Request correlation

- Every daemon request has a `request_id`.
- All events emitted during handling include that `request_id`.
- Background-loop events use a synthetic `request_id` (e.g. `bg-<loop_name>-<timestamp>`).
- Idempotent retries reuse the original `request_id`.

### AD-6: SSE protocol

- `Content-Type: text/event-stream`
- `http.Flusher` used
- Heartbeat comment every ~15s
- Supports `since=<cursor>` query param and `Last-Event-ID` header (query param wins if both present)
- Supports `repo_id=<id>` query param (omitted = all repos)
- Invalid cursor → typed error before streaming begins

## Data Model

### Event Record (in-memory / SSE wire format)

```json
{
  "cursor": 42,
  "timestamp": "2026-02-05T14:03:12Z",
  "type": "invocation.upsert",
  "entity_kind": "invocation",
  "entity_id": "inv-abc123",
  "repo_id": "abc123",
  "request_id": "7f8e9d...",
  "data": { /* InvocationDTO directly, no wrapper */ }
}
```

### Cursor Semantics

Cursors are strictly increasing `uint64`, assigned at emit time, held in memory only.

- On daemon boot: cursor starts at 1. Previous cursors are invalid.
- Ring buffer retains last N events (default 1000).
- `since=<n>`: if `n` is in the ring buffer, replay events with `cursor > n`, then live.
- `since=<n>` where `n` is evicted or from a prior daemon instance: 409 `E_CURSOR_INVALID`.
- `since` omitted: live only, no replay. `daemon.hello` provides `cursor_now`.

Clients detect daemon restart by comparing `daemon_instance_id` in `daemon.hello` against their stored value.

## Daemon Changes

### 1. EventEmitter (new internal component)

File: `internal/daemon/event_emitter.go`

```go
type EventEmitter struct {
    mu                sync.Mutex
    daemonInstanceID  string
    nextCursor        uint64
    ring              []EventRecord       // fixed-size ring buffer
    ringStart         int                 // oldest valid index
    subscribers       map[uint64]chan EventRecord
    bufSize           int                 // per-subscriber channel buffer, default 256
    fingerprints      map[string]invocationFingerprint // dedup
    activityTimers    map[string]time.Time // last activity emit per invocation
}
```

**Subscriber lifecycle:**
1. SSE handler validates `since` (or `Last-Event-ID`). If invalid → HTTP 409 JSON error. Connection does not upgrade to SSE.
2. If valid (or omitted): set `Content-Type: text/event-stream`, flush headers.
3. Send `daemon.hello` as first event.
4. If `since` provided and valid: replay from ring buffer **directly** to HTTP response writer (not via channel).
5. After replay: register subscriber with emitter (buffered channel, size 256).
6. Live events read from channel, written to response.
7. Emitter uses **non-blocking send**. If channel full → close channel. SSE handler detects close, terminates connection. Client reconnects.
8. Subscriber deregisters on client disconnect or overflow.

**Client requirement**: on SSE connect, if HTTP status != 200 or `Content-Type` != `text/event-stream`, read body as `APIResponse` and surface `error_code`.

### 2. State Service (unit-of-work boundary)

File: `internal/daemon/state/service.go`

All daemon handlers and background loops call this service for mutations. This is the **only** code path allowed to emit state-change events.

```go
type StateService struct {
    store   *store.Store
    emitter *EventEmitter
    derive  *StatusDeriver  // reuse existing status_derive.go logic
}

// Mutate executes a mutation closure and emits events for changed entities.
func (s *StateService) Mutate(ctx context.Context, repoID, requestID string, fn func(tx *MutateTx) error) error

// MutateTx tracks which entities were written during the closure.
type MutateTx struct {
    store           *store.Store
    writtenInvocations []string  // IDs of invocations whose meta was written
    writtenWorktrees   []string  // IDs of worktrees whose meta was written
}
```

On closure success, `Mutate`:
1. For each written entity: build DTO, compute derived status (display_status, attention_flags, sort_key).
2. Compare against fingerprint. If display-relevant fields changed → emit upsert.
3. If worktree `last_used_at` changed → emit `worktree.upsert`.

### 3. Emission Rules

#### Request-driven mutations

| Operation | Events emitted |
|-----------|----------------|
| Worktree create | `worktree.upsert` |
| Worktree rm/archive | `worktree.archived` |
| Invocation start | `invocation.upsert` + `worktree.upsert` (last_used_at) |
| Invocation status change | `invocation.upsert` |
| Land start | `invocation.op{op:"land",phase:"started"}` |
| Land success | `invocation.op{op:"land",phase:"succeeded"}` + `invocation.upsert` + `worktree.upsert` |
| Land failure | `invocation.op{op:"land",phase:"failed"}` |
| Discard | `invocation.upsert` + `worktree.upsert` (last_used_at) |
| Checkpoint apply start | `invocation.op{op:"checkpoint_apply",phase:"started"}` |
| Checkpoint apply end | `invocation.op{...phase:"succeeded"|"failed"}` + `invocation.upsert` |

#### Background-driven transitions

These are **critical** — watch must update when no HTTP request is happening:

| Source | Events emitted |
|--------|----------------|
| Headed tmux disappears (PR-11 reconcile loop) | `invocation.upsert` (status→finished/failed) |
| Headless process exits | `invocation.upsert` (status→finished/failed) |
| Checkpoint engine creates checkpoint | `invocation.upsert` |
| Stall detection flips (attention_flags change) | `invocation.upsert` |
| Landable flag changes | `invocation.upsert` |

Background loops must call `StateService.Mutate(...)` and run the same derive logic used by read endpoints. If the derived `display_status` or `attention_flags` change → emit.

#### Activity signal

For running invocations, emit `invocation.activity` at most once per second per invocation. This is a lightweight event (just `entity_id` + `last_output_at`) so watch can show freshness without full upserts flooding the stream.

**Ordering invariant**: `invocation.upsert` is emitted only after the relevant `meta.json` atomic rename is complete. If the DTO references checkpoints, `checkpoints.json` must be written first. If it references landing status, the git ref update must be complete first.

### 4. Upsert Deduplication (fingerprint)

Per-invocation fingerprint held in emitter memory. Cleared on daemon restart (fine — clients resync anyway).

Fingerprint fields: `Status`, `SemanticStatus`, `LandingStatus`, `DisplayStatus`, `AttentionFlags`, `FinishedAt`, `ExitReason`, `ExitCode`.

`LastOutputAt` is **not** in the fingerprint. Activity is handled by the separate `invocation.activity` event.

Rate limit: emit at most one `invocation.upsert` per 250ms per invocation, even if multiple writes happen within the window.

### 5. SSE Endpoint

```
GET /events?since=<cursor>&repo_id=<id>
```

Also accepts `Last-Event-ID` header (standard SSE reconnect). Query param `since` wins if both present.

**Query parameters:**
- `since` (optional): cursor to replay from ring buffer.
- `repo_id` (optional): filter events to a single repo. Omitted means all repos.

**Behavior:**

1. Parse `since` from query param, falling back to `Last-Event-ID` header.
2. Validate cursor against ring buffer. If invalid → HTTP 409 with `Content-Type: application/json` and JSON error envelope. Connection does not upgrade to SSE.
3. If valid (or omitted): set `Content-Type: text/event-stream`, flush headers, begin streaming.
4. **After streaming begins**: errors close the connection. No JSON responses mid-stream.
5. Send `daemon.hello` as first event (always).
6. If `since` provided: replay from ring buffer, then switch to live.
7. Heartbeat `": ping\n\n"` every ~15s.

**SSE framing:**

```
event: daemon.hello
data: {"type":"daemon.hello","daemon_instance_id":"d-abc","cursor_now":42,"api_version":2}

event: invocation.upsert
id: 42
data: {"cursor":42,"type":"invocation.upsert","entity_kind":"invocation","entity_id":"inv-1","repo_id":"abc","data":{...}}

event: invocation.activity
id: 43
data: {"cursor":43,"type":"invocation.activity","entity_id":"inv-1","last_output_at":"..."}

: ping

```

### 6. Cursor Watermark

Add `cursor_now` and `daemon_instance_id` to `HealthResponse` only:

```json
{
  "ok": true,
  "api_version": 2,
  "pid": 12345,
  "daemon_instance_id": "d-abc123",
  "cursor_now": 542,
  "uptime_seconds": 3600
}
```

Not added to `APIResponse` globally — that contaminates existing contracts for minimal benefit. Watch uses `/health` + `daemon.hello` for cursor discovery.

### 7. Log Streaming Deferral

Log SSE is **deferred from PR-13**.

Rationale: doing it right requires start-position semantics, partial-line handling, and file-rotation behavior.

**Watch and logs**: PR-13 watch does not include a logs pane. The `l` keybinding is deferred. Log viewing remains `agent logs --follow` as a separate command (polling `GetInvocationLogs` every 1-2s).

Explicit policy:
- **State updates**: SSE only, no polling.
- **Log content**: polling is acceptable only in `agent logs --follow` (separate command, not watch).

## Watch Client (CLI)

### Command

```
agency watch [--repo <repo_id>]
```

### Startup Sequence

1. **Page through all list endpoints** until `NextCursor == ""`:
   - `GET /worktrees?repo_id=<repo_id>&limit=500` (page until done)
   - `GET /invocations?repo_id=<repo_id>&limit=500` (page until done)
2. Build initial in-memory model:
   - `map[WorktreeID]WorktreeDTO`
   - `map[InvocationID]InvocationDTO`
3. Call `GET /health` to get `cursor_now` + `daemon_instance_id`.
4. Connect to `GET /events?repo_id=<repo_id>&since=<cursor_now>`.
5. On receiving `daemon.hello`: verify `daemon_instance_id` matches. If mismatch → full resync.

**Pagination rule**: watch must page until `NextCursor` is empty for both lists. Failure to do so silently drops state.

### Event Handling

- On `daemon.hello`: verify `daemon_instance_id`. If changed → full resync. Otherwise update `cursor_now`.
- On `worktree.upsert`: upsert local model.
- On `worktree.archived`: update state in model.
- On `invocation.upsert`: upsert local model, recompute worktree rollups.
- On `invocation.activity`: update `last_output_at` display for the invocation (no model upsert needed, just UI freshness).
- On `invocation.op`: show transient indicator (e.g. "landing..." spinner) on the invocation row.
- Unknown event types: ignore (forward-compatible).

### Reconnect Protocol

If SSE disconnects:
1. Reconnect with `since=<last_seen_cursor>`.
2. If HTTP 409 (`E_CURSOR_INVALID`):
   - Full resync (repeat startup sequence steps 1-5).
3. On receiving `daemon.hello`: if `daemon_instance_id` changed → full resync regardless of cursor validity.
4. Backoff: 100ms → 200ms → 500ms → 1s → 2s cap.

## Watch UI (Bubbletea)

### View Model

Hierarchical:

```
<worktree name> [branch] [state]  (3 running, 1 needs input)
  ├─ <invocation> <runner> <mode> <display_status>  [landing...]
  └─ ...
```

Derived only from DTOs and events (no git, no store).

### Worktree Header Rollups (client-side)

Each worktree node displays a summary computed from its child invocations:
- Count by `display_status` bucket: `running`, `needs input`, `blocked`, `ready for review`, `failed`.
- Only non-zero buckets shown.
- Example: `(2 running, 1 needs input)`

### Sorting

- **Worktree nodes**: sorted by `LastUsedAt` descending (most recently active first).
- **Invocation nodes within worktree**: sorted by `InvocationDTO.SortKey` ascending (lower = higher priority), then `StartedAt` descending as tiebreaker.
- Sort is **stable**: re-sort only when the model changes, not on every render tick.

### Selection Stability

- Selection tracks `invocation_id` (or `worktree_id` if on a worktree row).
- On model update: if the selected ID still exists, selection stays on it regardless of position change.
- If the selected ID is removed: selection moves to the nearest neighbor (prefer next, fallback previous).
- Collapse/expand state of worktree nodes is preserved across updates.

### Keybindings

| Context | Key | Action |
|---------|-----|--------|
| Invocation | Enter | Attach (headed) |
| Invocation | d | Diff |
| Invocation | L | Land |
| Invocation | D | Discard |
| Invocation | s | Stop |
| Invocation | k | Kill |
| Worktree | o | Open integration tree |
| Global | q | Quit |

All actions call existing daemon mutation endpoints. No logs keybinding in PR-13 (deferred with log streaming).

## Error Handling

- Mutation errors are rendered inline (toast/status bar).
- SSE errors:
  - Cursor invalid (409 before streaming) → full resync.
  - Daemon instance changed → full resync.
  - Temporary disconnect (mid-stream close) → reconnect with last cursor + backoff.
  - Hard error → show banner + retry with backoff.

## Acceptance Criteria

- `agency watch` shows live updates without filesystem polling for state.
- SSE stream delivers all display-relevant mutation events.
- Cursor resume works within same daemon lifetime.
- Stale cursor / daemon restart forces resync.
- Watch never reads store or git directly.
- Daemon is sole event authority.
- CLI does not derive status.
- No deadlocks or crashes under rapid event bursts.
- Pagination: watch pages through all list results at startup.
- Background transitions (tmux exit, process exit, stall detection) produce events.
- Activity signal keeps "last output" freshness without upsert floods.
- Multi-step operations show phase indicators.

## Invariants (Must Hold)

1. Watch state is fully reconstructible from daemon **list/get endpoints**. Events are notifications for incremental updates only; resync is authoritative.
2. No display-relevant mutation is invisible to the event stream (background loops included).
3. Events are emitted **after** state is durable — meta.json, checkpoints.json, git refs must all be committed before the corresponding event.
4. CLI remains stateless across restarts (resync works).
5. Daemon restart invalidates all cursors. Clients detect this via `daemon_instance_id` and resync.
6. SSE endpoint never sends JSON error responses after streaming headers are flushed.
7. No event state survives daemon restart. The ring buffer starts empty on boot.
8. Background transitions (process exit, stall detection) emit events with the same guarantees as request-driven mutations.
