# PR-06 — Daemon Owns Integration Worktree Mutations

## Purpose

Move **integration worktree creation and removal** behind the daemon, making the daemon the **single writer** for top-level v2 objects and eliminating split-brain git mutations.

This PR establishes safe serialization of `git worktree add/remove`, aligns daemon behavior with future landing/checkpoint flows, and reduces later migration complexity.

After PR-06:

- All **integration worktree mutations** (`create`, `rm`) are daemon-owned
- CLI becomes a thin RPC client for these operations
- Git worktree operations are serialized via the **repo lock**
- Daemon begins writing **repo.json**, not just `repo_index.json`

This PR satisfies **Parity Rule A (single writer)** for integration worktrees.

---

## Scope

### In Scope

- New daemon endpoints:
  - `POST /worktrees/create`
  - `POST /worktrees/{id}/rm`
- Daemon acquires **repo lock** for all integration worktree mutations
- Daemon writes:
  - `integration_worktrees/<id>/meta.json`
  - Integration worktree directory via `git worktree add/remove`
  - `.agency/INTEGRATION_MARKER`
  - `repo.json` (create/update)
  - `repo_index.json` (existing behavior)
- CLI routes `worktree create` and `worktree rm` through daemon RPC
- CLI auto-starts daemon for these commands if not running

### Explicitly Out of Scope

- Sandboxes
- Invocations
- Headed or headless runners
- Landing
- Checkpoints
- Watch
- Read-only commands (`worktree ls/show/path`) — still CLI-local until PR-12
- Worktree **branch deletion** or ref cleanup (branch is retained after `rm`; cleanup is a future concern)

## API Contract

### `POST /worktrees/create`

**Request**

```json
{
  "repo_root": "/abs/path/to/repo",
  "name": "my-feature",
  "parent_branch": "main",
  "idempotency_key": "uuid-optional"
}
```

**Behavior**

1. Canonicalize `repo_root`:
   - `Abs` -> `EvalSymlinks` -> `git rev-parse --show-toplevel`
2. Derive `repo_id` via `identity.DeriveRepoIdentity`
3. Acquire **repo lock** `${DATA_DIR}/repos/<repo_id>/.lock`
4. Validate name:
   - `core.ValidateName`
   - Unique among **non-archived** integration worktrees
5. Generate `worktree_id`
6. Compute branch name: `agency/<name>-<shortid>`
7. Create record dir (exclusive `os.Mkdir`)
8. Run:
   ```
   git -C <repo_root> worktree add -b <branch> <tree_path> <parent_branch>
   ```
9. Write `.agency/INTEGRATION_MARKER`
10. Write `meta.json`
11. Write/update `repo.json`
12. Release repo lock

**Rollback on partial failure:**

> **Create must be atomic from the user's perspective.**
> If any step after `git worktree add` (steps 9–11) fails, daemon must:
>
> 1. Remove the created git worktree (`git worktree remove --force`)
> 2. Delete the sandbox branch (best-effort; ignore if never created)
> 3. Remove the record directory (`os.RemoveAll`)
> 4. Release the repo lock
> 5. Return an error
>
> All cleanup steps are best-effort (log errors, don't panic). The repo lock is released in all cases (success or failure) via defer.

**Response**

```json
{
  "ok": true,
  "worktree_id": "20260128120000-a3f2",
  "tree_path": "/data/.../integration_worktrees/20260128120000-a3f2/tree"
}
```

**Idempotency**

- Idempotency key is scoped to `(repo_id, endpoint)` — i.e. `(repo_id, "worktrees/create")`
- Daemon stores an in-memory mapping: `idempotency_key → worktree_id`
- Mapping persists until daemon restart (acceptable; retry after restart creates a new worktree, not a conflict)
- If the key matches an existing entry: return the same `ok=true` response with the existing `worktree_id` and `tree_path`
- If the first attempt **failed after `git worktree add` but before response**, retry must detect the recovered worktree (via record dir existence + meta) and return it, not error
- Prevents double creation on client retry/crash

### `POST /worktrees/{id}/rm`

**Request**

```json
{
  "force": false
}
```

**Behavior**

1. Resolve worktree by id/name/prefix (error `E_WORKTREE_NOT_FOUND` if resolution fails)
2. Verify tree contains `.agency/INTEGRATION_MARKER` (error `E_NOT_AN_INTEGRATION_WORKTREE` if missing — prevents accidentally deleting user-managed worktrees)
3. Acquire **repo lock**
4. Check for active invocations targeting this worktree:
   - Source of truth: daemon queries its **own supervised processes map** (not a store scan)
   - Active := `status ∈ {starting, running}`, regardless of mode (headed/headless)
   - If any exist and `force=false` → error `E_WORKTREE_HAS_ACTIVE_INVOCATIONS`
   - If `force=true`:
     - Stop (SIGINT) → wait 5s → kill (SIGKILL) → discard all invocations (sandbox removal + meta update to `failed`, `failure_reason=worktree_removed`)
5. If integration tree is dirty and `force=false` → error `EDirtyWorktree`
6. Run:
   ```
   git -C <repo_root> worktree remove [--force] <tree_path>
   ```
7. Update `meta.json`:
   - `state = archived`
   - If `git worktree remove` succeeded but this meta update fails, the next rm attempt must detect the archived state and return success (idempotent rm)
8. Release repo lock

**Response**

```json
{ "ok": true }
```

**Notes**

- Branch is **not deleted**
- Record directory is retained (archived state)

## Locking Semantics

- Lock implementation reused from `internal/lock/repo_lock.go`
- Lock held for the **entire mutation sequence**, not just the git command
- Staleness detection remains PID-based

### Lock Acquisition Order

Daemon must acquire the repo lock **before**:

1. Generating a branch name
2. Checking name uniqueness
3. Creating the record directory
4. Invoking `git worktree add/remove`

Reason: two concurrent creates with the same name could otherwise race on name uniqueness checks, creating duplicate worktrees.

For `create`, this means the lock is acquired at step 3 (before step 4–12) and released at step 12.
For `rm`, the lock is acquired at step 3 (after resolve + marker check, before step 4–8) and released at step 8.

### Races Prevented

- Headless sandbox creation (PR-05 also acquires repo lock)
- Concurrent worktree creation with the same name
- Concurrent `create` + `rm` of the same worktree
- Future landing/checkpoint operations

## Repo Metadata Ownership

### Changes

- Daemon now writes `${DATA_DIR}/repos/<repo_id>/repo.json`
- CLI must **not** write `repo.json` for v2 flows after this PR
- CLI may continue writing `repo.json` for **legacy v1 commands only** (push, resume, merge, etc.) until PR-12 removes those code paths

### Rationale

- Integration worktree creation is a repo-authoritative operation
- Centralizing repo record writes avoids split-brain and simplifies PR-14
- Permitting legacy CLI writes avoids premature breakage of v1 commands before migration

## CLI Changes

- `agency worktree create`:
  - Auto-starts daemon if not running
  - Calls `POST /worktrees/create`
  - Prints returned `worktree_id` + path
- `agency worktree rm`:
  - Routes through daemon
- CLI must not:
  - Run `git worktree add/remove`
  - Write integration worktree `meta.json`

Read-only commands remain unchanged in this PR.

## Error Codes

New / reused error codes:

| Code | Meaning |
| --- | --- |
| `E_WORKTREE_HAS_ACTIVE_INVOCATIONS` | rm blocked by active agents |
| `E_WORKTREE_NOT_FOUND` | id/name/prefix resolution failed |
| `E_NOT_AN_INTEGRATION_WORKTREE` | tree missing `.agency/INTEGRATION_MARKER` on rm |
| `EDirtyWorktree` | uncommitted changes without `--force` |
| `E_WORKTREE_NAME_EXISTS` | name collision |
| `E_DAEMON_NOT_RUNNING` | daemon autostart failed |
| `E_DAEMON_INCOMPATIBLE` | API version mismatch |

All errors returned with structured `{ error_code, message, hint }`.

## Tests

### Required Tests

**Create:**

- Daemon creates integration worktree with marker + meta
- Name uniqueness enforced among non-archived worktrees
- Repo lock acquired before name check and held through meta write
- Concurrent create attempts serialize correctly (no duplicate names)
- Partial failure after `git worktree add` → rollback removes worktree + record dir
- Partial failure before `git worktree add` → no residue
- Idempotency key returns same worktree on retry
- Idempotency key after first-attempt crash (worktree exists, no response sent) → returns recovered worktree

**Remove:**

- `rm` resolves by id/name/prefix
- `rm` verifies integration marker before proceeding
- `rm` fails with active invocations (`E_WORKTREE_HAS_ACTIVE_INVOCATIONS`)
- `rm --force` stops (SIGINT) → waits 5s → kills (SIGKILL) → discards invocations → removes worktree
- `rm` after `git worktree remove` succeeds but meta update fails → retry returns success (idempotent)
- `rm` of non-integration worktree (missing marker) → `E_NOT_AN_INTEGRATION_WORKTREE`

**General:**

- CLI does not write meta files directly
- Daemon writes `repo.json` on create

### Non-Goals for Tests

- No sandbox or invocation behavior tests
- No watch or daemon streaming tests

## Acceptance Criteria

- [ ] `worktree create` and `rm` are daemon-owned
- [ ] Daemon acquires repo lock before name check / branch generation, holds through completion
- [ ] Create is atomic: partial failure rolls back worktree + record dir + branch
- [ ] Daemon writes `repo.json` and `repo_index.json`
- [ ] CLI performs no direct git worktree operations for v2 flows
- [ ] Active invocation guard enforced (daemon queries own process map, not store scan)
- [ ] `rm --force` escalation: SIGINT → 5s → SIGKILL → discard → remove
- [ ] `rm` verifies integration marker before proceeding
- [ ] `rm` is idempotent (retry after meta-update failure succeeds)
- [ ] Idempotent create supported (same key returns same worktree, including crash recovery)
- [ ] `E_WORKTREE_NOT_FOUND` returned for failed resolution
- [ ] Existing integration worktrees remain usable
