# Agency — Slice 8 · PR-11  
## Daemon-Owned Reconciliation for Headed Invocations

---

## Purpose

Move **headed invocation lifecycle reconciliation** fully into the daemon.

After this PR:

- The daemon is the **sole authority** for detecting when headed invocations finish.
- All reconciliation occurs in **daemon background loops**, not on read paths.
- CLI read commands (`agent ls`, `agent show`, `watch`) become **purely read-only**.
- Headed invocations are **reconciled on daemon startup and continuously thereafter**.

This PR completes the ownership transfer begun in PR-10 and satisfies **Parity Rule B** for headed invocations.

---

## Problem Statement

Currently:

- Headed invocations (tmux-backed) have no exit code.
- “Finished” is inferred by **tmux session disappearance**.
- Detection logic previously existed on *read paths* or ad-hoc checks.

This causes:

- Side effects during reads (anti-pattern).
- Inconsistent state after daemon restarts.
- In-memory state (`s.processes`) acting as accidental authority.

**Correct model:**  
The daemon must reconcile persisted invocation state against reality **independently of clients**.

---

## Goals

This PR must ensure:

1. **Daemon-only reconciliation**
   - No CLI code mutates invocation meta on read paths.
2. **Startup recovery**
   - Headed invocations are reconciled after daemon restart.
3. **Continuous correctness**
   - Long-running daemon detects tmux session termination promptly.
4. **Idempotence**
   - Reconciliation is safe to run repeatedly.
5. **Minimal surface area**
   - No new user-facing commands.
   - No new schema fields unless strictly necessary.

---

## Non-Goals

Explicitly out of scope:

- SSE / watch event emission (PR-13)
- Semantic status inference
- Checkpoint logic
- Landing or sandbox cleanup
- CLI UX changes

## Definitions

### Headed Invocation

An invocation where:

- `meta.mode == "headed"`
- `meta.tmux_session != ""`
- Lifecycle is tied to tmux session existence

### Terminal Lifecycle States

Per existing schema:

- `finished`
- `failed`

Landing status (`pending | landed | discarded`) is **orthogonal**.

---

## Source of Truth

- **Persisted invocation meta** (`invocations/<id>/meta.json`) is authoritative.
- `s.processes` is an **optimization only**.
- Reconciliation enumerates from store, not memory.

### In-Memory Process Map Rehydration (Headed)

After daemon restart, headed invocations may exist in the store (`status ∈ {starting, running}`) with a live tmux session but **no corresponding entry in `s.processes`**. This is valid.

Reconciliation relies solely on tmux session existence; `s.processes` is **not authoritative** for headed invocations.

Specifically, on reconciliation if:

- `mode == headed`
- `status ∈ {starting, running}`
- tmux session exists
- invocation is not present in `s.processes`

Then:

- **Do not change persisted meta** (invocation is still running).
- Do not re-insert into `s.processes`. The in-memory map is incomplete for headed invocations by design.
- `stop` / `kill` handlers must look up the tmux session name from persisted meta, not from `s.processes`.

## Reconciliation Model

### Scope

Reconciliation applies to invocation records where:

```text
mode == headed
status ∈ { starting, running }

tmux Presence Check

Use injected tmux.Client.HasSession(ctx, sessionName).

Interpretation:

Result	Meaning
exists	invocation still running
not exists	invocation has finished
error (non-no-session)	transient failure; do not finalize


⸻

Lifecycle Transitions

Reconciliation performs only one-way transitions:

Starting → Failed

If:
	•	status == starting
	•	invocation has **passed the tmux creation grace window**
	•	tmux session does not exist

Grace window: the reconciliation loop must **not** finalize a `starting` invocation on its first observation. A `starting` invocation is eligible for `→ failed` only after it has been observed as `starting` with no tmux session for **at least 2 consecutive reconciliation ticks** (i.e., ≥ 1 full tick interval after first observation). This avoids false failures when tmux session creation is still in-flight.

Implementation: track first-seen time per `starting` invocation in-memory (map evicted on transition or terminal). No new persisted field required.

Then:

status: "failed"
exit_reason: "start_failed"
finished_at: now
failure_reason: "tmux_session_missing"


⸻

Running → Finished

If:
	•	status == running
	•	tmux session does not exist

Then:

status: "finished"
exit_reason: "exited"
finished_at: now


⸻

No Other Transitions
	•	Never transition terminal → non-terminal
	•	Never modify landing_status
	•	Never infer semantic meaning

⸻

Error Handling

tmux Errors

If HasSession returns an error that is not IsNoSessionErr:
	•	Do not finalize invocation
	•	Log structured warning to **daemon log** (`agencyd.log`)
	•	Optionally append an `agency.reconcile_warning` event to the invocation's `events.jsonl` (best-effort, not required for PR-11)
	•	Retry on next tick

The daemon log entry must include: invocation ID, tmux session name, error string, tick number.

Examples:
	•	tmux binary missing
	•	tmux server unavailable
	•	permission errors

Idempotence

If invocation is already terminal:
	•	Reconciliation must no-op
	•	No writes

⸻

Daemon Architecture Changes

New Background Loop

Introduce a headed reconciliation loop inside daemon.

Lifecycle:
	•	Started during daemon initialization
	•	Runs until daemon shutdown

Tick interval:
	•	Default: 3 seconds
	•	Must be configurable via constant (no CLI flag)

Behavior per tick:
	1.	Enumerate headed, non-terminal invocations from store
	2.	For each:
	•	Check tmux session existence
	•	Apply transition if needed
	3.	Write meta only if transition occurred

Shutdown ordering constraint:

The reconciliation loop **must exit before** `terminateAllInvocations()` mutates invocation state. On shutdown:

1. Close `shutdownCh` (or cancel context).
2. Reconciliation loop selects on shutdown signal and **returns immediately** — no partial tick.
3. Only after the loop has exited do shutdown handlers write terminal meta.

This ensures shutdown handlers are the **sole writers during shutdown**. Without this invariant, a reconcile tick and a shutdown handler can race on the same meta (e.g., reconcile writes `finished` while shutdown writes `failed/killed`), producing nondeterministic terminal state.

⸻

Startup Recovery

On daemon startup:
	•	Headed invocations must be reconciled
	•	Either:
	•	Run one reconciliation pass synchronously before serving, or
	•	Allow background loop to run immediately after start

Requirement:
No headed invocation may remain permanently running if its tmux session is gone.

⸻

Store Writes
	•	Use existing Store.UpdateInvocationMeta(...)
	•	No repo lock required
	•	Atomic JSON replace semantics preserved
	•	Writes are rare and bounded

⸻

Removal of Legacy Logic

After this PR:
	•	Remove any remaining on-read reconciliation hooks (if present)
	•	CLI read paths must not:
	•	Check tmux
	•	Infer lifecycle transitions
	•	Write meta

CLI status derivation remains pure.

⸻

Testing Strategy

Unit Tests

Using FakeTmuxClient:
	1.	Running → Finished
	•	tmux session present → absent
	•	assert terminal transition
	2.	Starting → Failed
	•	no tmux session ever existed
	3.	Error handling
	•	HasSession returns non-no-session error
	•	assert no transition
	4.	Idempotence
	•	terminal invocation remains unchanged
	5.	tmux flaps (adversarial)
	•	HasSessionFunc returns sequence: error (tick 1) → exists (tick 2) → not exists (tick 3)
	•	assert: no transition on tick 1 (error does not poison state)
	•	assert: no transition on tick 2 (session exists)
	•	assert: transition to finished only on tick 3 (session gone)
	•	ensures errors don't finalize, existence beats transient failure, and condition ordering is correct

⸻

Integration Tests

Using daemon test harness:
	1.	Start headed invocation
	2.	Kill tmux session externally
	3.	Wait ≤ 2 reconciliation ticks
	4.	Assert:
	•	status == finished
	•	finished_at set
	•	exit_reason == exited

Also verify:
	•	Restart daemon → reconciliation still occurs
