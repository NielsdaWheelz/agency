# PR-05 — Daemon Control Plane for Headless Invocation Start

## Purpose

Make the daemon the **single creator and lifecycle owner** for **headless invocations**.

After PR-05:

* `agent start --headless` is a **single RPC**
* The daemon:

  * resolves the integration worktree
  * self-registers the repo if needed
  * creates the sandbox worktree
  * creates invocation metadata
  * spawns the runner
  * owns all lifecycle writes
* The CLI:

  * does **not** create invocation IDs
  * does **not** create sandboxes
  * does **not** write any v2 store files for headless
  * only sends requests and renders responses

This PR completes the architectural cut for headless execution.

---

## Invariants (Hard Requirements)

These invariants are **non-negotiable** and must be enforced by code + tests:

1. **Daemon is the sole writer** for all headless invocation artifacts:

   * invocation `meta.json`
   * sandbox directory
   * logs
   * lifecycle fields (`status`, `pid`, `exit_code`, etc.)
2. **No runner may ever execute in an integration worktree.**
3. **Sandbox creation is atomic**: no half-created sandbox or invocation record may remain after a failed start.
4. **Invocation IDs are daemon-generated.**
5. **Invocation names are unique among active invocations per repo.**
6. **CLI never touches the v2 store for headless paths.**

## API Changes

### New Endpoint

```
POST /invocations/start_headless
```

### Request

```json
{
  "repo_root": "/absolute/path/to/repo",
  "worktree_ref": "my-feature",
  "runner": "claude",
  "prompt": "fix the bug",
  "invocation_name": "auth-fix",          // optional, null/omitempty = no name
  "runner_args": ["--model", "opus"],     // optional
  "client_request_id": "uuid"            // required, client-generated
}
```

#### Validation Rules

* `client_request_id`

  * required, UUID format
  * used for idempotency (see Idempotency section)
* `repo_root`

  * must exist
  * resolved to canonical absolute path via `filepath.EvalSymlinks` (realpath)
  * daemon derives git root via `git rev-parse --show-toplevel`
  * **recursion guard**: daemon rejects if resolved path is inside an agency-managed worktree (`${DATA_DIR}/repos/<repo_id>/worktrees/.../tree` or `sandboxes/.../tree`) → `E_UNSAFE_REPO_ROOT`
  * if repo not in `repo_index.json`, daemon writes it
  * if repo already exists under a different path: update paths list + set `last_seen`
* `worktree_ref`

  * resolved by daemon (name → exact ID → unique prefix)
* `runner`

  * one of: `claude`, `codex`
* `invocation_name` (if provided)

  * null/omitempty means "no name" (unnamed invocation)
  * validated via `core.ValidateName`
  * must be unique among **active** invocations for this repo (see Name Uniqueness)
* `runner_args`

  * must not include reserved flags (see Runner Policy)
* `prompt`

  * required, non-empty
  * max size: 256 KB (reject with `E_PROMPT_TOO_LARGE` if exceeded)

### Idempotency

The daemon maintains a **recent requests map** keyed by `(repo_id, client_request_id)` → `invocation_id`.

* If a request arrives with a `client_request_id` that matches an existing entry:

  * return the same `ok=true` response with the existing `invocation_id`
  * do **not** create a new sandbox or invocation
* Map entries are evicted after 5 minutes (configurable)
* Map is in-memory only; lost on daemon restart (acceptable: client retries will see `E_INVOCATION_NAME_TAKEN` if named, or create a new invocation if unnamed)

Why this matters: autostart polls health and may race with the actual start RPC; socket hiccups cause client retries; without idempotency, one click creates multiple sandboxes.

---

### Name Uniqueness

* **Active** := `status` in `{starting, running}` AND `landing_status` is null
* Names are released when status becomes terminal (`finished`/`failed`) OR `landing_status` is set (`landed`/`discarded`)
* Collisions return `E_INVOCATION_NAME_TAKEN`
* Empty string / null / omitted `invocation_name` means "unnamed"; unnamed invocations skip uniqueness checks
* Uniqueness check is performed under the repo lock to prevent concurrent CLI processes from creating duplicates

---

### API Compatibility Check

Before calling `POST /invocations/start_headless`, the CLI must:

1. Call `GET /health`
2. Compare `api_version` in response against the CLI's expected version
3. If mismatch → return `E_DAEMON_INCOMPATIBLE` to the user with a hint to restart the daemon

The daemon includes `api_version` in every response for ongoing verification.

## Daemon Responsibilities (Headless Start)

### 1. Repo Resolution & Self-Registration

On request:

1. Resolve `repo_root` to canonical absolute path (`filepath.EvalSymlinks`)
2. Derive git root via `git rev-parse --show-toplevel`
3. **Recursion guard**: reject if resolved path is inside `${DATA_DIR}/repos/<repo_id>/worktrees/.../tree` or `sandboxes/.../tree` → `E_UNSAFE_REPO_ROOT`
4. Compute `repo_id` via `identity.DeriveRepoIdentity`
5. If repo not registered:

   * write `repo.json`
   * update `repo_index.json`
6. If repo already exists under a different path:

   * update `paths` list (append new path)
   * set `last_seen` timestamp
7. All subsequent paths derive from `repo_id`

---

### 2. Integration Worktree Resolution

* Resolve `worktree_ref` → `worktree_id`
* Load integration worktree meta
* Verify:

  * tree exists
  * `.agency/INTEGRATION_MARKER` exists
* Capture:

  * integration branch name
  * integration tree path
  * current HEAD commit → `base_commit`

Failure here aborts before any sandbox creation.

---

### 3. Atomic Invocation + Sandbox Creation

**Creation sequence (must be followed exactly):**

1. Generate `invocation_id`
2. Create invocation dir (exclusive mkdir)
3. Create sandbox dir (exclusive mkdir)
4. Create sandbox git worktree:

   ```
   git -C <repo_root> worktree add -b agency/sandbox-<invocation_id> <sandbox_path> <integration_branch>
   ```
5. Write `.agency/SANDBOX_MARKER` into sandbox
6. Verify sandbox does **not** contain integration marker
7. Write `invocation/meta.json` with:

   * status = `starting`
   * base_commit
   * sandbox_path
   * sandbox_branch
   * runner, mode, invocation_name
   * prompt_sha256
8. Create sandbox logs dir
9. Persist prompt:

    * write to `invocations/<id>/prompt.txt` (mode 0600)
    * compute `prompt_sha256` and store in meta
    * do **not** log prompt contents in daemon logs (only hash + first 80 chars for debug)
10. Spawn runner process
11. Update meta:

    * status = `running`
    * pid / pgid
    * daemon_instance_id
    * claimed_at

---

### 4. Cleanup on Failure (Critical)

If any step **before process spawn** fails, cleanup runs in reverse order:

1. Remove sandbox git worktree (`git worktree remove --force`) — must happen before branch delete
2. Delete sandbox branch — **best-effort**: if branch was never created, ignore error
3. Remove sandbox dir (`os.RemoveAll`)
4. Remove invocation dir (`os.RemoveAll`)

All cleanup steps are best-effort (log errors, don't panic). No recovery scan should be required for creation failures.

---

### 5. Runner Execution Policy

#### Command Construction

* **Claude**

  ```
  claude -p --output-format stream-json --verbose <prompt>
  ```
* **Codex**

  ```
  codex -C <sandbox_path> exec --json <prompt>
  ```

Both: `cmd.Dir` is always `sandbox_path` (belt+suspenders — codex uses `-C` for its internal path resolution, `cmd.Dir` sets process cwd).

#### Reserved Flags (Rejected if user supplies)

Reserved flag detection must catch:

* exact token matches (`--verbose`)
* prefix form (`--output-format=...`, `--cd=/x`)
* short flags (`-p`, `-C`)

Rejected flags:

* Claude:

  * `--output-format` (including `--output-format=...`)
  * `--print` / `-p`
  * `--verbose`
* Codex:

  * `exec`
  * `--json`
  * `-C` / `--cd` (including `--cd=...`)

Daemon returns `E_RUNNER_ARG_CONFLICT` if violated.

---

### 6. Lifecycle Ownership

After spawn:

* daemon is the **sole writer** for:

  * `status`
  * `pid` / `pgid`
  * `last_output_at`
  * `exit_code`
  * `exit_reason`
  * `failure_reason`
  * `finished_at`
* CLI must never write these fields.

#### `failure_reason` (string enum, optional/omitempty)

Set when `status` transitions to `failed`:

* `start_incomplete` — daemon crashed or timed out before runner spawned
* `sandbox_missing` — sandbox path disappeared while running
* `spawn_failed` — `exec.Command.Start()` returned error
* `runner_exit_nonzero` — runner exited with non-zero code
* `killed` — terminated via `kill` command (SIGKILL)
* `stopped` — terminated via `stop` command (SIGINT escalation)
* `daemon_shutdown` — terminated by `daemon stop --force`

---

### 7. Stop / Kill Semantics

* **stop**

  1. SIGINT to process group
  2. wait 5s
  3. SIGTERM
  4. wait 2s
  5. SIGKILL
* **kill**

  * immediate SIGKILL to pgid

---

### 8. Recovery Semantics (Daemon Startup)

On daemon startup:

* scan invocation metas with:

  * `status = starting`

    * if `started_at` > 60s ago and no pid → mark `status=failed`, `failure_reason=start_incomplete`
  * `status = running`

    * pid dead → `status=failed`, `failure_reason=runner_exit_nonzero` (or appropriate reason)
    * sandbox missing → `status=failed`, `failure_reason=sandbox_missing`
* mark `flags.orphaned=true` if daemon instance mismatch (informational, not blocking for stop/kill)

## Tests (Required)

### Unit / Integration Tests (fake runner)

Daemon spawns a test helper binary that emits JSONL and exits. No real claude/codex.

**Happy path:**

* start headless from inside repo cwd
* start headless from outside repo cwd
* fake runner runs to completion → verify log streaming + meta transitions
* status transitions: `starting` → `running` → `finished`

**Invariants:**

* sandbox never equals integration path
* sandbox contains SANDBOX_MARKER
* sandbox never contains INTEGRATION_MARKER
* daemon rejects repo_root inside agency-managed worktree (`E_UNSAFE_REPO_ROOT`)

**Failure cases:**

* invalid worktree_ref → error, no residue
* conflicting invocation name → `E_INVOCATION_NAME_TAKEN`
* reserved runner flag supplied → `E_RUNNER_ARG_CONFLICT`
* reserved flag in prefix form (`--output-format=json`) → `E_RUNNER_ARG_CONFLICT`
* prompt exceeds 256KB → `E_PROMPT_TOO_LARGE`
* failure during sandbox creation → no residual dirs/branches
* daemon crash mid-run → recovery marks invocation failed with `failure_reason`

**Idempotency:**

* same `client_request_id` returns same `invocation_id`, no duplicate sandbox
* different `client_request_id` creates new invocation
* expired idempotency entry → new invocation created

**API compatibility:**

* CLI detects `api_version` mismatch → `E_DAEMON_INCOMPATIBLE`

**Name uniqueness:**

* name freed after terminal status → can reuse
* name freed after `landing_status` set → can reuse
* concurrent create with same name → one succeeds, one gets `E_INVOCATION_NAME_TAKEN`

### Manual / E2E Tests (real runner)

Gated behind `E2E=1` env var. Not run in CI.

* real claude headless start → verify output + exit
* real codex headless start → verify output + exit

## Error Codes

| Code | Meaning |
|------|---------|
| `E_INTEGRATION_WORKTREE_NOT_FOUND` | worktree_ref does not resolve |
| `E_INVOCATION_NAME_TAKEN` | name already used by active invocation in this repo |
| `E_RUNNER_ARG_CONFLICT` | user-supplied args include reserved flags |
| `E_UNSAFE_REPO_ROOT` | repo_root is inside an agency-managed worktree |
| `E_PROMPT_TOO_LARGE` | prompt exceeds 256 KB |
| `E_DAEMON_INCOMPATIBLE` | CLI api_version does not match daemon api_version |
| `E_RUNNER_NOT_FOUND` | runner binary not in PATH |
| `E_RUNNER_START_FAILED` | exec.Command.Start() failed |
| `E_SANDBOX_VALIDATION_FAILED` | sandbox path / marker validation failed |
