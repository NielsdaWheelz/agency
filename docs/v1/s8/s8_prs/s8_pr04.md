# Slice 8 — PR-04: Headless Execution Supervisor via Daemon + Raw Logging

## Purpose

Introduce a **long-lived daemon** to own all **headless agent execution**, providing:

- Streaming stdout/stderr capture
- Correct process lifecycle management (start / stop / kill)
- Reliable PID tracking and recovery
- A foundation for future TUI (`watch`) and richer agent interaction

This PR completes **headless execution correctness** without touching checkpoints, parsing, or watch UI. In PR-04, the daemon supervises headless processes; sandbox + invocation record creation remains CLI-owned and is migrated to daemon ownership in PR-05.

### In Scope

## Architectural Decision

### Why a Daemon (Hard Decision)

Headless execution **must not** be implemented via:

- tmux
- Synchronous `exec.Run`
- Ad-hoc goroutines inside CLI commands

**Professional gold standard:**
Long-running, streaming, cancelable processes are owned by a **single supervisor process**.

The daemon:

- Owns child processes
- Streams logs incrementally
- Survives CLI exits
- Becomes the single coordination point for future watch/TUI features

## Daemon Model

### Process

- Same binary: `agency daemon`
- Subcommands:
  ```
  agency daemon start              # foreground: run server loop in current process
  agency daemon status             # client: call GET /health
  agency daemon stop               # client: graceful shutdown via RPC, pidfile SIGTERM fallback
  ```
- `daemon start` runs the server loop in the current process — foreground, Ctrl-C kills, easy to debug. This is also what process supervisors (systemd, launchd) would invoke.
- There is **no** `--detach` flag, `setsid` re-exec, or background mode in PR-04. Background spawning is an implementation detail of **autostart** (see below), not a user-facing daemon command. `--detach` may be added in a later PR if needed.
- Single instance per user
- No system install (no launchd/systemd required; architecture should not preclude it)

### IPC

- Unix domain socket:
  ```
  ${AGENCY_DATA_DIR}/agencyd.sock
  ```
- Permissions: `0600` (owner-only read/write)
- Protocol: HTTP + JSON (not gRPC)

#### Socket Security

- Daemon binds **only** to Unix domain socket — **never** TCP
- Daemon creates socket and immediately `chmod 0600` (owner-only read/write)
- If existing socket file found on startup:
  - Read PID file → if PID is dead (stale socket) → delete socket file, proceed
  - If PID is alive → refuse to start (`E_DAEMON_ALREADY_RUNNING`)
- No authentication token needed — Unix socket perms are the auth boundary
- No "refuse if widened" check in v0 — not a realistic local threat model

### Daemon Lifetime

- `agency daemon start` runs the server loop in the current process (foreground, Ctrl-C kills).
- If daemon is already running (socket responds to `/health`), `start` prints a message and exits 0 (no-op).
- PID file: `${AGENCY_DATA_DIR}/agencyd.pid` — written by server on startup, removed on clean shutdown.
- **SIGTERM handler (daemon side):** On SIGTERM (or SIGINT), the daemon:
  1. Stops accepting new requests (closes listener)
  2. Drains in-flight HTTP handlers
  3. Flushes all pending `meta.json` writes for supervised processes
  4. Removes socket file and PID file
  5. Exits 0

### `daemon stop`

`daemon stop` is an **RPC-first** operation with a **pidfile fallback**:

1. Attempt `POST /shutdown` on socket
   - Daemon handler checks for active headless invocations (`status=running`, `mode=headless`)
   - If any active: return `E_DAEMON_BUSY` with list of running invocation IDs — CLI prints error and refuses
   - `--force` flag: CLI sends `POST /shutdown?force=true` — daemon **terminates all supervised headless invocations** before shutdown:
     1. Send SIGINT to each active process group
     2. Wait up to 5s for graceful exit
     3. SIGKILL any remaining process groups
     4. Mark all terminated invocations `status=failed`, `exit_reason=killed`
     5. Proceed with graceful daemon shutdown
   - If no active (or after force-termination): daemon initiates graceful shutdown (same as SIGTERM handler sequence) and returns `{ "ok": true }`
   - **Rationale:** `--force` must not leave runaway agent processes with tool permissions. A daemon that leaves orphaned agents is worse than one that kills them.
2. If socket is dead (connection refused, no socket file): fall back to PID file
   - Read PID file, send SIGTERM
   - Wait for process to exit (max 5s — acceptable arbitrary threshold for local tooling)
   - If still alive after timeout, send SIGKILL
   - After PID is confirmed dead: CLI removes socket file and PID file only if PID is dead
   - **Note:** This path skips graceful shutdown — daemon may leave partial meta writes. Daemon startup always performs full stale cleanup (recovery scan) to handle this.

**Rationale:** In PR-04 the daemon is the supervisor — killing it mid-run is "cut the power." RPC-first lets the daemon refuse safely and terminate children cleanly. Pidfile fallback is the emergency path for when the daemon is wedged and the socket is unresponsive.

### `daemon status` Independence

`daemon status` is a purely control-plane operation. It does **not** require access to the store, repo state, or any invocation data. It operates via socket (`GET /health`).

### Daemon Instance Identity

On startup, the daemon generates a `daemon_instance_id` (UUID v4). This token is:

- Returned in `GET /health` responses
- Written into invocation meta when claiming a process:
  - `daemon_pid` (int) — daemon's own PID
  - `daemon_instance_id` (string) — current daemon run token
  - `claimed_at` (RFC3339 timestamp) — when the daemon took ownership

**Ownership vs. liveness vs. operability:**
- **Ownership** = which daemon instance is actively supervising (streaming logs, waiting on exit). Determined by `daemon_instance_id` match.
- **Liveness** = is the runner process still alive. Determined by PID/PGID liveness check.
- **Operability** = what can the current daemon still do. After restart, the daemon *cannot* reattach pipes (log streaming lost), but it *can* still stop/kill by PID/PGID from meta.

`daemon_instance_id` tracks ownership, not liveness. A mismatched instance means "no one is streaming logs," not "the process is broken." `flags.orphaned` is **informational** — it does not block stop/kill operations.

### Autostart

Any command requiring the daemon (`agent start --headless`) must:

1. Attempt `GET /health` on socket
2. If socket missing, connection refused, or `/health` fails → spawn daemon in background:
   ```go
   cmd := exec.Command(os.Args[0], "daemon", "start")
   cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}
   cmd.Stdout = logFile  // ${AGENCY_DATA_DIR}/agencyd.log
   cmd.Stderr = logFile
   cmd.Start()           // do NOT Wait — parent returns immediately
   ```
   The CLI spawns `agency daemon start` in a detached process group with stdout/stderr redirected to `agencyd.log`. Since `daemon start` is foreground-only, it will run the server loop in that background process.
3. Poll `GET /health` with exponential backoff until ok (max 5s)
4. Retry the original request

## Daemon Server Architecture

The daemon is implemented as a `daemon.Server` type with injected dependencies, making it unit-testable without forking real processes:

```go
type Server struct {
    Store      *store.Store
    Runner     exec.Runner         // interface for spawning processes
    FS         fs.FS               // filesystem abstraction
    Clock      func() time.Time    // injectable clock
    PIDChecker func(int) bool      // injectable "is PID alive" check
    InstanceID string              // UUID generated at startup
}

func (s *Server) Serve(listener net.Listener) error
func (s *Server) Shutdown(ctx context.Context) error
```

**Rationale:** Spawning a real daemon process in tests is slow and flaky. An injectable `Server` type lets tests run the HTTP handler on a temp Unix socket or `httptest.Server` with mocked dependencies. `exec.Runner`, `Clock`, and `PIDChecker` are the key injection points — they control process lifecycle, time, and liveness checks respectively.

Tests use `httptest.NewUnstartedServer` with the daemon's `http.Handler`, or bind to a temp Unix socket. No process forking needed for unit tests.

### Package Layout

```
internal/daemon/         # server, handlers, supervisor logic
internal/daemonclient/   # HTTP-over-Unix-socket client, used by CLI commands
internal/commands/daemon_start.go
internal/commands/daemon_status.go
internal/commands/daemon_stop.go
```

Process supervision logic lives in `internal/daemon`, never in `internal/commands`. CLI daemon commands are thin wrappers that call `daemonclient`.

## Invocation Naming

PR-04 introduces invocation naming, completing the unified name resolution pattern established by worktree naming in PR-01.

### `--name` Flag

`agency agent start --name <name>` assigns an optional human-readable name to the invocation.

- Validated by `core.ValidateName()` (same rules as worktree names: 2-40 chars, lowercase alphanum + hyphens)
- Unique among active (non-terminal) invocations per repo
- Stored in `invocation_name` field in `meta.json`
- If omitted, invocation is unnamed (referenced by ID or prefix)

### Resolver Update

The invocation resolver (`ids.ResolveInvocationRef`) is updated to match the worktree resolver pattern:

1. **Exact name match** among eligible (active, non-terminal) invocations
2. **Exact ID match** (works for all including terminal — escape hatch)
3. **Unique ID prefix match** among eligible invocations
4. **Ambiguous** → error listing candidates

Previously, the invocation resolver only supported steps 2-3. This PR adds step 1.

### Uniqueness

- Checked at invocation creation time (in `invocation.Service.Create`) **under repo lock**
- The name scan + meta write must be atomic (hold repo lock for the entire create-with-name path). Without this, two concurrent CLI processes can both pass the uniqueness check and create duplicate-named invocations.
- Scope: all active (non-terminal) invocations per repo, globally (not per-worktree)
- Released when invocation reaches terminal state (finished, failed, landed, discarded)
- `E_NAME_EXISTS` error if name collides with an active invocation
- Name reservation moves to daemon in PR-05 when invocation creation migrates

### Display

- `agent start` output includes name when provided
- Future `agent ls`/`show` (PR-12) display name as primary label when present, truncated ID otherwise

## CLI ↔ Daemon API (PR-04)

### `POST /invocations/{id}/start_headless`

**Request:**

```json
{
  "repo_id": "abc123",
  "invocation_id": "20260128120500-b7c9",
  "runner": "claude",
  "sandbox_path": "/path/to/data/repos/.../sandboxes/20260128120500-b7c9/tree",
  "prompt": "implement feature X ...",
  "runner_args": ["--model", "sonnet"],
  "env": { "KEY": "value" }
}
```

**Notes:**

- `invocation_id` is generated by CLI (already created invocation record + sandbox before this call)
- `sandbox_path` is supplied by CLI (already created by `invocation.Service.Create`)
- `prompt` is the full prompt text (CLI reads from file/editor/string, sends as string)
- Daemon constructs the full runner command via its runner adapter — **CLI does not send command arrays**
- `runner_args` are optional pass-through args appended after the daemon-constructed base command

**Response:**

```json
{
  "ok": true,
  "pid": 54321,
  "pgid": 54321,
  "daemon_instance_id": "<uuid>",
  "already_running": false,
  "orphaned": false,
  "log_paths": {
    "raw": "sandboxes/<id>/logs/raw.jsonl",
    "stderr": "sandboxes/<id>/logs/stderr.log"
  }
}
```

Notes:
- `already_running: true` + `orphaned: false` = idempotent hit, this daemon is supervising
- `already_running: true` + `orphaned: true` = process alive but no daemon streaming logs (previous instance)
- `pid`/`pgid` returned for debugging; CLI does not use them directly (stop/kill go through daemon endpoints)
- `log_paths` enables CLI to print where logs are being written

**Error response:**

```json
{
  "ok": false,
  "error_code": "E_SANDBOX_VALIDATION_FAILED",
  "message": "sandbox does not contain SANDBOX_MARKER",
  "hint": "verify sandbox was created correctly via agent start"
}
```

### `POST /invocations/{id}/stop`

Graceful stop (SIGINT to process group).

### `POST /invocations/{id}/kill`

Force kill (SIGKILL to process group).

### `POST /shutdown`

Graceful daemon shutdown. Used by `daemon stop`.

**Query parameters:**
- `force=true` — terminate all active headless invocations (SIGINT → wait 5s → SIGKILL), then shut down

**Behavior:**
1. If `force` is not set, check for active headless invocations (`status=running`, `mode=headless`)
2. If any active → return `E_DAEMON_BUSY` with list of running invocation IDs
3. If `force=true` → terminate all active headless invocations (SIGINT to process groups → wait 5s → SIGKILL remaining → mark all `status=failed, exit_reason=killed`), then initiate graceful shutdown, return `{ "ok": true }`
4. If none active → initiate graceful shutdown (same as SIGTERM handler), return `{ "ok": true }`

### `GET /health`

Returns:
```json
{
  "ok": true,
  "api_version": 1,
  "build_version": "<semver_or_sha>",
  "git_sha": "<sha>",
  "pid": 12345,
  "daemon_instance_id": "<uuid>",
  "uptime_seconds": 3600
}
```

### MUST NOT appear in request

- `command: [...]` — daemon constructs command via runner adapter
- Any field implying daemon computes `sandbox_path` — CLI supplies it in PR-04

## Invocation Lifecycle (Headless)

### Start

1. **CLI:**
   - Resolves integration worktree (verify marker, validate state)
   - Creates sandbox worktree + invocation record via `invocation.Service.Create` (`status=starting`, `mode=headless`)
   - Reads prompt (from file, string, or editor)
   - Sends `POST /invocations/{id}/start_headless` to daemon with `repo_id`, `sandbox_path`, `runner`, `prompt`
2. **Daemon:**
   - Validates gates (see Daemon Validation Gates below)
   - Creates logs directory (`sandboxes/<id>/logs/`) if missing
   - Writes prompt to `invocations/<id>/prompt.txt`, records `prompt_sha256` in meta
   - Resolves runner command via `config.ResolveRunnerCmd`
   - Spawns process with:
     - `cmd.Dir = sandbox_path`
     - `cmd.SysProcAttr.Setpgid = true` (new process group)
     - stdout/stderr piped to log files
   - Updates invocation meta via `UpdateInvocationMeta`:
     - `pid = <pid>`, `pgid = <pgid>`, `status = "running"` (`started_at` already set by CLI at invocation creation — daemon does not overwrite)
     - `daemon_pid = <daemon_pid>`, `daemon_instance_id = <uuid>`, `claimed_at = now`
   - Returns response with `ok`, `pid`, `pgid`, `daemon_instance_id`, `log_paths`, `already_running`, `orphaned` to CLI

## Logging Contract (Hard Requirement)

### Directory

```
sandboxes/<invocation_id>/logs/
├── raw.jsonl     # verbatim stdout (JSONL)
└── stderr.log    # verbatim stderr
```

### File Open Contract

Daemon must:

- Create logs dir eagerly (before process start)
- Open both files with `O_APPEND | O_CREATE | O_WRONLY`
- Write **as bytes arrive** (no buffering until exit)
- No fsync on every write (v0 — acceptable loss window is process crash)
- No file rotation or size limits in v0; if `raw.jsonl` grows beyond practical limits, set `flags.needs_attention = true` (deferred)
- **No combined log** in PR-04 — `raw.jsonl` and `stderr.log` are the only output files

### `raw.jsonl`

- **Runner stdout verbatim** — exact bytes as emitted, even if content is not valid JSONL at every intermediate moment (e.g., codex may emit progress items that aren't newline-terminated promptly)
- Implementation: `io.Copy` (or `io.CopyBuffer`) from stdout pipe into file. Do not couple meta update frequency to file write granularity — `last_output_at` is tracked in-memory on each read, flushed independently.
- Newline preservation exact — bytes stored as received, no line-buffering or newline injection

### `stderr.log`

- Exact stderr bytes, same `io.Copy` approach

### Meta Updates

Daemon updates meta fields with two different strategies:

- **Status transitions** (`status`, `pid`, `pgid`, `exit_code`, `exit_reason`, `finished_at`, `daemon_pid`, `daemon_instance_id`, `claimed_at`): written **immediately** via `UpdateInvocationMeta`. These are low-frequency, high-importance events.
- **Activity timestamps** (`last_output_at`): throttled. Daemon updates an in-memory timestamp on **every** stdout/stderr chunk, and flushes to `meta.json` at most **once per 500ms** via `UpdateInvocationMeta`.

Logs themselves are **never** throttled — every byte is written to disk immediately. Only the `last_output_at` meta write is throttled. Do not throttle status transitions — juniors throttling everything will produce stale status.

## Exit Handling

When process exits (detected by daemon's wait loop):

- Record `exit_code`
- Set status:
  - `status = "finished"` if `exit_code == 0`
  - `status = "failed"` otherwise
- Set `exit_reason = "exited"`
- Set `finished_at = now`
- Clear `pid` (set to nil)

Daemon must treat **non-zero exit code as non-error** at execution level (matches existing CommandRunner semantics).

### `exit_reason` Values (Canonical)

| Value | Set by | Meaning |
|---|---|---|
| `"exited"` | Daemon exit handler | Process exited normally (any exit code) |
| `"killed"` | Kill endpoint | SIGKILL sent by user via `agent kill` |
| `"start_failed"` | Daemon start path | Process failed to start (binary not found, etc.) |
| `"unknown"` | Crash recovery | Daemon restarted, process gone, exit not observed |

### PID Clearing Rules

`pid` is cleared (set to nil) whenever the invocation reaches a terminal state:

- Normal exit → pid cleared
- Kill → pid cleared
- Stop that escalates to kill → pid cleared
- Crash recovery marks failed → pid cleared

PID is **kept** while the invocation is still `running` — even if `stop_requested_at` is set (the process may still be alive).

## Stop / Kill Semantics

### Process Group Contract

At spawn, daemon sets `cmd.SysProcAttr.Setpgid = true` to create a new process group. This ensures signals reach the runner **and all its children**.

**PGID retrieval:** After `cmd.Start()`, the child's PGID equals its PID (because `Setpgid = true` makes the child the process group leader). Daemon records `pgid = cmd.Process.Pid` in memory **and persists it in invocation meta** (`pgid` field). For defense, daemon may also call `syscall.Getpgid(pid)` to verify.

**Why persist pgid:** After daemon restart, the daemon cannot reattach pipes but can still stop/kill by signaling the process group. Without a persisted pgid, the daemon must guess (assume pgid==pid, which is usually true but not guaranteed if something went wrong). Persisting eliminates the guess.

- **Stop:** `syscall.Kill(-pgid, syscall.SIGINT)` — sends SIGINT to entire process group
- **Kill:** `syscall.Kill(-pgid, syscall.SIGKILL)` — sends SIGKILL to entire process group

Both `setpgid` and `killpg` (negative PID) work identically on macOS and Linux.

### Stop/Kill for Orphaned Invocations

Stop and kill endpoints work **even for orphaned invocations** (where `flags.orphaned=true` and `daemon_instance_id` doesn't match). The daemon reads `pgid` from persisted meta and signals the process group directly. `flags.orphaned` is informational — it means "no daemon is streaming logs," not "the process is unreachable."

### Stop

- Send SIGINT to process group via `syscall.Kill(-pgid, syscall.SIGINT)`
- Update invocation meta:
  - `stop_requested_at = now`
  - `flags.needs_attention = true`
  - `status` remains `running` (stop is a request, not a guarantee)
- If process exits → normal exit path (status set by exit handler)
- If still alive after 5s → CLI may escalate to `kill`

### Kill

- Send SIGKILL to process group via `syscall.Kill(-pgid, syscall.SIGKILL)`
- Update invocation meta:
  - `status = "failed"`
  - `exit_reason = "killed"`
  - `finished_at = now`
  - `pid` cleared (set to nil)

If PID is already gone when kill is called: still mark `status=failed`, `exit_reason=killed`, `finished_at=now`. The user's intent is to finalize the invocation regardless of current process state.

## Crash Recovery (v0)

On daemon startup:

1. Scan invocation metas where:
   - `mode=headless`
   - `status=running`
   - `pid != null`
2. For each, check if PID is alive (`syscall.Kill(pid, 0)`):

**Case A: PID is NOT alive:**
   - Mark `status = "failed"`
   - `exit_reason = "unknown"`
   - `finished_at = now`
   - `pid` cleared (set to nil)
   - `flags.needs_attention = true`
   - `flags.orphaned = true`

**Case B: PID IS still alive but `daemon_instance_id` doesn't match current daemon (or is missing):**
   - Keep `status = "running"` (do not change)
   - Set `flags.needs_attention = true`
   - Set `flags.orphaned = true`
   - Set `orphaned_at = now`
   - Daemon does **not** attempt to resume log streaming (pipes were lost with the old daemon process)
   - User should `agent kill` and restart the invocation

**Rationale for Case B:** Killing a still-running process automatically on daemon restart would be surprising behavior. The user may want to inspect. Setting `needs_attention` surfaces the problem without destroying work.

No restart or resumption in PR-04.

## Prompt Handling

- **CLI** reads prompt from file, string, or editor and sends full prompt text in the API request
- **Daemon** writes prompt to:
  ```
  invocations/<id>/prompt.txt
  ```
- Prompt file permissions: `0600` (prompts can contain secrets — API keys, credentials in context)

- Daemon records in invocation meta via `UpdateInvocationMeta`:
  ```json

    "prompt_path": ".../prompt.txt",
    "prompt_sha256": "..."
  }
  ```

This guarantees auditability and reproducibility. The CLI acquires the prompt; the daemon persists it.

## CLI Behavior Contracts

### `agency agent start --headless [--worktree <ref>] [--name <name>]`

- **Default (no `--detached`):** CLI sends start request to daemon, prints invocation info, then returns immediately. Headless implies detached by default — there is no terminal to occupy.
- **`--detached`:** Identical to default. The flag is accepted but is a no-op for headless mode (exists for symmetry with headed mode).

**Rationale:** Unlike headed mode where "not detached" means "attach to tmux", headless has no interactive session to attach to. Blocking the CLI to tail logs is a UX feature (`--follow`) deferred to a later PR. In v0, headless start always returns immediately after daemon acknowledges.

### `agency agent stop <invocation>` (headless)

- CLI sends `POST /invocations/{id}/stop` to daemon
- Daemon sends SIGINT to process group
- CLI prints confirmation and returns immediately
- **Does not** wait for process to exit — user may follow up with `kill` if needed

### `agency agent kill <invocation>` (headless)

- CLI sends `POST /invocations/{id}/kill` to daemon
- Daemon sends SIGKILL to process group, updates meta
- CLI prints confirmation

## Daemon Validation Gates (Non-negotiable)

Before spawning the runner, daemon must verify:

1. Invocation `meta.json` exists at the **computed** path `Store.InvocationMetaPath(repo_id, invocation_id)`
2. **Meta cross-validation:** daemon reads invocation meta from disk and verifies:
   - `meta.mode` == `headless`
   - `meta.sandbox_path` == request `sandbox_path` (exact equality)
   - This prevents a client from supplying a `sandbox_path` that doesn't match what the CLI persisted, or invoking start on a non-headless invocation
3. `sandbox_path` exists and contains `.agency/SANDBOX_MARKER`
4. `sandbox_path` does **not** contain `.agency/INTEGRATION_MARKER`
5. `sandbox_path` equals the **computed** expected path `Store.SandboxTreePath(repo_id, invocation_id)` — not a substring match, but exact equality against the store-derived path
6. `runner` is a recognized value (`claude`, `codex`)
7. `prompt` is non-empty

**Path derivation rule:** daemon uses `repo_id` from the request and store path helpers to compute expected paths. Gate 5 compares against the **store-computed path**, not a string pattern match. Gate 2 adds a second layer by verifying the request matches what the CLI already persisted in meta.

### Idempotency

`POST /invocations/{id}/start_headless` must be idempotent to handle retries, user impatience, and autostart races:

- If `status=running` and `pid != nil` and PID is alive **and** `daemon_instance_id` matches current daemon → return ok with `already_running: true, orphaned: false` (idempotent success, this daemon is actively supervising)
- If `status=running` and `pid != nil` and PID is alive **but** `daemon_instance_id` doesn't match (or is missing) → return ok with `already_running: true, orphaned: true`. Set `flags.orphaned=true`, `orphaned_at=now` in meta. Process is still running but no daemon is streaming logs. Stop/kill still work.
- If `status=running` and `pid != nil` but PID is dead → mark `status=failed`, `exit_reason=unknown`, `flags.orphaned=true`, `flags.needs_attention=true`. Return error `E_INVOCATION_ORPHANED`.
- If terminal status (`finished`, `failed`, `landed`, `discarded`) → return error `E_INVOCATION_TERMINAL`

### Failure Marking

On **permanent** validation failure (bad marker, wrong path, unrecognized runner): daemon marks invocation `status=failed`, `exit_reason=start_failed`, `flags.needs_attention=true` via `UpdateInvocationMeta`. This prevents "stuck in `starting` forever" states.

On **transient** failure (connection error, autostart race): CLI reports the error, no meta change.

On **runner spawn failure** (binary not found, exec error): daemon marks invocation `status=failed`, `exit_reason=start_failed`, `finished_at=now`.

**Rationale:** Prevents a buggy or malicious client from asking the daemon to run in an integration tree or arbitrary directory. Permanent failures are surfaced truthfully in state.

## Store Interaction Rules

- Daemon uses `UpdateInvocationMeta` exclusively — it never calls `WriteInvocationMeta` (CLI creates the initial record)
- No direct file writes outside store helpers (except log files and prompt.txt, which are daemon-owned)
- Atomic JSON writes only for meta.json (write to temp file + rename)
- Repo lock **not held** by daemon (sandbox creation is CLI-owned in PR-04)

### Lifecycle Ownership Enforcement

The CLI creates the invocation record. The daemon mutates lifecycle fields. To prevent concurrent writes to the same meta.json:

- When daemon claims an invocation (on `start_headless`), it sets `lifecycle_owner: "daemon"` in meta
- CLI **must not** update meta fields on any invocation where `lifecycle_owner == "daemon"` — it should go through daemon endpoints (stop/kill) instead
- `lifecycle_owner` is cleared when invocation reaches terminal state (daemon sets it back to `""` or omits it)
- This is a **code-level enforcement**, not just a social contract — `UpdateInvocationMeta` checks `lifecycle_owner` before writing and returns an error if the caller is not the owner

## Tests (Required)

### Fake Runner Script

All integration-style tests use a fake runner script (shell script, not a real claude/codex binary):

```bash
#!/bin/sh
# Usage: fake_runner.sh <exit_code> <num_lines> [delay_seconds]
EXIT_CODE="${1:-0}"
NUM_LINES="${2:-5}"
DELAY="${3:-0.1}"

# Trap SIGINT for stop tests (exit 130 = 128 + 2)
trap 'echo "{\"type\":\"signal\",\"sig\":\"INT\"}" ; exit 130' INT

i=1
while [ "$i" -le "$NUM_LINES" ]; do
  echo "{\"type\":\"assistant\",\"content\":\"line $i\"}"
  sleep "$DELAY"
  i=$((i + 1))
done

echo "stderr output" >&2
exit "$EXIT_CODE"
```

Key properties:
- Prints N JSONL lines with configurable delays (tests partial writes)
- Prints to stderr (tests stderr capture)
- Exits with configurable code (tests exit_code capture)
- Traps SIGINT explicitly (tests stop behavior — emits signal event, exits 130)
- No dependency on `bc` or `seq` — portable across macOS and Linux `/bin/sh`

**Variant: `fake_runner_with_child.sh`** (for process group signaling tests):

```bash
#!/bin/sh
# Spawns a background child, then waits. Tests that stop/kill hits children too.
sleep 3600 &
CHILD_PID=$!
echo "{\"type\":\"child_spawned\",\"pid\":$CHILD_PID}"
trap 'kill $CHILD_PID 2>/dev/null; exit 130' INT
wait $CHILD_PID
exit 0
```

This variant verifies that SIGINT/SIGKILL sent to the process **group** (negative PGID) reaches child processes — the hardest bug class in process supervision.

### Unit Tests

- **Start:** daemon updates invocation meta to `status=running` with `pid` set (CLI already created record with `mode=headless`, `status=starting`)
- **Logging:** stdout streamed into `raw.jsonl` incrementally (verify partial writes before exit)
- **Logging:** stderr streamed into `stderr.log`
- **Exit:** exit code captured correctly; `status=finished` for exit 0, `status=failed` for non-zero
- **Exit reason:** `exit_reason=exited` on normal exit, `exit_reason=killed` on kill
- **PID clearing:** pid is nil after process reaches terminal state
- **Stop:** SIGINT sent to process group (verify via fake runner that traps and exits)
- **Kill:** SIGKILL sent to process group (verify via fake runner that ignores SIGINT)
- **Meta throttle:** `last_output_at` updated in meta at most once per 500ms despite many output chunks

### Integration-style Tests (no real runners)

- **Full lifecycle:** start → fake runner writes output → exits → verify meta + log files
- **Stop with slow runner:** start → fake runner sleeps 60s → stop → verify exit within timeout
- **Kill with stubborn runner:** start → fake runner ignores SIGINT → kill → verify SIGKILL terminates
- **Process group signaling (critical):** start → `fake_runner_with_child.sh` spawns background `sleep` → stop/kill → verify **both** runner and child PID are dead. This is the hardest test — without it, "stop works" but leaves orphan children.

### Recovery Tests

- Simulate daemon restart with orphaned `status=running` + dead PID → verify marked `status=failed`, `exit_reason=unknown`, `flags.needs_attention=true`, `flags.orphaned=true`
- Simulate daemon restart with orphaned `status=running` + alive PID + mismatched `daemon_instance_id` → verify `status` stays `running`, `flags.needs_attention=true`, `flags.orphaned=true`, `orphaned_at` set
- Simulate daemon restart with orphaned `status=running` + alive PID + matching `daemon_instance_id` → impossible case (daemon just started with new ID), treated as orphaned

### Safety Tests (Validation Gates)

- Daemon rejects request if `meta.json` does not exist for given invocation_id
- Daemon rejects request if `meta.json` indicates `mode != headless`
- Daemon rejects sandbox_path missing `SANDBOX_MARKER`
- Daemon rejects sandbox_path containing `INTEGRATION_MARKER`
- Daemon rejects sandbox_path that doesn't match store-computed expected path
- Daemon rejects request where `sandbox_path` in request doesn't match `sandbox_path` in invocation meta (meta cross-validation)
- Daemon rejects empty prompt
- Permanent validation failure marks invocation `status=failed`, `exit_reason=start_failed`

### Naming Tests

- `--name` with valid name → stored in `invocation_name` in meta.json
- `--name` with invalid name (uppercase, too short, special chars) → rejected with validation error
- `--name` with name already used by active invocation → rejected with `E_NAME_EXISTS`
- `--name` with name previously used by terminal invocation → accepted (name released)
- Unnamed invocation → `invocation_name` is empty/omitted in meta.json
- Resolver: exact name match returns correct invocation
- Resolver: name match excluded for terminal invocations
- Resolver: unnamed invocations not matched by name (only ID/prefix)

### Daemon Stop Tests

- `daemon stop` with no active invocations → daemon shuts down cleanly
- `daemon stop` with active headless invocations → returns `E_DAEMON_BUSY`, daemon stays running
- `daemon stop --force` with active invocations → daemon terminates all (SIGINT→wait→SIGKILL), marks `status=failed, exit_reason=killed`, then shuts down
- `daemon stop` with dead socket → falls back to pidfile SIGTERM

### Idempotency Tests

- Duplicate `start_headless` with already-running invocation + matching `daemon_instance_id` → returns ok with `already_running: true, orphaned: false`
- Duplicate `start_headless` with already-running invocation + mismatched `daemon_instance_id` → returns ok with `already_running: true, orphaned: true` (pid alive, but no daemon supervising logs)
- `start_headless` on terminal invocation → returns `E_INVOCATION_TERMINAL`
- `start_headless` on invocation with dead PID → marks failed, returns `E_INVOCATION_ORPHANED`

## Error Codes (PR-04)

All error codes introduced in this PR. Prevents ad hoc error invention.

| Code | Raised by | Meaning |
|---|---|---|
| `E_DAEMON_NOT_RUNNING` | CLI (daemon status/stop) | Daemon is not running (socket missing, /health fails) |
| `E_DAEMON_ALREADY_RUNNING` | Daemon (start) | Another daemon instance is already running on this socket |
| `E_DAEMON_BUSY` | Daemon (POST /shutdown) | Active headless invocations exist; use `--force` to override |
| `E_SANDBOX_VALIDATION_FAILED` | Daemon (start_headless) | Sandbox marker missing, integration marker present, or path mismatch |
| `E_INVOCATION_TERMINAL` | Daemon (start_headless) | Invocation already in terminal state (finished/failed) |
| `E_INVOCATION_ORPHANED` | Daemon (start_headless, recovery) | PID dead but was previously running; process exited without daemon observing |
| `E_NAME_EXISTS` | CLI (agent start) | Invocation name already used by an active invocation |
| `E_RUNNER_NOT_FOUND` | Daemon (start_headless) | Runner binary not found on PATH or in config |
| `E_RUNNER_START_FAILED` | Daemon (start_headless) | Runner process failed to start (exec error) |
