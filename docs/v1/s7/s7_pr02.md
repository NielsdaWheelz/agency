# PR-02: Enhanced `ls`/`show` Runner Visibility

## Goal

Make runner-reported state actionable in everyday CLI use by surfacing status context directly in `agency ls` and `agency show`.

## Builds On

PR-01 (runner status contract, status derivation, and stall detection primitives) must be merged first.

## Acceptance

- `agency ls` shows runner-reported semantic status (`working`, `needs input`, `blocked`, `ready for review`) when runner status data is present and valid.
- `agency ls` includes a SUMMARY column that surfaces runner summary text; stalled runs show a no-activity message with duration.
- `agency ls` reports `stalled` when tmux is active and no runner-status update has occurred for 15+ minutes.
- `agency ls` falls back to `active`/`idle` behavior when runner status data is missing or invalid.
- `agency show` includes a `runner_status` section with status, recency, summary, and any provided questions, blockers, `how_to_test`, and risks.
- Invalid or unreadable runner status artifacts do not crash `ls` or `show`; commands continue with deterministic fallback behavior.

## Non-Goals

- Does not change the runner status schema, required fields, or validation rules introduced in PR-01.
- Does not change precedence of terminal/flag-based statuses (`merged`, `abandoned`, `failed`, `needs attention`).
- Does not add real-time streaming, runner interruption, or automatic remediation for stalled runs.
- Does not redesign unrelated `ls`/`show` output contracts outside runner-status visibility.

## Key Decisions (if any beyond L2)

**Operator-first table layout**: human `ls` prioritizes actionable context by dedicating a column to summary text rather than additional metadata columns.

**Backward-compatible fallback**: pre-contract runs and invalid status artifacts continue to resolve via tmux-based `active`/`idle` semantics.

**Status detail gating**: `show` surfaces runner details only when runner status data is valid, avoiding noisy or misleading partial output.
